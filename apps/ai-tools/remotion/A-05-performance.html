A-05 性能优化 A 进阶

并发渲染、内存调优、Lambda 云渲染——5 倍提速方案。

Chapter 01

瓶颈分析

Remotion 渲染的三大耗时阶段:

阶段耗时占比优化空间
Bundle 打包5-15%小
帧渲染70-90%极大
FFmpeg 合流5-15%中

帧渲染是最大瓶颈,优化重点。

Chapter 02

并发参数调优

每个并发实例是独立的 Chrome 浏览器,内存约 300MB:

# 8 核 16GB 机器推荐值
npx remotion render Video out.mp4 --concurrency=4

# 公式:可用内存 / 350MB ≈ 最大并发
# 4GB 可用 → 最多 11
⚠️

并发数过高会触发 OOM;过低会浪费时间。需根据实际机器配置测试。

Chapter 03

Bundle 缓存

第二次渲染时复用 bundle,跳过 Webpack 打包:

# 第一次:完整 bundle
npx remotion render Video out.mp4  # 30 秒

# 第二次:复用 build/ 目录
npx remotion render Video out.mp4 --bundle=build  # 5 秒

CI 流程可将 build/ 缓存到 S3,大幅加速流水线。

Chapter 04

内存优化技巧

  • OffthreadVideo:抽帧在 ffmpeg 阶段,不占浏览器内存
  • 避免大数组渲染:用 Series 代替 1000 个 Sequence
  • 图片懒加载:用 prefetch 一次性预热
  • CSS transform:用 GPU 加速而非 layout 触发的属性
// ❌ 触发 layout 重排
style={{ left: x, top: y }}

// ✅ 走 GPU 合成
style={{ transform: `translate(${x}px, ${y}px)` }}
Chapter 05

Lambda 云渲染

对超长视频(数小时)或批量渲染,本地机器不够,推到 AWS Lambda:

# 安装 CLI
npm i @remotion/lambda

# 部署到 AWS(一次性)
npx remotion lambda deploy

# 提交渲染任务
npx remotion lambda render Video out.mp4 \
  --function-name=remotion-render \
  --region=us-east-1 \
  --frames-per-lambda=60
☁️

Lambda 模式将视频拆为多个并行任务,数百个 Lambda 函数同时渲染数百段,10 分钟视频只需 1 分钟。

Chapter 06

CDN 分发

渲染结果上传 S3,通过 CloudFront 分发:

npx remotion lambda render Video out.mp4 \
  --out-name=video-v1.mp4 \
  --privacy=public \
  --public-url=https://cdn.example.com/videos/video-v1.mp4

详见 S-03 Lambda 云端渲染。

Chapter 07

帧率精确控制

默认 30fps,常用档位:

fps应用场景
24电影标准
30网络视频(YouTube/抖音)
60游戏/体育/丝滑动效
25PAL 制电视
⚠️

固定 fps 后,所有时间必须按 useCurrentFrame() / fps 换算成秒。避免在 React state 中存"秒",存帧号才精确。

Chapter 08

Bundle 体积优化

Remotion 启动速度取决于 bundle/ 大小。优化策略:

策略效果
Tree-shake(避免 import * as)减小 20-40%
webpackIgnore 标记 Node 包防止误打包
大依赖 dynamic import主 chunk 减小
图片静态化(不放源码)加速构建
字体子集化(fontTools)字体从 MB → KB
Chapter 09

并发渲染调优

默认并发数 = CPU 核数 - 1。可调参数:

场景建议
本地开发--concurrency=1 实时调试
本地 4K 渲染--concurrency=4 平衡 CPU/内存
Lambda 渲染用 framesPerLambda 拆分大任务
Server-side 批量外层 P 进程 × 每进程 N 帧

Chrome 单实例可并行多个标签页,Remotion 用 worker pool 管理。Lambda 用 framesPerLambda=200 拆分后,1000 帧视频会被分给 5 个 Lambda 同时跑。
