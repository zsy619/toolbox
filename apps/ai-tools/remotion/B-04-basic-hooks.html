B-04 Remotion 基础 Hooks B 基础

useCurrentFrame / useVideoConfig / useDelayRender —— React 视频编程的三个基础钩子。

阅读 ~ 9 分钟
前置 B-02 核心概念
类型 入门
Chapter 01

useCurrentFrame:读取当前帧

最常用的 Hook,返回当前正在渲染的帧号(从 0 开始):

import { useCurrentFrame } from 'remotion';

const frame = useCurrentFrame();  // 0, 1, 2, 3, ...

// 常见用法:基于帧号计算动画进度
const progress = frame / totalFrames;  // 0.0 - 1.0
const angle = frame * 2;               // 每帧转 2 度
⚠️

Sequence 内部的 useCurrentFrame 返回的是相对于 Sequence 起始的帧号,不是全局帧号。这常让初学者困惑,务必注意。

Chapter 02

useVideoConfig:访问视频元数据

返回当前 Composition 的所有元数据,无需在 Props 中传递:

import { useVideoConfig } from 'remotion';

const { fps, width, height, durationInFrames, id } = useVideoConfig();
// 例: { fps: 30, width: 1920, height: 1080, durationInFrames: 150, id: "HelloWorld" }

典型用途:根据视频尺寸动态调整布局,或计算时间(秒)。

Chapter 03

useDelayRender:等待异步资源

当组件需要先加载远程数据或字体才能渲染时,用此 Hook 阻止渲染直到就绪:

import { useEffect, useState } from 'react';
import { useDelayRender, continueRender, delayRender } from 'remotion';

const [data, setData] = useState(null);
const handle = useDelayRender();  // 返回一个 handle

useEffect(() => {
  fetch('/api/data').then(r => r.json()).then(d => {
    setData(d);
    continueRender(handle);  // 告诉 Remotion 资源就绪
  });
  return () => continueRender(handle);  // 清理
}, []);
💡

超时默认 30 秒(可在 Composition 设置 delayRenderTimeoutInMilliseconds 调整)。超时未完成会渲染错误界面。

Chapter 04

常见反模式

Hook 使用中的 3 大陷阱:

  1. 不要在循环/条件中调用 Hook:违反 React 规则,会导致帧间状态错乱
  2. 不要在 useEffect 中调用 delayRender:在组件函数顶层调用,而不是 effect 里
  3. 不要把异步数据直接传给 useState:必须用 delayRender 包装,否则首帧拿到 undefined
Chapter 05

Hook 实战:旋转动画

结合 useCurrentFrame 与 useVideoConfig 实现每秒转一圈的旋转动画:

const frame = useCurrentFrame();
const { fps } = useVideoConfig();
const angle = (frame / fps) * 360;  // 每秒 360 度

<div style={{ transform: `rotate(${angle}deg)` }}>🔄</div>

Chapter 06

getRemotionEnvironment()

运行时检测当前是预览还是渲染,根据环境走不同逻辑(如 Studio 显示调试信息、Lambda 渲染时跳过):

ts
import { getRemotionEnvironment } from 'remotion';

const env = getRemotionEnvironment();
// { isStudio: boolean, isRendering: boolean, isPlayer: boolean, ... }

if (env.isStudio) {
  console.log('调试面板');
}
Chapter 07

useDelayRender 异步加载

Remotion 渲染时默认同步执行,任何数据获取(API/字幕/远端图片)都必须先于渲染完成。useDelayRender(v4.0.342+) 是推荐的标准模式:

tsx
import { useState, useEffect, useCallback } from 'react';
import { useDelayRender, staticFile } from 'remotion';

const { delayRender, continueRender, cancelRender } = useDelayRender();
const [handle] = useState(() => delayRender());

useEffect(() => {
  fetch(staticFile('data.json'))
    .then(r => r.json())
    .then(data => { setData(data); continueRender(handle); })
    .catch(e => cancelRender(e));
}, [handle]);
💡

useDelayRender 返回的 delayRender 绑定到当前渲染作用域,比全局 delayRender 更安全(避免组件卸载后继续渲染)。

Chapter 08

useCurrentScale() 缩放感知

Player 与渲染分辨率不一致时,可用此 hook 获取当前实际显示比例,做 响应式布局:

tsx
import { useCurrentScale } from 'remotion';

const scale = useCurrentScale();  // 0.5 表示 Player 缩到 50% 显示
const fontSize = 80 * scale;      // 字号同步缩放

常见用法:Studio 中拖动滑块改变显示大小时,UI 元素也跟着缩放而不溢出。

Chapter 09

useRemotionEnvironment() 完整版

除 isStudio/isRendering/isPlayer 外,还提供:

ts
const env = useRemotionEnvironment();
// {
//   isStudio: boolean      Studio 内
//   isRendering: boolean   正在 SSR/Lambda 渲染
//   isPlayer: boolean      Player 组件内
//   isReadOnlyStudio: boolean  只读模式
//   isClientSideRendering: boolean  客户端渲染
// }

在 Studio 实时显示 FPS、帧号等调试面板:用 env.isStudio 判断,渲染/Player 时跳过。

Chapter 10

useWindowedAudioData 大文件流式

传统 useAudioData 会全量加载 WAV 头,在处理几十分钟的播客/长录音时慢且占内存。useWindowedAudioData 按 5s 窗口流式加载:

tsx
import { useWindowedAudioData } from '@remotion/media-utils';

// 注意:只支持 .wav 格式
const { audioData, durationInSeconds } = useWindowedAudioData({
  src: staticFile('podcast.wav'),
  windowInSeconds: 5,
});

// 渲染当前帧所在的 5s 窗口数据
// 内存占用减少 95%

适用场景:播客可视化(几十分钟)、长录音分析、音频编辑器预览。
