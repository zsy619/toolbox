5-Step Process

5步重建流程

完整的知识库重建方法论

1

拆分旧库 → raw/ + inbox/

将历史笔记迁移到 raw 目录，新建 inbox 收集零散灵感

2

AI 编译规则 → 定义处理文档的规则

用 AI 编写笔记编译规则，让 AI 理解你的知识结构

3

批量编译 → 先验证一份，再批量

先测试编译效果，确认无误后批量处理

4

双链与索引 → 反向链接 + MOC 入口

建立笔记间的双向链接，创建 MOC (Map of Content) 导航

5

闭环使用 → 丢素材 → 编译 → 提问 → 写回

形成完整的知识输入输出闭环

FAQ

常见问题

关于知识库重建的疑问解答

任何支持 API 的 LLM 都可以，如 ChatGPT、Claude、通义千问等。Karpathy 方法的核心是用 LLM 作为"编译器"，自动处理和结构化你的笔记内容。

非常适合。虽然方法论稍复杂，但步骤清晰，先验证一份再批量处理的策略让新手也能轻松上手。配合视频教程，1小时内即可完成基础重建。

首次重建需要 1-2 小时，之后每天使用只需要几分钟。随着知识库的积累，你会发现检索速度越来越快，知识之间的连接越来越清晰，2-3 周后效果会非常明显。

统一放到 raw/ 目录，让 AI 批量编译处理。不用逐个手动整理，AI 会按照你定义的规则自动提取核心内容、生成结构化笔记。

Obsidian 基础版免费，社区插件免费。AI 编译需要消耗 LLM API 额度，但批量处理效率极高，平均每百条笔记仅需几分钱。长远来看，效率提升远超成本。
