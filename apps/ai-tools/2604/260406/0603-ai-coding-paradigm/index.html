2024

Vibe Coding

Andrej Karpathy 提出的概念，自然语言描述需求，AI生成代码

零门槛 30分钟 Web应用

核心优势

  • • 零门槛，不需要编程基础
  • • 快速生成代码原型
  • • 适合 POC 快速验证
  • • Hackathon 和 Demo 利器

致命缺陷

  • • 歧义问题：AI替人做沉默决策
  • • 范围蔓延：需求边界模糊
  • • 幻觉：代码可能看似正确
  • • 不可审查：难以人工验证
  • • 不可复现：相同需求结果不同

核心洞察

"看起来能用"和"真正能用"之间隔着一道深渊

Vibe Coding 是 AI 编程的"素描"，不是"施工图"。它的最佳场景是快速验证想法可行性，一次性脚本，个人项目。

2025

Spec Coding

行业集体转向：在写代码之前，先把"做什么"定义清楚

Spec Kit Symphony Plan Mode

Spec Driven Development 流程

1

Spec

定义做什么

2

Plan

规划怎么做

3

Tasks

拆解任务

4

Implement

逐个实现

解决了什么问题

  • • 歧义问题：Agent 不需要再猜
  • • 可审查性：团队可在实现前对齐预期
  • • 可复现性：相同 Spec 产出一致结果
  • • 质量底线：验收标准就是测试用例

没解决什么

  • • Agent 运行时的故障恢复
  • • 多 Agent 协作的编排与状态管理
  • • 上下文窗口的动态管理
  • • 安全防护与人工审批流程

Spec Coding 的三个成熟度层级

L1 Spec-First

在编码前编写功能规格说明

L2 Spec-Anchored

规格作为验证和决策的核心依据

L3 Spec-as-Source

规格本身成为源代码的一部分

2026

Harness Engineer

Harness 不是 Agent，是管理 Agent 如何运行的软件系统

计算机类比： CPU = LLM，RAM = 上下文窗口，操作系统 = Harness，应用程序 = Agent

Harness 的六大核心组件

工具集成层

设备驱动程序 - Agent 调用外部工具的接口

内存与状态管理

内存管理 + 文件系统 - 持久化与临时状态

上下文工程

进程调度器 - 管理上下文窗口的动态分配

规划与分解

任务调度器 - 复杂任务的分层规划

验证与防护

防火墙 + 权限系统 - 安全防护与审批流程

模块化与扩展

内核模块 - 可扩展的功能组件

Harness Engineer 的五大核心技能

上下文工程

约束设计

工具编排
