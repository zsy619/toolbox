# 让 AI 写前端变好看的野路子 🪄

用 AI 写代码已经很强了，但有一个问题一直让我很头疼：

功能能跑，但 UI 风格每次都像随机抽奖。

## 痛点

按钮颜色、间距、字号，AI 每次生成的结果都不一样。

同一句"按钮用蓝色"，它用的蓝跟你想的蓝不是同一个蓝。

你说"间距大一点"，它大得像个 KTV 大堂。

程序员面对混乱的 UI 设计，就像在解一道没有标准答案的题。

## 解决方案

直到我看到了 **awesome-design-md** 这个 GitHub 项目。

它把 Linear、Vercel、Stripe、Notion、Spotify、Supabase 等知名产品的设计规范，整理成 Markdown 格式的文件。

AI 编程时直接读取这个文件，生成的 UI 风格瞬间稳定了。

## 工作原理

**DESIGN.md**：一个 Markdown 格式的设计规范文档，通常放在项目根目录。

**AI 读取**：AI 编程 Agent 在生成代码前读取文件内容。

**风格统一**：生成的代码遵循统一的视觉风格规范。

## 效果对比

| 使用前 | 使用后 |
|--------|--------|
| 纯靠模型猜 UI | 有设计规范参考 |
| 字体层级混乱 | 字体层级稳定 |
| 间距随机 | 间距合理统一 |
| 暗色模式不一致 | 暗色模式统一 |

## Unix 哲学

这种思路特别符合 Unix 哲学：

- 不引入复杂工具链
- 不要求设计师额外学习
- 不依赖某个特定平台
- 只用纯文本表达规则

> do one thing and do it well

## 使用方法

1. 找一个喜欢的 DESIGN.md 风格
2. 复制到项目根目录
3. 告诉 AI：生成 UI 时必须遵循这个文件

## 局限性

- 不能替代完整的交互设计
- 不能替代品牌设计团队的审美判断
- 部分信息可能是推断而非官方来源
- 复杂组件和动效仍需手工补充

但作为"让 AI 写前端更像样"的方法，它非常值得尝试。
