为什么需要理解容器命令

Docker 容器是为了 运行容器中的应用 ,对外提供服务。应用运行完毕后,容器就会 自动终止 。如果不想让容器启动后立即终止,需要使容器应用 不能立即结束 ——通常采用两种方式:使应用处于 与用户交互的状态 (如 /bin/bash )或 等待状态 (如 Tomcat 服务器持续监听)。

⚠️

直接 docker run -d ubuntu:latest 没有任何前台进程,容器会立即退出( docker ps 查不到, docker ps -a 才能看到已退出的容器)。

Chapter 01

2 种运行模式:交互 vs 分离

容器有两种运行模式: 交互模式 与 分离模式 。

1.1 交互模式(ubuntu)

以交互模式运行 ubuntu:

bash 
                
                  
docker run
                  
                  
--name
                  
 myubuntu
                  
-it
                  
 ubuntu:latest /bin/bash
  • --name :指定当前容器名称为 myubuntu
  • -it :指定以 交互模式 运行容器,且为容器分配一个 伪终端
  • 后面的 /bin/bash 用于指定容器启动后要运行的命令

运行命令后发现命令行前面发生变化:从 root@docker~ 变为 root@de0940ad17dd:/# ,这就是 docker 生成的伪客户端,数字 de0940ad17dd 表示 容器 ID 。

1.2 交互模式(Tomcat)

bash 
                
                  
docker run
                  
                  
--name
                  
 mytomcat8
                  
-it
                  
 tomcat:8.5.32 /bin/bash

通过 ls -l 命令查看 tomcat 根目录下的文件,注意 不支持 ll 命令。

正式启动 tomcat(端口映射):

bash 
                
                  
docker run
                  
                  
--name
                  
 mytomcat8081
                  
-it
                  
                  
-p
                  
 8081:8080 tomcat:8.5.32

-p 指定端口映射,格式为 暴露给宿主机的端口:容器中应用的端口 。

1.3 分离模式(Tomcat 集群)

以分离模式运行 tomcat: -d 表示以 分离模式 运行容器,即命令在 后台运行 :

bash 
                
                  
docker run
                  
                  
--name
                  
 tomcat01
                  
-dp
                  
 8081:8080 tomcat:8.5.32
                  
docker run
                  
                  
--name
                  
 tomcat02
                  
-dp
                  
 8082:8080 tomcat:8.5.32
                  
docker run
                  
                  
--name
                  
 tomcat03
                  
-dp
                  
 8083:8080 tomcat:8.5.32

现在已经启动了 3 个 tomcat 容器,可以通过浏览器访问了。

1.4 分离模式(ubuntu 误区)

bash 
                
                  
docker run
                  
                  
-d
                  
 ubuntu:latest
⚠️

该运行方式有一个问题:虽然容器启动了,但是 docker ps 命令 查看不到 。 docker ps -a 命令可以查看到该容器,只不过其 已经退出了 。 docker ps 查看的是 up 状态的容器。原因是 ubuntu 没有前台进程运行,容器启动后立即终止。

1.5 docker create(仅创建不启动)

docker create 命令 仅创建容器但不启动 ,用法与 docker run 非常相似。但是 没有 -d 选项,因为 docker create 默认就是采用后台方式运行的。

Chapter 03

exec vs attach 6 维度对比

exec 和 attach 命令只能对 正在运行 的容器进行操作,是日常使用频率最高的两个命令。

3.1 新建进程进入容器(exec)

bash 
                
                  
# 1. 先以分离模式运行 tomcat 容器
                  
                  
docker run
                  
                  
--name
                  
 mytom10
                  
-dp
                  
 8081:8080 tomcat:8.5.32
                  
# 2. 使用 exec 命令进入此容器
                  
                  
docker exec
                  
                  
-it
                  
 mytom10 /bin/bash
                  
# 3. 使用 exit 退出容器,此时 tomcat 容器并未结束
                  
                  
# 说明 exec 命令会创建一个新的进程,exit 只是结束了这个新建的进程
                  
                  
exit

3.2 6 维度对比表

对比项 docker exec docker attach
进程行为 新建独立进程(非 PID1) 连接容器 主进程 PID1
退出影响 退出 不影响 容器,容器继续运行 Ctrl+C 会 停止容器 ;需 Ctrl+P+Q 安全分离
终端独立性 每个 exec 都是独立 shell 多终端 attach 共享同一会话、同步输出
常用场景 日常进容器调试、改配置、查日志 看主进程实时输出、接回前台交互容器
多次连接 每次创建新进程,互不影响 多个终端同时连接同一进程
安全退出 直接 exit 必须 Ctrl+P+Q (或容器会停止)

3.3 外部操作容器(exec 不进入)

其实也可以不进入容器直接对容器进行操作。比如想查看 tomcat 容器工作目录中的文件,直接在 exec 命令后紧跟执行的命令即可:

bash 
                
                  
docker exec
                  
                  
-it
                  
 mytomcat02
                  
ls
                  
                  
-l

3.4 容器附加标准输入(attach)

bash 
                
                  
# 1. 先以交互方式运行一个 ubuntu 容器,然后使用 Ctrl+P+Q 命令退出但不停止容器
                  
                  
docker run
                  
                  
--name
                  
 myubuntu
                  
-it
                  
 ubuntu:latest /bin/bash
                  
# 2. 然后使用 attach 进入容器命令行,此时再使用 exit 命令退出容器,容器也就停止了
                  
                  
# attach 命令没有另外创建新进程,而是使用了容器进程,所以 exit 命令结束当前进程后,容器就停止了
                  
                  
docker attach
                  
 myubuntu

3.5 容器附加标准输出

启动一个 tomcat 容器(分离模式),然后执行 docker attach 可以看到:占用了命令行,但没有任何输出。此时的容器附加了标准输出,只不过,其输出的是 tomcat 的 启停日志信息 。

bash 
                
                  
docker run
                  
                  
--name
                  
 mytomcat
                  
-dp
                  
 8081:8080 tomcat:8.5.32
                  
docker attach
                  
 mytomcat
⚠️

通过 Ctrl+C 可结束 tomcat,此时能看到停止日志显示出来。但是此时 tomcat 已经停止,容器已经退出,所以 docker attach 命令也随之结束了。

4.2 容器日志查看(docker logs)

7 种常用选项,覆盖 实时/历史/筛选/格式化 所有场景:

命令 说明
docker logs <容器> 查看指定容器中应用的运行日志,不论容器是运行还是停止状态
docker logs 查看所有容器中应用的运行日志
docker logs mytom3 查看 mytom3 容器的日志
docker logs -n 5 mytomcat 查看最后 5 条日志
docker logs --since="2022-08-11" --tail=3 mytomcat 查看指定日期以来的最后 3 条
docker logs --since=30m --tail=3 mytomcat 查看近 30 分钟内的最后 3 条
docker logs --until=5m --tail=3 mytomcat 查看截至 5 分钟前的最后 3 条
docker logs -t --tail=3 mytomcat 显示详细时间戳
docker logs -f --tail=3 mytomcat 查看动态日志(实时跟踪)
💡

时间单位说明: m =分, s =秒, h =小时。 --since 与 --until 配合使用可以精确定位时间窗口内的日志,排错时非常有用。

# 将 mytomcat 容器的 tomcat 中 webapps 目录复制到宿主机的当前目录

6.2 宿主机 → 容器

bash 
                
                  
# 将宿主机当前目录下的 hw.tar 文件复制到 mytomcat 容器的 /usr/local/tomcat 目录中

Chapter 08

export/import vs save/load

8.1 导入导出容器

bash 
                
                  
# 将 tomcat:8.5.32 镜像的容器 tom 导出到当前 /root 目录的 tomcat8.tar 文件中
                  
                  
docker export
                  
                  
-o
                  
 tomcat8.tar tom
                  
# docker import 用于将指定的 tar 文件构建新的镜像
                  
                  
docker import
                  
 tomcat8.tar mytomcat:1.0

8.2 4 维度对比:export vs save

对比项 export save
作用对象 容器 镜像
结果 tar 文件 tar 文件
多对象支持 ❌ 一次只能导出一个容器 ✅ 一次可导出多个镜像
历史记录 ❌ 丢弃原镜像的所有历史记录与元数据信息 ✅ 保存原镜像的完整记录

8.3 4 维度对比:import vs load

对比项 import load
导入对象 容器(export 导出的 tar) 镜像(save 导出的 tar)
结果 新镜像 恢复为镜像
分层数 只包含 一层 与原镜像 分层相同
ImageID 与原镜像 不同 (新镜像) 与原镜像 相同
指定 repo:tag ✅ docker import tar mytomcat:1.0 ❌ 只能从 tar 元数据中读取

8.4 与 docker commit 对比

  • 相同点 :docker import + docker export 和 docker commit 都能将一个容器变为一个镜像
  • 不同点 :docker import + docker export 恢复的镜像 只包含原容器生成的一层分层 ;docker commit 生成的镜像中 包含原镜像的所有分层
🎯

迁移场景选择 :完整迁移镜像(保留历史)用 save/load ;只关心当前容器文件系统(丢弃历史缩小体积)用 export/import ;有 Git 化的镜像管理需求用 commit 。

FAQ

常见问题

Docker 容器启动后为什么会立即终止?

Docker 容器是为了 运行容器中的应用 ,对外提供服务。应用运行完毕后,容器就会自动终止。如果不想让容器启动后立即终止,需要使容器应用不能立即结束,通常采用两种方式:1) 使应用处于与用户 交互的状态 (如 /bin/bash);2) 使应用处于 等待状态 (如 Tomcat 服务器持续监听)。直接 docker run -d ubuntu:latest 没有任何前台进程,容器会立即退出。

docker exec 和 docker attach 有什么区别?

核心区别 4 点:1) 进程行为:exec 新建独立进程 (非 PID1),attach 连接容器主进程 PID1 ;2) 退出影响:exec 退出不影响容器,容器继续运行,attach 用 Ctrl+C 会停止容器,需 Ctrl+P+Q 安全分离;3) 终端独立性:每个 exec 都是独立 shell,多终端 attach 共享同一会话;4) 常用场景:exec 用于日常进容器调试、改配置、查日志,attach 用于看主进程实时输出、接回前台交互容器。

docker export/import 和 docker save/load 有什么区别?

export 作用于 容器 ,save 作用于 镜像 ,但导出的结果都是 tar 文件。export 只对当前容器的文件系统快照进行导出, 丢弃原镜像的所有历史记录与元数据 ;save 则保存了原镜像的完整记录。import 恢复的镜像 只包含一层 ,且 ImageID 不同;load 恢复的镜像与原镜像 分层相同 ,ImageID 也相同。import 可以为镜像指定 repository:tag,load 不行。

什么是悬虚镜像(dangling image)?

悬虚镜像是 没有 repository 和 tag 的镜像。悬虚镜像一般是由一些失误操作产生的副产物(如 docker commit 时没指定 repository:tag),一般要被清除掉。如果非要使用,只能通过 imageID 来使用。清理命令:docker image prune 或 docker system prune。

docker cp 能用于容器之间传递文件吗?

不可以。docker cp 不支持容器间 的文件传递。语法只能是 docker cp 容器:路径 宿主机路径,或反向。如果要在两个容器间传递文件,需要先 cp 到宿主机作为中转,再从宿主机 cp 到目标容器。

docker stop 和 docker kill 有什么区别?

docker stop: 优雅 停止,先发送 SIGTERM 信号(默认 10 秒超时),让容器内的应用有机会优雅关闭(如保存数据、释放资源);docker kill: 强制 停止,直接发送 SIGKILL 信号,应用来不及做任何清理。生产环境推荐先 docker stop,超时未关闭再用 docker kill。

docker system prune 有什么用?

docker system prune 用于 删除 docker 中无用的数据 ,包括:已经停止的容器、没连任何容器的网络、悬虚镜像、悬虚构建缓存等。加上 -a 可删除所有未被使用的镜像,加 --volumes 还会删除未被使用的数据卷。这是一个 非常实用的清理命令 ,特别适合磁盘空间告急时一键释放空间。
