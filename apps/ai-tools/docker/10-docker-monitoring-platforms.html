Docker 管理监控平台完全指南

当 Docker 中管理的镜像、容器、网络等变得很多时,命令行管理力不从心,就应该使用 Docker 可视化平台。本文详解 4 款主流工具:Docker UI、Portainer、Shipyard、CIG 监控三剑客。

为什么需要可视化管理平台

当 Docker 中管理的 镜像、容器、网络、卷 等资源变得很多时,通过命令管理就很吃力,容易遗漏、出错且不便于团队协作。可视化管理平台提供:

  • 图形化界面 :降低学习成本,新人快速上手
  • 集中管理 :多台 Docker 主机统一管理
  • 权限分配 :RBAC 角色权限,适合团队
  • 可视化监控 :CPU/内存/网络/磁盘趋势图,健康指标预警

Chapter 02

Docker UI

Docker UI 是一个 开源的、基于 Docker API 的 Web 应用程序 ,支持容器管理与镜像管理,但 不支持集群管理 。适合个人开发与学习测试。

2.1 安装与启动

bash 
                
                  
# 1. 拉取 Docker UI 镜像
                  
                  
docker pull
                  
 uifd/ui-for-docker
                  
# 2. 启动 Docker UI 容器(挂载 Docker socket)
                  
                  
docker run

-p

-v
                  
 /var/run/docker.sock:/var/run/docker.sock \

浏览器访问 http://:9000 即可看到管理页面。

💡

Docker UI 通过挂载宿主机的 /var/run/docker.sock 与 Docker 引擎通信,这是 Docker 管理工具的通用做法。

Chapter 04

Shipyard

Shipyard 是 Docker 的 Web 可视化界面管理工具,建立在 Docker 集群管理工具 Citadel 之上,可以管理镜像、容器、主机等资源。Shipyard 包括两个版本:

  • core 版本 :把多个 Docker host 上的 containers 统一管理(支持跨多个 host)
  • extension 版本 :在 core 基础上添加了 应用路由和负载均衡、集中化日志、部署 等
⚠️

Shipyard 自 2017 年起已停止维护,部分镜像可能无法在新版 Docker 中正常运行。生产环境强烈建议使用 Portainer。新项目不建议采用。

4.1 安装方式

Shipyard 提供两种安装方式:

  • 手动安装 :比较麻烦,需要拉取很多镜像
  • 自动安装 :运行一个部署脚本,自动拉取全部镜像并启动这些容器(推荐)

4.2 自动部署脚本

在 /root/shipyard 目录下新建 deploy 脚本文件(内容较长,约 200 行),然后执行:

bash 
                
                  
# 添加可执行权限
                  
                  
chmod
                  
 +x deploy
                  
# 执行脚本
                  
                  
./deploy

脚本会自动完成以下步骤:

  1. 启动数据库 (rethinkdb)
  2. 启动服务发现 (etcd)
  3. 启动证书卷 (certs)
  4. 启动 Docker 代理 (proxy)
  5. 启动 Swarm Manager
  6. 启动 Swarm Agent
  7. 启动 Controller

脚本运行完成后会输出访问地址和默认账号密码:

  • 访问地址: http://:8080
  • 用户名: admin
  • 密码: shipyard
Chapter 05

CIG 监控系统(三剑客)

通过 docker stats 命令可以查看当前所有容器的 CPU 占用率、内存占用率等数据。但它 只显示实时数据 ,无法存储和查询历史数据,没有健康指标预警功能。而 CIG 解决了这个问题。

5.1 CIG 三剑客

CIG = CAdvisor + InfluxDB + Grafana ,也称 docker 监控三剑客:

组件 角色 技术栈 职责
CAdvisor 数据采集 Go 监控容器的内存、CPU、网络、磁盘 IO 等;提供 Web 页面;支持 InfluxDB、Redis、Kafka、Elasticsearch 等存储后端
InfluxDB 时序存储 Go 高性能时序型数据库,专注海量时序数据的高效读写、存储与实时分析,无需外部依赖
Grafana 可视化 Go 开源的数据监控分析可视化平台,支持丰富的数据源与告警规则
为什么需要 CIG?docker stats 不够用吗?

docker stats 存在三个局限:1) 不存储历史 ,关闭后无法回溯;2) 无法做趋势分析 ;3) 无健康指标预警 。CIG 通过"采集 → 存储 → 展示"三层架构补齐这三个能力,适合生产环境长期监控。

5.2 安装 CIG (使用 docker compose)

  1. 创建工作目录: mkdir /root/cig
  2. 在目录下定义 compose.yml (见下方)
  3. 启动容器: docker compose up -d

5.5 访问各组件

组件 URL 默认账号
CAdvisor http://:8080 无
InfluxDB http://:8083 root / (空)
Grafana http://:3000 admin / admin
⚠️

三个容器启动较慢,需要耐心等待 1-2 分钟。同时注意 compose.yml 中 links 字段在新版 Docker compose 中已废弃,新版应使用 networks 自定义网络。

5.6 配置 Grafana 数据源

Grafana 默认不连接 InfluxDB,需要手动添加数据源:

  1. 登录 Grafana → 左侧齿轮 → Data Sources → Add data source
  2. 选择 InfluxDB
  3. 填写配置:
    • URL: http://influxsrv:8086 (用 compose 中的服务名)
    • Database: cadvisor
    • User: root
    • Password: (空)
  4. 点击 Save & Test ,显示绿色 Data source is working 即成功

之后即可在 Grafana 中创建 Dashboard,选择 InfluxDB 数据源,展示容器 CPU、内存、网络等历史指标。

FAQ

常见问题

Docker UI、Portainer、Shipyard 应该选哪个?

Docker UI 官方推荐,功能最简单,适合学习测试,不支持集群;Portainer 目前最主流的轻量级管理工具,免费开源,支持单机/集群,适合中小团队;Shipyard 基于 Citadel 集群的 Web 工具,支持跨主机容器管理,但 2017 年后停止更新,仅适合旧项目维护。新项目首选 Portainer,需要历史监控数据时叠加 CIG。

什么是 CIG 三剑客?

CIG = CAdvisor + InfluxDB + Grafana 的组合:CAdvisor 负责数据采集(每 2 分钟采样);InfluxDB 负责时序数据存储;Grafana 负责数据可视化与告警。docker stats 只能看实时数据,CIG 能记录历史并设置健康指标预警。

Portainer 社区版(CE)与商业版(EE)有什么区别?

CE(Community Edition)免费开源,功能包括容器/镜像/网络/卷管理、Swarm 集群、Kubernetes 集成、RBAC 权限等,适合大多数场景;EE(Enterprise Edition)商业付费,增加 SSO、审计日志、镜像签名、漏洞扫描、跨集群复制等高级功能,适合金融/医疗等合规要求严格的场景。

为什么 docker stats 不够用?

docker stats 只能显示当前时刻的 CPU、内存、网络、磁盘 IO 等实时数据,存在三个问题:1) 不存储历史,关闭后无法回溯;2) 无法做趋势分析;3) 没有健康指标预警。CIG 三剑客正好补齐这三个能力。

Grafana 如何连接 InfluxDB?

Grafana Web UI → 左侧齿轮 → Data Sources → Add data source → 选择 InfluxDB → 填写 URL(http://influxsrv:8086)、Database(cadvisor)、User(root)、Password(空) → Save & Test 显示绿色 Data source is working 即连接成功。

docker compose up -d 超时怎么解决?

镜像较大时(docker compose up -d 会自动 pull)会超时。解决方法:1) 手动 docker pull 三个镜像;2) docker compose pull 拉取 service 镜像;3) docker compose build . 重新构建;4) 再执行 docker compose up -d 启动。

Portainer 默认账号密码是什么?

Portainer 首次访问时强制要求设置管理员密码(不少于 8 位),无默认密码。设置后才能进入主界面,适合新部署安全。
