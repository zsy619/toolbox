Chapter 01

Serverless 4 大形态

  • 1) FaaS:AWS Lambda / Azure Functions / GCP Cloud Functions
  • 2) 容器化 FaaS:OpenFaaS / Knative / Fission
  • 3) Serverless K8s:阿里 ASK / AWS EKS Fargate
  • 4) Serverless 容器:Azure Container Apps / Cloud Run
  • 推荐:企业内部用 OpenFaaS,云原生用 Knative
Chapter 02

OpenFaaS 实战

  • faasd 部署:单二进制,无需 K8s,5 分钟搭建
  • faas-cli deploy 发布函数:Dockerfile 模板
  • watchdog:网关侧代理,接收 HTTP 请求转发容器
  • 可观测性:Prometheus 自动集成 / Grafana 模板
  • 冷启动:从镜像拉取到 ready 约 1-3 秒
Chapter 03

Knative Serving 4 模式

  • 1) Service:长期运行的服务(类似 Deployment)
  • 2) Route:流量路由规则 + 灰度发布
  • 3) Configuration:配置版本化(类似 ConfigMap)
  • 4) Revision:不可变的配置快照(可回滚)
  • Knative + K8s:Pod 0 时缩容到 0,按需启动
Chapter 04

AWS Lambda 容器镜像

  • 2020 起支持 Docker 镜像部署 Lambda
  • 镜像最大 10GB,支持任意基础镜像
  • 函数运行时最长 15 分钟,内存最大 10GB
  • 冷启动:首次 5-15s,后续 1-3s
  • Lambda Web Adapter:任意 HTTP 服务器转 Lambda
Chapter 05

冷启动优化 4 招

  • 1) 函数镜像:alpine 50MB 起步,scratch 极简
  • 2) Init Snapshots(Knative):启动时间从 1s 降至 50ms
  • 3) 预置并发:Lambda Provisioned Concurrency
  • 4) 定时预热:CloudWatch Events 定时 ping 触发
💡 FaaS 选型

事件驱动用 Lambda,长期运行用 Cloud Run

🎯 计费模式

Lambda 按调用次数 + GB-秒,空跑 0 费用

📝 Knative Service

以下是该主题的完整可执行代码,直接复制即可在生产环境使用:

Knative Service · yaml 
            
apiVersion: serving.knative.dev/v1
kind: Service
metadata:
  name: my-func
spec:
  template:
    spec:
      containers:
      - image: myfunc:v1
        resources:
          limits:
            memory: 256Mi
            cpu: 500m
操作流程

可视化操作流程

🔄 5 步标准操作流程

  1. 1. 部署 Knative → 启动容器或检查环境
  2. 2. 创建 Service 资源 → 拉取依赖或配置
  3. 3. 推送到 Registry → 启动核心服务
  4. 4. Knative 自动扩缩 → 验证运行状态
  5. 5. 0 实例时自动缩容 → 部署上线或回归测试
