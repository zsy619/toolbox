TiDB 容器化分布式数据库实战

MySQL 兼容 + 水平扩展 + HTAP 实时分析

Chapter 01

TiDB 3 层架构

  • PD(Placement Driver):集群元数据 + 调度 + TSO 时间戳
  • TiKV:分布式 KV 存储,Raft 共识 + RocksDB 引擎
  • TiDB Server:SQL 层,MySQL 协议兼容
  • TiFlash:列存副本,HTAP 实时分析(可选)
  • TiCDC:变更数据捕获,同步到下游 Kafka/MySQL
Chapter 02

最小集群 5 节点

  • pd1/pd2/pd3 三个 PD 节点(需奇数)
  • tikv1/tikv2/tikv3 三个 TiKV 节点(可扩展)
  • tidb1/tidb2/tidb3 三个 SQL 层(可扩展)
  • tiflash 节点按需部署,提供列存副本
  • Compose 启动顺序:PD → TiKV → TiDB
Chapter 03

MySQL 兼容性

  • 协议兼容:MySQL 5.7 / 8.0 协议
  • DDL/DML 大部分兼容 MySQL 语法
  • 不兼容:存储过程/触发器/外键/MyISAM
  • TiDB-specific:Auto Random 主键、AUTO_INCREMENT 不连续
  • 迁移工具:TiDB DM (Data Migration) 全量 + 增量
Chapter 04

水平扩缩容 3 步

  • 1) 添加 TiKV 节点:扩容只需 docker run 新节点 + tiup scale-out
  • 2) PD 自动 rebalance:数据按 region 重新分布
  • 3) 在线扩缩容:无停机,业务零感知
  • TiDB Server 也可独立扩容(应对连接数暴涨)
  • 缩容:先 drain 流量 → 节点 offline → 物理移除
Chapter 05

HTAP 实时分析

  • TiFlash 是 TiKV 的列存副本,Raft Learner 角色
  • 主从复制:TiKV(行存)→ Raft → TiFlash(列存)
  • 查询智能路由:小结果 TiKV,大分析 TiFlash
  • CREATE TABLE ... SET TIFLASH REPLICA = 2 启用
  • 适用场景:同一份数据,既支持 OLTP 又支持 OLAP

操作流程

可视化操作流程

🔄 5 步标准操作流程

  1. 启动 PD(3) → 启动容器或检查环境
  2. 启动 TiKV(3+) → 拉取依赖或配置
  3. 启动 TiDB(2+) → 启动核心服务
  4. 可选 TiFlash → 验证运行状态
  5. 验证 MySQL 协议 → 部署上线
