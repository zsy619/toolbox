Chapter 01

Go 容器化 3 大优势

  • 静态二进制:CGO_ENABLED=0 后无依赖,可放 scratch 镜像(0 层)
  • 小体积:典型 Go 二进制 10-30MB,镜像可缩到 15MB
  • 启动快:无 JVM 预热,毫秒级启动,适合 Serverless
  • scratch 镜像:0 层 0 包,只含你的二进制
  • distroless 替代:含 ca-certificates / tzdata 适合 HTTPS 调用
Chapter 02

3 阶段 Dockerfile 模板

  • Stage 1 (build):golang:1.22-alpine 含 Go 工具链
  • GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -ldflags='-s -w' -o /app
  • Stage 2 (compress):UPX --best --lzma 压缩二进制 30%
  • Stage 3 (runner):FROM scratch 或 gcr.io/distroless/static-debian12
  • COPY --from=compress /app /app + ca-certificates + tzdata
Chapter 03

生产配置 5 要点

  • GOMAXPROCS 自动检测容器 CPU 限制(Go 1.25+)
  • GOMEMLIMIT 自动检测容器内存限制(Go 1.19+)
  • GOGC=200 调整 GC 触发阈值,降低内存压力
  • GODEBUG=gctrace=1 调试 GC 行为(生产关)
  • pprof 端点:net/http/pprof 集成 + go tool pprof 分析
Chapter 04

主流 Go 框架容器化

  • Gin:小巧,中间件丰富,ORM 用 GORM
  • Kratos:Bilibili 出品,完整微服务框架 + gRPC
  • Go-Zero:字节跳动出品,内置代码生成
  • Fiber:Express 风格 API,基于 fasthttp 性能更高
  • 推荐:微服务用 Kratos,简单 API 用 Gin
Chapter 05

健康检查与可观测性

  • /healthz 端点:liveness probe(进程是否存活)
  • /readyz 端点:readiness probe(可服务,DB 连接就绪)
  • Prometheus 客户端:prometheus/client_golang 暴露 /metrics
  • OpenTelemetry:go.opentelemetry.io/otel 分布式追踪
  • 结构化日志:log/slog 1.21+ 内置 JSON logger

📝 Go 极小镜像

完整可执行代码,直接复制即可在生产环境使用:

Go 极小镜像 · dockerfile 
            
FROM golang:1.22-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -ldflags='-s -w' -o /app/server
FROM scratch
COPY --from=builder /app/server /server
ENTRYPOINT ["/server"]

可视化操作流程

🔄 5 步标准操作流程

  1. 写 Go 应用 → 启动容器或检查环境
  2. 阶段一 go build → 拉取依赖或配置
  3. 阶段二 scratch → 启动核心服务
  4. 复制二进制 → 验证运行状态
  5. 验证 < 20MB → 部署上线
