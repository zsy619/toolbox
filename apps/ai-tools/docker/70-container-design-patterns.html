容器设计模式 4 大经典实战

Sidecar / Ambassador / Adapter / Init Container

详解 K8s 容器设计模式 4 大经典(Sidecar / Ambassador / Adapter / Init Container)及其在 Docker Compose 中的实现,涵盖服务网格、配置注入等场景。

Chapter 01

Sidecar 边车模式

  • 主容器 + 辅助容器共享网络/数据卷
  • 典型场景:日志收集(Filebeat)、监控(Exporter)、代理(Envoy)
  • Docker Compose:两个 services 共享同一 network
  • K8s 实现:Pod 内多容器,共享 namespace
  • 代表:Spring Cloud + Prometheus Operator
Chapter 02

Ambassador 大使模式

  • 代理外部调用,屏蔽后端服务发现复杂性
  • 典型场景:连接 Redis 集群、Sentinel、DB 代理
  • Ambassador 容器代理 localhost: 请求转发
  • K8s 实现:同 Pod 中,Service 通过 ClusterIP 访问
  • 案例:数据访问代理(影子库 + 影子表)
Chapter 03

Adapter 适配器模式

  • 统一异构系统的输出格式
  • 典型场景:异构数据库 → 统一数据格式
  • Adapter 容器将多种数据源归一化为标准协议
  • 应用:多语言微服务的统一日志格式
  • 案例:Prometheus exporter 适配 MySQL/Redis/MongoDB
Chapter 04

Init Container 初始化容器

  • Pod 启动前运行的初始化容器,完成后消失
  • 典型场景:配置生成、依赖等待、权限设置
  • K8s:initContainers 与 containers 字段分离
  • Docker Compose:用 depends_on + healthcheck condition
  • 案例:Spring Cloud 应用等待 Nacos 启动后再启动
Chapter 05

组合应用 5 大场景

  • 1) Service Mesh:Envoy/Linkerd Sidecar 代理 + 主服务
  • 2) 日志收集:Filebeat/Fluentd Sidecar + 业务容器
  • 3) 监控:Prometheus exporter Sidecar + 业务容器
  • 4) 分布式追踪:Jaeger agent Sidecar + 业务容器
  • 5) 密钥注入:Init Container 从 Vault 拉取 secret
