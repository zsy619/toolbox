Chapter 01

Redis 4 种部署模式

  • 1) 单机:开发测试,无高可用
  • 2) 主从:1 主 N 从,手动故障转移
  • 3) Sentinel:1 主 N 从 + 3 哨兵,自动故障转移
  • 4) Cluster:3 主 3 从,水平扩展分片
  • 生产推荐:小数据用 Sentinel,大数据用 Cluster
Chapter 02

Sentinel 哨兵容器化

  • 3 个 Sentinel 节点:奇数避免脑裂(quorum=2)
  • sentinel monitor mymaster redis-master 6379 2
  • sentinel down-after-milliseconds mymaster 5000
  • sentinel failover-timeout mymaster 60000
  • Sentinel 间通过 gossip 协议发现彼此,无需全部配置
Chapter 03

Cluster 集群部署

  • 3 主 3 从:奇数 master + 副本(故障容忍 = 半数主故障)
  • 16384 虚拟槽:每个 master 负责部分槽位
  • 数据分片:CRC16(key) % 16384 决定槽位
  • Hash Tags:{user:1001} 保证多 key 路由同一节点
  • 客户端:redis-cli --cluster create 自动分配槽位
Chapter 04

持久化 2 选

  • RDB 快照:全量备份,默认 1 小时,文件紧凑,恢复快
  • AOF 追加日志:增量记录,everysec 每秒刷盘,文件大
  • RDB+AOF 混合:Redis 4.0+,推荐 appendonly yes + aof-use-rdb-preamble
  • AOF 重写:子进程完成,避免阻塞主线程
  • fsync 策略:always 慢但安全 / everysec 平衡 / no 最快
Chapter 05

性能调优 5 关键

  • maxmemory 4gb + maxmemory-policy allkeys-lru 内存淘汰
  • lazy-freeing + lazy-eviction 减少删除延迟
  • io-threads 4 启用多线程 IO(Redis 6+)
  • 禁用 THP:transparent_hugepage never 提升性能 10x
  • 慢查询 slowlog-log-slower-than 10000 微秒阈值
💡 bigkey 处理

redis-cli --bigkeys 扫描大 key,unlink 异步删除

⚠️ 内存陷阱

容器内存 80% 给 Redis,20% 给宿主机页缓存
