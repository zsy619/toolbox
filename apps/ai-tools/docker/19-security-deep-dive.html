Chapter 01

Linux capabilities 37 项

  • 默认:CHOWN/DAC_OVERRIDE/FOWNER/SETUID/SETGID/SETPCAP/NET_BIND_SERVICE 等
  • 默认禁用:SYS_ADMIN/SYS_PTRACE/SYS_MODULE/MAC_ADMIN
  • 全禁用:--cap-drop ALL + 显式 --cap-add 必要项
  • 生产示例:web 服务仅需 NET_BIND_SERVICE,DB 需 IPC_LOCK
Chapter 02

seccomp 系统调用过滤

  • 默认配置:Docker 自带 300+ 允许的 syscall 白名单
  • 自定义:seccomp_profile.json + --security-opt seccomp=xxx
  • 危险 syscall:reboot/swapon/umount/kexec_load 全部禁用
  • 审计:strace -f -p 跟踪容器进程系统调用
Chapter 03

AppArmor vs SELinux

  • AppArmor:Ubuntu 主流,基于路径的 MAC
  • SELinux:CentOS/RHEL 主流,基于标签的 MAC
  • Docker 默认:app-armor=docker-default / selinux 启用
  • 自定义策略:aa-genprof / audit2allow 工具
Chapter 04

Rootless 模式 5 优势

  • 1) Docker daemon 以非 root 用户运行
  • 2) 容器进程命名空间无 root 权限
  • 3) 攻击面更小(无特权升级路径)
  • 4) 适合 CI/CD + 多用户共享宿主机
  • 5) slirp4netns / pasta 用户态网络
Chapter 05

镜像签名与验证

  • Docker Content Trust:DCT_NOTARY 签名验证
  • Docker Content Trust 启用:export DOCKER_CONTENT_TRUST=1
  • Cosign + Sigstore:新一代签名,简化工作流
  • Admission Controller(K8s):校验镜像签名后才准入
  • 镜像扫描:Trivy / Snyk / Anchore 三选一
💡 安全清单

USER 非 root + --read-only + --cap-drop ALL + seccomp + 镜像签名

⚠️ 性能影响

默认 seccomp/AppArmor 性能影响 < 1%,基本可忽略
