什么是 Docker 引擎

Docker 引擎是用来 运行和管理容器的核心软件 ,其现代架构由 4 部分主要组件构成: Docker Client、Dockerd、Containerd 与 Runc ,加上不可或缺的 Shim(垫片) 。理解这 5 大组件的职责划分,是掌握 Docker 内部工作原理的关键。

引擎核心价值

从用户视角看,Docker 引擎是 单一可执行文件 docker ;从架构视角看,它是 由多个独立组件协作 构成的复杂系统——每个组件都有独立功能,组件间通过明确的接口(API/gRPC)协作,这种分层设计让 Docker 既能持续演进,又能保持稳定兼容。

Chapter 01

Docker 引擎架构 5 大组件

Docker 引擎的现代架构由 4 部分主要组件构成: Docker Client、Dockerd、Containerd 与 Runc ,加上不可或缺的 Shim(垫片) 。

5 大组件协作流程图

1.1 Docker Client

Docker 客户端,即 Docker 引擎提供的 CLI 工具 ,用于用户向 Docker 提交命令请求。用户在终端输入 docker ps 、 docker run 等命令,实际是 Docker Client 在向 Dockerd 发起 HTTP REST API 请求。

1.2 Dockerd

Dockerd 即 Docker Daemon(Docker 守护进程) 。主要包含的功能有:

  • 镜像构建 (docker build)
  • 镜像管理 (docker images、docker rmi 等)
  • REST API (供 Docker Client 调用)
  • 核心网络 (bridge/host/overlay 网络管理)
  • 编排 (Swarm mode)

Dockerd 通过 gRPC 与 Containerd 进行通信。

1.3 Containerd

Containerd 即 Container Daemon(容器守护进程) 。主要功能是 管理容器的生命周期 。Containerd 本身 不会创建容器 ,而是调用 Runc 来创建容器。

1.4 Runc

Runc,Run Container,只有一个作用: 创建容器 。其本质是一个 独立的容器运行时 CLI 工具 。Runc 在 fork 出一个容器子进程后启动该容器进程。容器进程启动完毕后, Runc 会自动退出 。

1.5 Shim(垫片)

Shim(垫片)是实现 " Daemonless Container(无 Docker Daemon 与 Container Daemon 容器) " 不可或缺的工具,使容器与 Docker Daemon 解耦 ,使得 Docker Daemon 的维护与升级不会影响运行中的容器。

💡

进程关系链 :每次创建容器,Containerd 会 fork 出 Shim 进程,由 Shim 进程 fork 出 Runc 进程。当 Runc 退出之前,会先将 新容器进程的父进程 指定为相应的 Shim 进程。除了作为容器的父进程外,Shim 进程还具有两个重要的功能:1) 保持所有 STDIN 与 STDOUT 流的开启状态 ,从而使当 Docker Daemon 重启时,容器不会因为 Pipe 的关闭而终止;2) 将容器的退出状态反馈给 Docker Daemon 。

Docker 分为三类:

类型 名称 定位 适用场景
Moby Moby Project Docker 开源项目,提供基础组件 二次开发、平台定制
Docker-CE Community Edition 社区版,免费 个人/小型团队、学习测试
Docker-EE Enterprise Edition 企业版,付费 企业关键系统、生产环境

选择建议 :日常学习和中小型项目用 Docker-CE ;大型企业、对安全/合规/支持有高要求的关键系统用 Docker-EE ;想深入研究 Docker 内部机制或做衍生项目(如 containerd、Podman)可参考 Moby 源码。

Chapter 06

Docker 镜像是什么

镜像是一种 轻量级、可执行的独立软件包 ,也可以说是一个 精简的操作系统 。

6.1 镜像核心特性

  • 镜像中包含 应用软件及其运行环境
  • 镜像包含某个软件所需的 所有内容 ,包括 代码、库、环境变量和配置文件 等
  • 几乎所有应用,直接打包为 Docker 镜像后就可以运行
  • 镜像运行时称为 容器 。容器设计得非常小巧,所以镜像也比较小
  • 镜像不包含内核 ,其 共享宿主机的内核
  • 镜像中只包含 简单的 Shell ,或没有 Shell
🎯

为何"共享内核" 很重要:这是 Docker 镜像体积小( < 几十 MB)而虚拟机镜像大(>几 GB)的根本原因。Docker 镜像只包含应用运行所需的 用户态文件 (如 /usr/bin、/etc/、/var/),而 内核 由宿主机提供。

FAQ

常见问题

Docker 引擎由哪些组件构成?

Docker 引擎现代架构由 4 部分主要组件构成: Docker Client、Dockerd、Containerd 与 Runc 。还有不可或缺的部分 Shim(垫片) 。1) Docker Client :CLI 工具,用户向 Docker 提交命令;2) Dockerd :Docker 守护进程,负责镜像构建/管理/REST API/核心网络/编排,通过 gRPC 与 Containerd 通信;3) Containerd :管理容器生命周期,本身不创建容器,而是调用 Runc;4) Runc :Run Container,只有一个作用就是创建容器;5) Shim :实现 Daemonless Container(无 Dockerd 与 Containerd 容器),使容器与 Dockerd 解耦,Dockerd 维护与升级不影响运行中的容器。

Shim 的作用是什么?

Shim(垫片)是实现 Daemonless Container(无 Docker Daemon 与 Container Daemon 容器) 不可或缺的工具,使容器与 Docker Daemon 解耦 ,使得 Docker Daemon 的维护与升级不会影响运行中的容器。具体作用:1) 保持所有 STDIN 与 STDOUT 流的开启状态 ,从而使当 Docker Daemon 重启时,容器不会因为 Pipe 的关闭而终止;2) 将容器的退出状态反馈给 Docker Daemon 。 每次创建容器 ,Containerd 会 fork 出 Shim 进程,由 Shim 进程 fork 出 Runc 进程。当 Runc 退出之前,会先将新容器进程的父进程指定为相应的 Shim 进程。

Docker 分为哪三类?

Docker 分为三类:1) Moby :Docker 开源项目,提供基础组件;2) 社区版 Docker-CE :Community Edition,免费,适合个人/小型团队;3) 企业版 Docker-EE :Enterprise Edition,付费,提供企业级支持、安全与编排能力。生产环境一般用 Docker-CE ,企业关键系统用 Docker-EE 。

Docker 镜像是什么?

镜像是一种 轻量级、可执行的独立软件包 ,也可以说是一个 精简的操作系统 。镜像中包含 应用软件及其运行环境 。镜像包含某个软件所需的 所有内容 ,包括 代码、库、环境变量和配置文件 等。几乎所有应用,直接打包为 Docker 镜像后就可以运行。镜像运行时称为容器。容器设计得非常小巧,所以镜像也比较小。 镜像不包含内核 ,其 共享宿主机的内核 ;镜像中只包含简单的 Shell,或没有 Shell。

Docker 镜像仓库分哪几类?

根据镜像发布者的不同,分成 4 类:1) Docker Official Image :Docker 官方镜像仓库,由 Docker 官方构建发布,质量高且安全,有完善的文档(如 Zookeeper/Redis/Nginx 等)。官方镜像仓库的 一般直接为该类软件的名称;2) Verified Publisher :已验证发布者仓库,由 Docker 公司认证通过的第三方(大型企业或组织)发布,有 VERIFIED PUBLISHER 标识。非官方镜像仓库名称格式为 /;3) Sponsored OSS :由 Docker 公司赞助开发的镜像仓库,质量有保证;4) 无认证仓库 :没有以上任何标识的仓库,质量无法保证,使用时需谨慎。

什么是 AUTOMATED 自动化镜像?

AUTOMATED 表示当前镜像是否是自动化镜像 。使用 Docker Hub 连接一个 包含 Dockerfile 文件的 GitHub 仓库 (专门构建镜像用的文件),然后 Docker Hub 就会自动创建镜像。这样构建出的镜像就是自动化镜像。 只要 Dockerfile 发生变化,那么 Docker Hub 就会构建出新的镜像 。自动化镜像的好处是源码与镜像构建过程完全透明、可审计、可复现。

docker save/load 与 docker export/import 有什么区别?

docker save/load :
1) save 将一个或多个镜像导出为 tar 文件,如 docker save -o my.tar busybox:latest hello-world:latest ;
2) load 将 tar 文件导入并加载为镜像,保留原镜像的所有分层与 metadata;
3) 镜像的 ImageID、repository、tag 全部保留,镜像与原镜像 完全一致 。

docker export/import :
1) export 作用于 容器 (不是镜像),导出当前容器文件系统快照;
2) import 加载为新镜像,但 丢弃原镜像的所有历史记录 ,ImageID 也会变化;
3) 通常用于 迁移容器当前状态 。
