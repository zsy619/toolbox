Docker Compose 容器编排完全指南

从 compose.yml 语法到 Spring Boot + MySQL + Redis 一键编排,Docker Compose 是多容器应用部署的事实标准。本文详解 6 大顶级属性、常用命令、完整实战与自定义命名。

最后更新 2026-06-03
Docker Compose compose.yml 容器编排 Spring Boot MySQL Redis

为什么需要 Docker Compose

现代应用大多由 多个微服务 组成:订单管理、用户管理、品类管理、网关、数据库、缓存……部署和管理大量的服务容器非常繁琐。而 Docker Compose 正是为解决此问题而生。

Docker Compose 是什么

Docker Compose 是一个安装在 Docker 主机上的 Docker 容器编排外部工具 ,通过一个声明式的 配置文件描述整个应用 ,然后通过 一条命令 完成应用部署。部署成功后,可通过一系列简单命令完成其生命周期管理。其 前身是 Fig(无花果) 。

💡

Compose 解决的不是"容器怎么跑"而是"应用怎么组装"。Dockerfile 解决镜像构建,docker run 解决单容器启动,Compose 解决 多容器协同 。

Chapter 01

Compose 文件结构

Docker Compose 使用 YAML 文件 来定义服务,默认文件名为 compose.yml ,同时也支持 docker-compose.yml (旧版命名)。

1.1 项目目录约定

由于一个 compose 文件为一个项目服务,一般按以下流程创建:

  1. 创建项目目录(目录名建议与项目名一致)
  2. 将项目所需的所有镜像、微服务的 Dockerfile 放入该目录
  3. 在该目录中新建 compose 文件

1.2 文件名对比

文件名 适用命令 状态
compose.yml docker compose (无连字符) ✅ 推荐,新版主流
docker-compose.yml docker-compose (有连字符) 旧版兼容
Chapter 02

compose.yml 的 6 大顶级属性

compose 文件包含 6 个顶级属性: version 、 services 、 networks 、 volumes 、 configs 、 secrets 及其子属性。

2.1 version (已过时)

顶级属性,但是已过时, 不再需要 出现在 compose 文件中。Docker Compose v2 起,Docker Engine 28.0+ 完全自动推断,无需指定版本。

2.2 services (核心)

顶级属性,用于定义一个应用所包含的服务。Docker Compose 会将 每个服务部署在各自容器中 。

2.3 networks (网络)

顶级属性,用于定义与创建网络:

yaml 
                
                  
services:
                  
                  
apps:
                  
                  
# 服务名称
                  
                  
networks:
                  
                  
# 这里使用的不是网络名称
                  
                  
-
                  
 app_bridge
                  
networks:
                  
                  
app_bridge:
                  
                  
name:
                  
 appBGnet
                  
# 这才是网络名称
                  
                  
driver:
                  
 bridge
                  
# 网络驱动,缺省为 bridge
                  
                  
attachable:
                  
                  
# true 表示允许其他独立容器连接

2.4 volumes (数据卷)

顶级属性,用于定义和创建应用中所用到的所有 volume (数据卷),实现 数据持久化 。MySQL、Redis 等有状态服务必须挂载数据卷,否则容器删除后数据丢失。

2.5 configs (配置文件)

用于定义 非敏感 配置文件(如 nginx.conf、redis.conf),通过文件或外部注入到容器中。

2.6 secrets (敏感信息)

用于定义 敏感信息 (如数据库密码、API 密钥、TLS 证书),通过文件或外部 secret store 注入,不会出现在环境变量或镜像层中。

Chapter 03

常用命令

bash 
                
                  
docker-compose pull
                  
                  
# 拉取 compose 中服务依赖的全部或指定镜像
                  
                  
docker-compose config
                  
                  
# 检查 compose 文件是否正确(-q 仅输出错误)
                  
                  
docker-compose up
                  
                  
# 启动所有容器
                  
                  
docker-compose logs
                  
                  
# 查看所有/指定服务的运行日志
                  
                  
docker-compose ps
                  
                  
# 列出所有/指定服务
                  
                  
docker-compose top
                  
                  
# 列出正在运行的所有/指定服务
                  
                  
docker-compose images
                  
                  
# 列出所有/指定服务镜像
                  
                  
docker-compose port
                  
                  
# 列出指定容器的指定端口所映射的宿主机端口
                  
                  
docker-compose run
                  
                  
# 在指定服务上执行一条命令
                  
                  
docker-compose exec
                  
                  
# 进入指定容器
                  
                  
docker-compose pause
                  
                  
# 暂停 compose 中所有/指定容器
                  
                  
docker-compose unpause
                  
                  
# 恢复处于暂停状态的容器
                  
                  
docker-compose stop
                  
                  
# 停止 compose 中所有/指定容器
                  
                  
docker-compose restart
                  
                  
# 重启 compose 中所有/指定容器
                  
                  
docker-compose start
                  
                  
# 启动 compose 中所有/指定容器
                  
                  
docker-compose kill
                  
                  
# 停止指定容器
                  
                  
docker-compose rm
                  
                  
# 删除处于停止状态的容器
                  
                  
docker-compose down
                  
                  
# 停止并删除所有容器、网络、镜像、数据卷
⚠️

docker-compose down 默认 不删除数据卷 ,数据可保留。如果要彻底清理,使用 docker-compose down -v 。

Chapter 05

Spring Boot 完整实战

以一个 Spring Boot 项目为例,演示如何组合 Redis 与 MySQL,完整通过 Compose 一键部署。

5.1 项目结构

典型 Spring Boot + MySQL + Redis 项目结构:

  • pom.xml (Maven 依赖)
  • src/main/java/... (Java 源码:实体、Controller、Service、Dao)
  • src/main/resources/application.yml (应用配置)
  • Dockerfile (镜像构建)
  • compose.yml (容器编排)

5.2 application.yml 配置

Compose 启动后,容器之间通过 服务名 (而非 IP)互访(DNS 自动解析)。所以数据库主机名从 192.168.192.101 改为 mysql 、Redis 主机名改为 redis 。

FAQ

常见问题

Docker Compose 与 Dockerfile、docker run 有什么区别?

Dockerfile 是镜像构建的说明书,定义如何从一个基础镜像构建出可运行的应用镜像;docker run 是启动单个容器的命令,适合 1-2 个容器场景;Docker Compose 是多容器编排工具,通过 yml 文件一键管理整个应用栈(应用 + 数据库 + 缓存 + 网关),适合微服务场景。三者关系:用 Dockerfile 构建镜像,用 docker run 验证,最终用 Compose 统一编排。

compose.yml 和 docker-compose.yml 有什么区别?

两者都支持,只是默认文件名不同:Docker Compose v2(无连字符 docker compose)默认使用 compose.yml;v1(有连字符 docker-compose)默认使用 docker-compose.yml。推荐使用 compose.yml + docker compose 命令,这是当前主流且未来方向。

Compose 中的 version 字段还需要写吗?

不需要。Docker Compose v2 起,version 顶级属性已过时且不再需要。Docker Engine 28.0+ 起,Docker Compose Spec 统一由 Docker 自动推断,完全不需要 version 字段。继续写 version 不会有错误,但属于冗余配置。

depends_on 能保证服务启动顺序吗?

depends_on 仅控制 启动顺序 (先启动依赖,再启动当前服务),但 不等待依赖服务就绪 (如 MySQL 启动后还需 5-10 秒初始化数据)。如果应用需要等待数据库就绪,需要:1) 应用层实现重试连接;2) 使用 healthcheck + condition: service_healthy;3) 使用 wait-for-it.sh 脚本。

docker-compose down 会删除数据吗?

down 命令会停止并删除容器、网络,但 默认不删除数据卷 (volumes),所以 MySQL 等数据可以保留。如果要彻底删除包括数据卷,使用 docker-compose down -v 。新版 docker compose 命令同样支持 -v 选项。

如何在 Compose 中使用环境变量?

三种方式:1) compose.yml 中直接 environment 写死值;2) .env 文件中定义 KEY=VALUE,compose.yml 用 ${KEY} 引用;3) shell 环境变量,compose.yml 用 ${VAR} 引用(需先 export)。推荐敏感信息(密码)使用 Docker secrets 而非 environment,生产环境强烈建议。

Compose 文件的 6 个顶级属性是哪些?

1) version:已过时,无需再写;2) services:定义应用包含的所有服务,每个服务部署为独立容器;3) networks:定义和创建网络,服务通过 networks 加入;4) volumes:定义和创建数据卷,用于持久化;5) configs:定义非敏感配置文件,通过文件或外部注入;6) secrets:定义敏感信息(如密码、证书),通过文件或外部注入。
