Chapter 01

WebSocket 协议核心

  • HTTP 升级握手:Upgrade: websocket + Connection: Upgrade
  • 双向全双工:服务端可主动推送,适合聊天/通知/实时数据
  • 心跳保活:ping/pong 帧 30s 一次,防止 NAT 超时
  • 子协议:Sec-WebSocket-Protocol 自定义应用层协议
  • 压缩扩展:permessage-deflate 减少带宽
Chapter 02

容器化 3 大挑战

  • 1) 黏性会话:同一用户路由到同一容器(否则 session 丢失)
  • 2) 状态共享:多容器间通过 Redis 共享连接状态
  • 3) 长连接超时:K8s 默认 30s 空闲超时需调整
  • 解决方案:K8s sessionAffinity=ClientIP + redis adapter
  • Socket.io-redis-adapter 自动同步事件给所有实例
Chapter 03

Dockerfile 与健康检查

  • WebSocket 服务端口:3000 / 8080 / 同 HTTP 端口共用
  • HEALTHCHECK 用 HTTP 而非 WS:GET /health 返回 200
  • liveness 探针不能直接用 WebSocket(K8s 不支持)
  • readiness 探针:HTTP 200 + 数据库连接 + Redis 连接
  • 启动时间预:WebSocket 启动快(<5s),start-period=10s
Chapter 04

Nginx 反向代理配置

  • Upgrade / Connection 头透传:proxy_set_header Upgrade $http_upgrade
  • 60s 超时:proxy_read_timeout 60s(默认 60s 适合大多数 WS)
  • wss 加密:Let's Encrypt 自动证书 + certbot
  • X-Forwarded-For:proxy_set_header X-Real-IP $remote_addr
  • buffering off:proxy_buffering off 实时转发
Chapter 05

K8s 部署关键

  • sessionAffinity: ClientIP, timeoutSeconds: 3600(1 小时)
  • Ingress nginx.ingress.kubernetes.io/proxy-read-timeout: 3600
  • HPA 不适合 WebSocket(基于连接数而非 CPU)
  • KEDA prometheus scaler 基于活跃连接数伸缩
  • PodDisruptionBudget 防止滚动升级断连
💡 最大并发

单容器 Socket.io 10K+ 连接,单节点 Nginx 可支撑 100K 活跃 WS

⚠️ 浏览器限制

Chrome 单域名最多 6 个 WS 并发,业务设计需考虑

📝 WS 心跳保活

完整可执行代码,直接复制即可在生产环境使用:

WS 心跳保活 · javascript 
            
const WebSocket = require('ws');
const wss = new WebSocket.Server({ port: 8080 });
setInterval(() => {
  wss.clients.forEach(ws => {
    if (ws.isAlive === false) return ws.terminate();
    ws.isAlive = false; ws.ping();
  });
}, 30000);
