Docker Build Cache 机制与数据持久化完全指南

理解 Docker 镜像构建的 build cache 机制、父子镜像关系、4 种 cache 失效情况;掌握数据持久化的 3 种方式(数据卷 / Bind mounts / tmpfs)以及 docker run -v 与 Dockerfile VOLUME 的核心区别。

为什么需要理解 Build Cache 与持久化

Docker 镜像由 多层只读文件系统 组成,构建过程中各层可被 复用 (build cache),极大提升构建速度。容器运行后产生的数据默认存放在 容器层 (UnionFS 联合文件系统)中,容器被删除时数据全部丢失——这就是为什么要 数据持久化 。

Docker 的两个核心机制

1) Build Cache :镜像构建时,各层可被本地复用,减少网络下载与磁盘占用;
2) 数据持久化 :容器数据(数据库、配置、上传文件等)需要保存到 宿主机 或 外部存储 ,以避免容器删除造成数据丢失。

Chapter 01

镜像的生成过程(父子关系)

Docker 镜像的构建过程,大量应用了 镜像间的父子关系 :下层镜像作为上层镜像的 父镜像 ,下层镜像是上层镜像的输入。上层镜像是在下层镜像的基础上变化而来。

1.1 搭建测试环境

在 /root/cache 目录下新建 hello.log 文件,并创建 Dockerfile :

dockerfile 
                
                  
FROM
                  
 centos:7
                  
LABEL
                  
 auth="TOM"
                  
COPY
                  
 hello.log /var/log
                  
RUN
                  
 yum -y install vim
                  
CMD
                  
 /bin/bash

第一次构建镜像:

bash 
                
                  
docker build
                  
                  
-t
                  
 test:1.0 .

1.2 各指令的镜像层生成

指令 是否产生新镜像层 说明
FROM centos:7 否 使用指定基础镜像,本身不产生新层
LABEL auth="TOM" 是(json 层) 仅修改镜像 json 文件内容,新层只记录 json 变化
COPY hello.log /var/log 是(文件层) 生成新文件系统镜像层
RUN yum -y install vim 是(文件层) 下载并安装工具改变了文件系统大小
CMD /bin/bash 是(json 层) 指令写入 json,改变 json 大小,镜像 id 也变
💡

理解"层"是关键:每个 Dockerfile 指令通常对应一个 只读镜像层 (json 变化或文件系统变化)。多个只读镜像层堆叠组成最终镜像,这种 分层架构 正是 build cache 能复用层的基础。

Chapter 02

build cache 机制

2.1 修改 Dockerfile 后重新构建

给原 Dockerfile 加一行 EXPOSE 9000 :

dockerfile 
                
                  
FROM
                  
 centos:7
                  
LABEL
                  
 auth="TOM"
                  
COPY
                  
 hello.log /var/log
                  
RUN
                  
 yum -y install vim
                  
CMD
                  
 /bin/bash
                  
EXPOSE
                  
 9000

重新构建:

bash 
                
                  
docker build
                  
                  
-t
                  
 test:2.0 .

此时构建过程中会发现很多 using cache ——这就是使用了 build cache 。

2.2 查看镜像层复用

bash 
                
                  
docker history
                  
 test:1.0
                  
docker history
                  
 test:2.0

查看这两个镜像的 docker history ,会发现除了新加的 EXPOSE 镜像层外, 其他层完全相同 。这就是 test:2.0 在构建时 复用了 test:1.0 的镜像层 。

2.3 build cache 的定义

构建镜像时,当发现新构建的镜像层与 本地已存在 的镜像层重复时,默认会复用本地的镜像层,这种机制称为 build cache 。

build cache 的本质

docker build cache 不是占用内存的 cache ,而是 磁盘中对镜像层的检索、复用机制 。无论是关闭 Docker 引擎,还是重启 Docker 宿主机,只要本地有镜像层,就会复用。

Chapter 03

build cache 失效 4 种情况

3.1 Dockerfile 文件发生变化

当 Dockerfile 文件中某个指令内容发生变化,那么变化的这个指令层开始, 所有后续镜像层 cache 全部失效 。镜像关系本质上是一种 树状关系 ,只要上层节点变了,那么下层节点也就全部变化了。

3.2 ADD/COPY 指令内容变化

Dockerfile 文件内容没变化,但是 ADD 或 COPY 指令所复制的 文件内容变化了 ,也会导致 build cache 失效。

3.3 RUN 指令外部依赖变化

Dockerfile 文件内容没变化,但是 RUN 命令外部依赖变了,比如要安装的 VIM 软件源变了(版本变化、下载地址变化等)。

3.4 指定不使用 build cache

bash 
                
                  
docker build
                  
                  
--no-cache
                  
                  
-t
                  
 test:11.0 .
🎯

优化 Dockerfile 提升 build cache 命中率 :把 容易变化的指令 (如 COPY 、 ADD 、应用代码)放在 后面 ,把 容易缓存的指令 (如 RUN apt-get 、 RUN pip install )放在 前面 。这样代码修改时前面的依赖层能被复用,只需重做代码层,构建时间可缩短 80% 以上。

Chapter 04

数据持久化的必要性

在容器层的 UnionFS(联合文件系统) 中对文件/目录的任何修改,在容器丢失或被删除后,这些修改将 全部丢失 。若要保存这些修改,一般有两种方式:

方式 说明 适用场景
定制镜像持久化 将修改过的容器生成新镜像(docker commit) 不常变更的快照,不适合频繁变更
数据卷持久化 通过数据卷将修改同步到宿主机 生产环境首选,适合频繁变更

4.1 定制镜像持久化实战

以 Tomcat 为例,演示如何保存容器内修改:

bash 
                
                  
# 1. 以分离模式运行 tomcat 容器
                  
                  
docker run
                  
                  
--name
                  
 mytom
                  
-dp
                  
 8081:8080 tomcat:10.0
                  
# 2. 进入容器后修改目录(把 webapps.list 改为 webapps 才能访问)
                  
                  
docker exec
                  
                  
-it
                  
 mytom /bin/bash
                  
rm
                  
                  
-rf
                  
 webapps
                  
mv
                  
 webapps.list webapps
                  
# 3. 容器生成新镜像(永久保存修改)
                  
                  
docker commit
                  
                  
-m
                  
=
                  
"modify webapps"
                  
                  
-a
                  
=
                  
"jerry"
                  
 mytom tomcat10:own
⚠️

这种方式的 新镜像就永久保存了我们的修改 ,但 不适合变更频繁的场景 ——每次修改都要 commit 一次,镜像会越积越多。生产环境请用数据卷持久化。

Chapter 05

数据卷介绍与特性

数据卷是 宿主机 中的一个特殊的文件/目录,这个文件/目录与容器中的另一个文件/目录进行了 关联 ,在任何一端对文件/目录进行写操作,另一端都会同时改变。

  • 宿主机中的这个文件/目录称为 数据卷
  • 容器中的这个关联文件/目录称为数据卷在该容器中的 挂载点

数据卷 完全独立于容器的生命周期 ,属于宿主机文件系统,当容器被删除时, 不会删除其挂载的数据卷 。

5.1 数据卷的 4 大特性

  1. 数据卷在容器启动时初始化,如果容器启动后容器本身包含了数据,那么数据在容器启动后直接出现在数据卷中,反之依然
  2. 可以对数据卷或挂载点的内容直接修改,修改后另一端可 立即生效
  3. 数据卷 一直存在 ,即使容器被删除
  4. 数据卷可以在 容器之间共享和复用
Chapter 06

3 种数据同步方式

Docker 提供了三种实时同步(宿主机与容器间数据同步)方式:

方式 管理方 宿主机位置 适合场景
数据卷(Volume) Docker 管理 /var/lib/docker/volumes/ 生产首选 ,无需关心具体路径,Docker 自动分配
Bind mounts(绑定挂载) 用户指定 宿主机 任意 路径 开发环境,需要明确指定宿主机路径(IDE 联动、配置文件注入)
tmpfs(临时文件系统) 内存 仅存在于内存 敏感数据/密码文件,容器停止后数据消失
Chapter 07

读写数据卷与只读数据卷

7.1 读写数据卷(默认)

读写数据卷指 容器对挂载点有读写权限 。数据卷是在启动容器时指定,语法格式:

bash 
                
                  
docker run
                  
                  
-it
                  
                  
-v
                  
 /宿主机目录绝对路径:/容器内目录绝对路径 镜像

如果指定的目录不存在会自动创建。完整示例:

bash 
                
                  
# 创建数据卷
                  
                  
docker run
                  
                  
--name
                  
 myubuntu
                  
-it
                  
                  
-v
                  
 /root/host_mount:/opt/uc_mount ubuntu:latest /bin/bash
                  
# 在宿主机数据卷创建一个新文件,在容器中就可以看到
                  
                  
echo
                  
                  
"host created file"
                  
 > hello.log

即使容器停止,数据仍会保存;当容器重启后,再进入容器就可以查看:

bash 
                
                  
# 退出容器
                  
                  
exit
                  
                  
# 重启容器
                  
                  
docker start
                  
 myubuntu
                  
# 进入容器
                  
                  
docker exec
                  
                  
-it
                  
 myubuntu /bin/bash
                  
# 查看挂载点
                  
                  
cat
                  
 /opt/uc_mount/hello.log

查看数据卷详情:

bash 
                
                  
docker inspect
                  
 myubuntu

7.2 只读数据卷(ro)

只读数据卷指的是 容器对挂载点只读 , 宿主机对数据卷始终是读写 。这样是为了防止容器在运行过程中对文件进行修改:

bash 
                
                  
docker run
                  
                  
--name
                  
 myubuntu
                  
-it
                  
                  
-v
                  
 /root/host_mount:/opt/uc_mount:ro ubuntu:latest /bin/bash
🎯

只读数据卷常用于:1) 防止容器运行时意外修改配置;2) 共享只读配置文件/证书;3) 提高安全性(容器被攻陷也无法篡改配置文件)。

Chapter 08

数据卷共享(--volumes-from)

当一个容器和另一个容器使用 相同的数据卷 时,这两个容器就实现了" 数据卷共享 "。

当一个容器 C 启动时创建并挂载了数据卷,而其他容器也要共享这个数据卷,那么这些容器只需要在 docker run 时通过 --volumes-from [容器 C] 选项就能实现数据卷共享。此时 容器 C 称为数据卷容器 。

8.1 数据卷容器共享实战

假设数据卷容器名为 myubuntu ,那么另一个容器创建如下:

bash 
                
                  
docker run
                  
                  
--name
                  
 myubuntu2
                  
--volumes-from
                  
 myubuntu
                  
-it
                  
 ubuntu:latest /bin/bash

此时就完成了两个容器的数据卷共享。

8.2 数据卷容器的特点

  • 数据卷容器 可以处于停止状态 (不需运行),但其数据卷会持续存在
  • 典型应用:把数据库数据放在数据卷容器中,多个应用容器( --volumes-from )同时挂载共享同一份数据
  • 实现配置/数据 集中管理
Chapter 09

Dockerfile VOLUME 指令(镜像层声明挂载点)

Dockerfile 持久化是通过 VOLUME 指令指定数据卷的方式实现持久化。

VOLUME 指令可以在容器中创建数据卷的 挂载点 。其参数可以是字符串数组,或者使用空格隔开:

dockerfile 
                
                  
# 两种写法等价
                  
                  
VOLUME
                  
 [
                  
"/var/www"
                  
,
                  
"/etc/apache"
                  
]
                  
VOLUME
                  
 /var/www /etc/apache

9.1 实现持久化 4 步走

1. 创建 Dockerfile (此容器有 2 个挂载点 /opt/xxx 和 /opt/ooo ):

dockerfile 
                
                  
FROM
                  
 centos:7
                  
VOLUME
                  
 /opt/xxx /opt/ooo
                  
CMD
                  
 /bin/bash

2. 构建镜像 :

bash 
                
                  
docker build
                  
                  
-t
                  
 volscon .

3. 运行镜像 :

bash 
                
                  
docker run
                  
                  
--name
                  
 myvols
                  
-it
                  
 volscon

4. 查看数据卷详情 (在 Mounts 字段中可以看到两个自动创建的 匿名数据卷 ):

bash 
                
                  
docker inspect
                  
 myvols
Chapter 10

docker run -v 与 Dockerfile VOLUME 的区别

维度 docker run -v Dockerfile VOLUME
作用对象 已存在的容器(启动时) 准备创建的镜像(构建时)
能否指定宿主机目录 ✅ 可以指定具体路径 ❌ 无法指定,Docker 自动分配匿名卷
优先级 会 覆盖 Dockerfile VOLUME 指令 只在镜像中预声明挂载点
数据卷名称 显式命名或匿名 通常为 匿名卷 (自动生成哈希名)
生产使用 推荐 (配合命名卷) 适合"希望所有运行的容器都有该挂载点"
🎯

生产推荐使用 命名卷 (Named Volume): docker volume create mydata 创建,再用 -v mydata:/path 挂载。这样数据卷有明确名称,便于管理、备份、迁移。

FAQ

常见问题

什么是 Docker build cache?

构建镜像时,当发现新构建的镜像层与本地已存在的镜像层重复时,默认会复用本地的镜像层,这种机制称为 build cache。该机制加快了镜像的构建过程,节省空间。docker build cache 不是占用内存的 cache,而是磁盘中对镜像层的检索、复用机制,无论是关闭 Docker 引擎还是重启宿主机,只要本地有镜像层,就会复用。

build cache 在什么情况下会失效?

1) Dockerfile 文件内容发生变化:从变化的指令层开始,所有后续镜像层 cache 全部失效(树状依赖);2) ADD 或 COPY 指令所复制的文件内容变化;3) RUN 指令外部依赖变化(例如 yum install 的软件源/版本变化);4) 通过 --no-cache 参数显式禁用。需要修改 Dockerfile 时,把容易变化的指令(如 COPY)放在后面,容易缓存的指令(如 RUN yum)放在前面,能显著提升构建速度。

数据持久化的 3 种方式是什么?

Docker 提供了 3 种宿主机与容器间的数据同步方式:1) 数据卷(Volume):由 Docker 管理,存储在 /var/lib/docker/volumes/ 下,推荐生产使用;2) Bind mounts(绑定挂载):用户指定宿主机任意路径挂载到容器,适合开发环境,需要明确指定路径;3) tmpfs(临时文件系统):存储在内存中,容器停止后数据消失,适合敏感数据/密码文件。

docker run -v 与 Dockerfile VOLUME 指令有什么区别?

1) 作用对象不同:docker run -v 针对已存在的容器启动;VOLUME 指令针对准备创建的镜像构建;2) 能否指定宿主机目录:docker run -v 可以指定宿主机数据卷目录;VOLUME 指令无法指定具体宿主机路径,挂载点由 Docker 自动分配匿名卷;3) 优先级:docker run -v 会覆盖 Dockerfile VOLUME 指令(后者只在镜像中预声明挂载点)。

什么是数据卷容器?

数据卷容器是挂载了一个或多个数据卷的容器,其他容器通过 --volumes-from <容器名> 共享它的数据卷。数据卷容器本身可以处于停止状态(不需运行),但其数据卷会持续存在。典型应用:把数据库数据放在数据卷容器中,多个应用容器(--volumes-from)同时挂载共享同一份数据,实现配置/数据集中管理。

如何让数据卷只读?

在 docker run -v 挂载命令末尾添加 :ro 标志即可:docker run -it -v /root/host_mount:/opt/uc_mount:ro ubuntu:latest /bin/bash。这样容器对挂载点只有只读权限,宿主机对数据卷始终是读写权限。常用于:1) 防止容器运行时意外修改配置;2) 共享只读配置文件/证书;3) 提高安全性。

数据卷容器和命名卷有什么区别?

数据卷容器:一种使用模式,通过 --volumes-from 共享其他容器的数据卷,适合多容器共享同一份数据的场景;命名卷(Named Volume):通过 docker volume create 显式创建的独立数据卷,由 Docker 在 /var/lib/docker/volumes/ 下管理,适合需要明确管理生命周期的数据。前者是容器挂载的组合方式,后者是物理存储实体。
