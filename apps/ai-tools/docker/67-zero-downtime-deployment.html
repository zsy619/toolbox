Chapter 01

3 大策略对比

  • 滚动发布:低风险,慢,回滚 30s
  • 蓝绿部署:高风险切流量,快,资源翻倍
  • 金丝雀:小流量验证,风险最低,需精细化监控
  • K8s 默认 RollingUpdate,生产用 Argo Rollouts
  • 推荐:核心服务金丝雀,普通服务滚动
Chapter 02

K8s 滚动发布配置

  • strategy.rollingUpdate.maxUnavailable=0 期间零丢失
  • strategy.rollingUpdate.maxSurge=1 最多多 1 个新 Pod
  • maxSurge:25% + maxUnavailable:0 推荐配置
  • preStop hook:sleep 15 让负载均衡器先摘除
  • terminationGracePeriodSeconds:30 默认 30s
Chapter 03

蓝绿部署 5 步

  • 1) 部署 green 环境(新版本),不接流量
  • 2) green 跑冒烟测试 + 集成测试
  • 3) 切换 Service selector 到 green
  • 4) 观察 5-15 分钟,无问题就停 blue
  • 5) 回滚:重新切回 blue(blue 仍运行)
Chapter 04

金丝雀发布 4 阶段

  • 1) 5% 流量给新版本(观察 1h)
  • 2) 20% 流量(观察 1h)
  • 3) 50% 流量(观察 1h)
  • 4) 100% 流量(全量,旧版本下线)
  • 判断指标:错误率 < 0.1% / 延迟 P99 < 基线 / CPU 正常
Chapter 05

回滚 4 种方法

  • 1) kubectl rollout undo deployment/app
  • 2) kubectl rollout history deployment/app 查看历史
  • 3) helm rollback my-release 1 回滚 1 个版本
  • 4) Argo CD 触发 Sync 到上一 Revision
  • 回滚时间目标 RTO < 5 分钟
💡 状态保护

preStop hook + sleep 避免请求被中断

🎯 数据库迁移

扩展部署 + 向前向后兼容(expand-contract pattern)

实战代码示例

📝 K8s 滚动更新

完整可执行代码,直接复制即可在生产环境使用:

K8s 滚动更新 · yaml 
            
strategy:
  type: RollingUpdate
  rollingUpdate:
    maxSurge: 1
    maxUnavailable: 0
template:
  spec:
    containers:
    - name: app
      lifecycle:
        preStop:
          exec:
            command: ["/bin/sh", "-c", "sleep 15"]
操作流程

可视化操作流程

🔄 5 步标准操作流程

  1. 配 maxSurge: 1 → 启动容器或检查环境
  2. 配 maxUnavailable: 0 → 拉取依赖或配置
  3. 加 preStop hook → 启动核心服务
  4. kubectl apply → 验证运行状态
  5. 观察滚动 → 部署上线
