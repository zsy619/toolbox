为什么需要理解 Docker 网络

Docker 网络的 底层是 Linux 的 Network Namespace 。理解它,需要先了解 Network Namespace 是什么。本文从基础到高级,逐层深入讲解。

Docker 网络的 3 大核心组件

Docker 网络架构由 三部分 组成:
1) CNM (Container Network Model,容器网络模型)——网络连接的设计规范,规定了基础组成要素;
2) Libnetwork ——开源的 Go 语言 CNM 标准实现;
3) Driver ——真正实现网络功能的底层驱动(如 bridge 驱动、host 驱动、overlay 驱动等)。

Chapter 01

Network Namespace(网络命名空间)

Network Namespace 是 Linux 用于实现网络虚拟化的重要功能,能创建多个 隔离的网络空间 ,每个独立网络空间内的防火墙、网卡、路由表、邻居表、协议栈都是独立的。

不管是虚拟机还是容器,当运行在独立的命名空间时,就像是一台独立的主机一样。下面的例子是:创建 2 个 Network Namespace,然后连通它们。

1.1 创建 2 个命名空间

bash 
                
                  
ip netns add
                  
 ns1
                  
ip netns add
                  
 ns2

1.2 创建 veth pair(虚拟设备接口)

如果要让两个命名空间连通,需要用到 虚拟设备接口技术 veth pair 。该技术需要一对网络接口分别置于两个命名空间中。

bash 
                
                  
ip link add
                  
 veth-ns1
                  
type
                  
 veth
                  
peer name
                  
 veth-ns2

此时通过 ip link 查看当前网络地址情况,看到新增了两个相同的 veth pair,它们都有 MAC 地址,但状态都是 DOWN ,都没有 IP。

1.3 为命名空间添加 veth 接口

通过 ip link set 命令,将刚才两个接口分配给两个命名空间:

bash 
                
                  
ip link set
                  
 veth-ns1
                  
netns
                  
 ns1
                  
ip link set
                  
 veth-ns2
                  
netns
                  
 ns2

此时分别在两个命名空间中执行 ip link 命令,可以看到它们都新增了网络接口。

1.4 为 veth 接口分配 IP

通过 ip netns exec 命令,为每个命名空间添加 IP:

bash 
                
                  
ip netns exec
                  
 ns1
                  
ip addr add
                  
 192.168.1.1/24
                  
dev
                  
 veth-ns1
                  
ip netns exec
                  
 ns2
                  
ip addr add
                  
 192.168.1.2/24
                  
dev
                  
 veth-ns2

1.5 启动 veth 接口

通过 ip link set dev [接口] up 来启动指定的网络接口:

bash 
                
                  
ip netns exec
                  
 ns1
                  
ip link set dev
                  
 veth-ns1
                  
up
                  
                  
ip netns exec
                  
 ns2
                  
ip link set dev
                  
 veth-ns2
                  
up

1.6 相互 ping 测试

在 ns1 中执行 ping 192.168.1.2 ,如果能看到正常回包,说明两个 Namespace 已通过 veth pair 互通。

💡

veth pair 就像一根"虚拟网线",数据从一端进入必定从另一端出来。Docker 正是用 veth pair 实现了容器与宿主机/网桥的互通——一端在容器内(显示为 eth0),另一端在宿主机(显示为 vethxxx@ifX)。

Chapter 02

CNM(容器网络模型)

CNM(Container Network Model,容器网络模型)是一种 网络连接的解决方案 ,是一种 设计规范、设计标准 ,其规定了 Docker 网络的基础组成要素。

CNM 中定义了 三个基本要素 :沙盒 Sandbox、终端 Endpoint 与网络 Network。

要素 英文 概念 标准实现
沙盒 Sandbox 一个独立的网络栈,包括以太网接口、端口号、路由表、DNS 配置等 Linux Network Namespace
终端 Endpoint 虚拟网络接口,负责创建连接,即将沙盒连接到网络上。一个终端只能接入一个网络 veth pair 端点
网络 Network 802.1d 网桥的软件实现,是需要交互的终端的集合 Linux Bridge / OVS
🎯

理解 CNM 三要素是掌握 Docker 网络的关键:一个 容器 = 一个 Sandbox ,容器内的一块 网卡 = 一个 Endpoint ,一个 用户自定义网络 / 默认 bridge = 一个 Network 。三者通过 Libnetwork 串联起来。

Chapter 03

Libnetwork(CNM 的标准实现)

Libnetwork 是 开源的、Go 语言编写、跨平台 的 CNM 标准实现。Libnetwork 除了实现 CNM 的三个组件,还实现了:

  • 本地服务发现
  • 容器负载均衡
  • 网络控制层与管理层功能
💡

Libnetwork 的 Go 语言实现让其能 天然跨平台 (Linux/Windows/macOS 都能跑),这是 Docker 网络能多平台统一的基础。

Chapter 04

Driver(驱动层)

不同的网络类型对应不同的底层 Driver,这些 Driver 负责在主机上真正实现需要的网络功能(例如创建 veth pair 设备等)。

4.1 工作流程

无论哪种网络类型,工作方式都是类似的:

  1. 调用 Docker 引擎的 API 发出请求
  2. Libnetwork 做出框架性处理
  3. 将请求转发给对应的 Driver

4.2 查看网络

通过 docker network ls 命令可以查看当前主机所连接的网络及网络类型:

bash 
                
                  
docker network ls

4.3 Docker 内置驱动

驱动类型 名称 用途
bridge 网桥驱动 单机容器互联(默认)
host 主机驱动 与宿主机共享网络
none 无网络驱动 无网络通信
overlay 覆盖网络驱动 多主机容器互联(Swarm 模式)
macvlan MAC VLAN 驱动 为容器分配 MAC 地址,使其在物理网络中显示为物理设备
Chapter 05

bridge 网络(默认网络模式)

bridge 网络也称 单机桥接网络 ,是 Docker 默认的网络模式。该模式只能存在单个 Docker 主机上,只能连接所在 Docker 主机上的容器。

5.1 docker0 网桥

bridge 网络模式中有个 默认的虚拟网桥 docker0 ,通过 ip a 或者 ifconfig 命令可以查看。

docker0 网桥的工作原理

在 Linux 主机上,Docker 的 bridge 网络在创建时会创建一个默认网桥 docker0。
1) 容器 ↔ 网桥 :通过 veth pair 技术 连接;
2) 网桥 ↔ 外网 :通过 网络地址转换 NAT 技术 连接,就是将通信的数据包中的内网地址转换为外网地址。

5.2 查看网络连接情况

通过 docker network inspect 命令查看当前 bridge 网络的连接情况。Containers 中可以看到连接的所有容器,这些容器和宿主机就是三个完全独立的 Network Namespace。

5.3 查看宿主机接口

发现除了回环地址 lo、本地网卡 ens33、网桥 docker0 外,还有 veth 网络接口。这些 veth 就是由 Libnetwork 生成的 veth pair 中宿主机的 EndPoint。

  • vethxxx@if4 :表示第 5 个接口,用来连接外部的第 4 个接口
  • vethxxx@if6 :表示第 7 个接口,用来连接外部的第 6 个接口

5.4 查看容器接口

可以看到容器都包含 eth0 接口。容器内的 eth0@ifN 与宿主机的 vethxxx@ifM 配对——这是 veth pair 的两端。

5.5 查看网桥连接

先安装网桥工具包 bridge-utils :

bash 
                
                  
yum -y install
                  
 bridge-utils
                  
brctl show
                  
 docker0

可以看到网桥上挂着两个接口,正是 5.3 中看到的 veth pair。

5.6 创建自定义网络

通过 docker network create 命令可以创建指定名称和类型的网络:

bash 
                
                  
docker network create
                  
                  
-d
                  
 bridge bridge2

-d :指定网络类型; bridge2 是网络名称。通过 docker network ls 可以看到刚才创建的网络。

5.7 创建容器指定网络

创建一个新的 BusyBox 容器 bb3 ,然后连接在新建的 bridge2 网络上:

bash 
                
                  
docker run
                  
                  
-d
                  
                  
--name
                  
 bb3
                  
--network
                  
 bridge2 busybox /bin/sh -c "while true; do sleep 3600; done"

通过 --network 指定要连接到的网络,如果不指定,连接默认的 bridge 。

5.8 容器连接到指定网络

将容器 bb2 连接到 bridge2 上。可以使用 docker network connect 命令:

bash 
                
                  
docker network connect
                  
 bridge2 bb2

此时 bb2 容器连接在两个网络上,具有两个 IP。此时 bb2 和 bb3 可以 ping 通。但 bb3 和 bb2 的另一个网段是 ping 不通的。

🎯

容器除了可以直接 ping IP 外,还可以直接 ping 容器名称 : docker exec bb3 ping bb2 。 自定义的 bridge 网络 可以通过容器名互相 ping, 但默认的 bridge 不行 。

5.9 创建定向连接容器(默认 bridge 也能用容器名)

如果想在默认的 bridge 网络上通过容器名称进行连接,则在创建容器时通过 --link 指定:

bash 
                
                  
docker run
                  
                  
-d
                  
                  
--name
                  
 bb4
                  
--link
                  
 bb1 busybox /bin/sh -c "while true; do sleep 3600; done"

此时 bb4 可以用容器名称 ping bb1 。

⚠️

bb1 无法通过容器名称 ping bb4 ——因为 --link 是一种 定向连接 ,带有 指向性和方向性 。 注意: --link 已被标记为 deprecated,新代码建议用自定义 bridge 网络。

5.10 创建共享网络命名空间容器

创建容器时可以指定其与已经存在的容器 共享 Network Namespace (要求已存在容器必须采用 bridge 模式):

bash 
                
                  
docker run
                  
                  
-d
                  
                  
--name
                  
 bb1-1
                  
--network
                  
 container:bb1 busybox /bin/sh -c "while true; do sleep 3600; done"

此时这两个容器的网络接口完全相同(共享 IP、共享端口、共享协议栈)。

Chapter 06

none 网络(无网络)

none 网络,即 没有网络 。容器仍是一个独立的 Network Namespace,但是 没有网络接口,没有 IP 。

6.1 创建 none 网络容器

在 docker run 命令中,通过 --network none 指定没有网络:

bash 
                
                  
docker run
                  
                  
-d
                  
                  
--name
                  
 bb5
                  
--network
                  
 none busybox /bin/sh -c "while true; do sleep 3600; done"
                  
# 查看容器详情,发现没有 IP、没有网关、没有 MAC 地址
                  
                  
docker inspect
                  
 bb5
                  
# 查看网络接口,发现只有一个回环地址 lo,没有其他接口
                  
                  
docker exec
                  
 bb5
                  
ip a
🎯

none 网络适合 不需要网络的批处理任务 (如离线数据转换、ETL 脚本、定时计算任务),最大程度减少攻击面。

Chapter 07

host 网络(与宿主机共享)

host 网络:与宿主机 host 共用一个 Network Namespace 。该网络类型的容器 没有独立的网络空间,没有独立 IP ,全部与 host 共用。

7.1 创建 host 网络容器

通过 --network host 指定为 host 网络:

bash 
                
                  
docker run
                  
                  
-d
                  
                  
--name
                  
 bb6
                  
--network
                  
 host busybox /bin/sh -c "while true; do sleep 3600; done"
                  
# 查看 host 网络详情,发现 bb6 连接在该网络上,但是没有 IP、MAC,并且该网络没有网关 Gateway。
                  
                  
# 因为该网络模式相当于没有网络,容器与宿主机共用 Network Namespace,不需要网络连接。
                  
                  
docker network inspect
                  
 host

7.2 关于端口映射

由于容器和宿主机共用一个 Network Namespace,所以无论 IP 还是 Port, 容器和宿主机都是相同的 。容器中的 Port 不存在映射问题 ,host 中的 Port 和容器中的 Port 相同。

bash 
                
                  
# 运行 tomcat(指定端口映射,但网络是 host 类型,端口映射不起作用)
                  
                  
docker run
                  
                  
--name
                  
 mytom
                  
--network
                  
 host
                  
-dp
                  
 8081:8080 tomcat:8.5.32
⚠️

上面虽指定了端口映射,但是网络是 host 类型,所以端口映射不起作用 。此时仍需要通过 8080 端口访问。由于端口相同的特性,所以当采用 host 网络模式时, 一个宿主机只能启动一个应用的一个容器 ,否则会出现端口号冲突。

Chapter 08

三种网络模式对比

维度 bridge none host
命名空间 独立 独立(无接口) 与宿主机共享
IP 地址 有(veth pair) 无 与宿主机相同
与外网通信 ✅ 经 docker0 + NAT ❌ 不行 ✅ 直接用宿主机网络
端口映射 必需(-p) 不需要 无效(端口直接共用)
DNS 解析(容器名) 自定义网络支持,默认不支持 ❌ 用宿主机 hosts
网络性能 中等(veth 转发) — 最高(无虚拟化)
适用场景 单机多容器互访(默认) 离线批处理任务 网络性能敏感场景
🎯

生产环境多机通信需用 overlay 网络(Swarm 模式);对老旧系统做容器迁移时 host 网络能减少 30% 性能损耗;批处理定时任务首选 none 网络降低攻击面;日常单机部署用 自定义 bridge 网络,既能 DNS 解析又能灵活管理。

FAQ

常见问题

Docker 网络的底层是什么?

Docker 网络的底层是 Linux 的 Network Namespace。它能创建多个隔离的网络空间,每个空间内独立的防火墙、网卡、路由表、邻居表、协议栈。不管是虚拟机还是容器,运行在独立的 Network Namespace 中就像是一台独立的主机一样。

什么是 veth pair?

veth pair 是成对出现的虚拟网络接口,数据从一端进入必定从另一端出来,像一根"网线"。Docker 用它连接两个 Network Namespace——一端放在容器里(容器内显示为 eth0),另一端放在宿主机里(对应 vethxxx 接口),通过这种方式实现容器与宿主机/网桥的互通。

CNM 三要素是什么?

CNM(Container Network Model,容器网络模型)是 Docker 网络的设计规范,定义了 3 个基本要素:1) Sandbox(沙盒):独立的网络栈,Linux Network Namespace 是其标准实现;2) Endpoint(终端):虚拟网络接口,负责创建连接,一个终端只能接入一个网络;3) Network(网络):802.1d 网桥的软件实现,是需要交互的终端的集合。

bridge、none、host 三种网络模式怎么选?

bridge:默认模式,容器有独立 Network Namespace,通过 docker0 网桥互联,适合单机多容器互访;none:无网络,容器只有回环地址 lo,适合不需要网络的批处理任务;host:与宿主机共用 Network Namespace,网络性能最高但端口冲突风险大,适合对网络性能敏感的特定场景。多机通信用 overlay 网络。

默认 bridge 网络为什么不能用容器名 ping?

默认 bridge 网络不支持 Docker DNS 解析,所以容器间不能用容器名互访,只能用 IP。自定义 bridge 网络(通过 docker network create)内置了 DNS 服务,可直接通过容器名 ping 通信。如果非要在默认 bridge 上用容器名,需用 --link 参数(但 --link 是定向连接,带方向性)。

host 网络模式下端口映射为什么不生效?

因为 host 模式下容器与宿主机共用 Network Namespace,IP 和 Port 完全相同——容器内的 Port 等于宿主机的 Port。所以无论是否写 -p 端口映射参数,实际访问都用宿主机端口。注意:由于端口相同的特性,一个宿主机只能启动 host 模式容器的一个实例,否则端口冲突。

如何让一个容器连接多个网络?

1) 启动时直接用 --network 指定;2) 容器已运行后用 docker network connect <网络名> <容器名> 动态添加;连接多个网络后容器会获得多个 IP(每个网络一个),但容器与每个网络的通信是隔离的——容器内的 eth0 只能和当前主网络通信,其他网络通过新增接口 veth1、veth2 等通信。
