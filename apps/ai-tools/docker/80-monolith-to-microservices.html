单体应用容器化拆分实战

绞杀者模式 + 抽象分支 + 持续演进

Chapter 01

单体应用 5 大痛点

  • 1) 部署慢:小改动需全量发布
  • 2) 技术栈单一:无法按业务选型
  • 3) 扩展受限:整体水平扩展,资源浪费
  • 4) 团队协作:代码冲突,合并地狱
  • 5) 可靠性差:一个 bug 全站崩溃
Chapter 02

5 大拆分策略

  • 1) 绞杀者模式:在单体前加 API 网关,逐步替换为新服务
  • 2) 抽象分支:从代码层抽象接口,新旧实现共存
  • 3) 数据拆分:先按数据库表拆分,再按业务拆分
  • 4) UI 拆分:微前端,独立部署前端模块
  • 5) 事件驱动:通过消息队列解耦同步调用
Chapter 03

5 步迁移路径

  • 第 1 步:单体应用 Docker 化(零代码改动)
  • 第 2 步:数据库读写分离,提升性能
  • 第 3 步:按业务拆分子系统(同进程多模块)
  • 第 4 步:API 网关 + 服务注册发现
  • 第 5 步:数据迁移,新旧系统共存 → 渐进切换
Chapter 04

容器化 4 阶段

  • Stage 1 - 整体容器化:Dockerfile + Compose 整体打包
  • Stage 2 - 拆分数据库:连接不同 DB,代码层适配
  • Stage 3 - 拆分子系统:每个子系统独立服务,共享 DB 视图
  • Stage 4 - 完全微服务:独立部署 + 独立 DB + Service Mesh
  • 推荐:从 Stage 1 起步,2-3 年逐步推进到 Stage 4
Chapter 05

典型案例:电商系统拆分

  • 用户服务 → 独立部署 + 独立 DB
  • 商品服务 → 独立部署 + 缓存层
  • 订单服务 → 独立部署 + Saga 分布式事务
  • 支付服务 → 独立部署 + 异步通知
  • 搜索服务 → 独立部署 + ES 集群

操作流程

可视化操作流程

🔄 5 步标准操作流程

  1. 部署 API 网关 → 启动容器或检查环境
  2. 逐步切路由 → 拉取依赖或配置
  3. 新功能新服务 → 启动核心服务
  4. 旧功能迁移 → 验证运行状态
  5. 下线单体 → 部署上线
