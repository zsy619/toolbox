Chapter 01

ES 容器化 4 大坑

  • 1) 内存锁:bootstrap.memory_lock=true 需 ulimit -l unlimited
  • 2) mmap 数量:vm.max_map_count >= 262144
  • 3) JVM 堆:容器内存 50% 给堆,其余给 OS 文件缓存
  • 4) 单节点发现:discovery.type=single-node 否则失败
  • 解决:Compose 用 privileged: true + 启动脚本调系统参数
Chapter 02

单节点快速启动

  • docker run -d -p 9200:9200 -e ES_JAVA_OPTS='-Xms1g -Xmx1g' elasticsearch:8.11
  • -e discovery.type=single-node 禁用集群发现
  • -e xpack.security.enabled=false 关闭安全(开发模式)
  • -v es_data:/usr/share/elasticsearch/data 持久化
  • Kibana:同时启动,配置 ELASTICSEARCH_HOSTS=http://es:9200
Chapter 03

3 节点集群生产部署

  • es01/es02/es03 三节点,镜像相同,环境变量区分
  • discovery.seed_hosts=es02,es03 种子节点
  • cluster.initial_master_nodes=es01,es02,es03 选举主节点
  • ES_JAVA_OPTS=-Xms8g -Xmx8g(容器 16GB)
  • 持久化:/usr/share/elasticsearch/data 三卷独立
Chapter 04

性能调优 4 维度

  • 1) JVM:G1GC 默认 / ZGC 适合大堆 / 堆 ≤ 32GB 避免压缩指针失效
  • 2) 索引:number_of_shards 按数据量定,单 shard 10-50GB
  • 3) Refresh:大索引可禁 _refresh_interval=30s 提升 50% 写入
  • 4) 副本:生产至少 1 副本,搜索可 0 副本 + 异步复制
Chapter 05

Kibana + ILM + 监控

  • Kibana 同容器部署,生产建议单独集群
  • ILM 索引生命周期:热(SSD)→ 温(HDD)→ 冷(对象存储)→ 删除
  • Cerebro / Elastic HQ:集群可视化监控
  • Prometheus exporter:Prometheus 抓取 ES 指标
  • 告警:Watch + Action 邮件/Webhook,Alertmanager 集成
💡 镜像选择

elasticsearch:8.11 官方 / docker.elastic.co 镜像

⚠️ JVM 堆

堆 = 容器内存 50%,且不超过 32GB(避免 OOP 压缩失效)

📝 ES 单节点配置

ES 单节点配置 · yaml
