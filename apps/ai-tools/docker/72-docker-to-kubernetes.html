Chapter 01

Docker 与 K8s 关键差异

  • 1) 调度:K8s 集群调度 vs Docker 主机调度
  • 2) 自愈:K8s 自动重启 + 迁移 + 替换
  • 3) 弹性:HPA/VPA/Cluster Autoscaler 自动伸缩
  • 4) 服务发现:K8s Service + DNS 自动发现
  • 5) 配置管理:ConfigMap / Secret 集中管理
Chapter 02

3 步迁移路径

  • 第 1 步:开发环境 Docker Compose(本地快速)
  • 第 2 步:测试环境 K8s(集群验证)
  • 第 3 步:生产环境 K8s(高可用 + 弹性)
  • 工具:Kompose 自动将 docker-compose.yml 转 K8s manifest
  • kompose convert -f docker-compose.yml -o k8s/ 一键生成
Chapter 03

K8s 核心资源 8 选

  • Deployment:无状态应用控制器
  • StatefulSet:有状态应用(如 DB)
  • DaemonSet:每节点一个 Pod(如日志收集)
  • Service:服务抽象 + 负载均衡
  • Ingress:HTTP 路由入口
  • ConfigMap / Secret:配置 / 密钥管理
  • PersistentVolume / PVC:持久化存储
  • Job / CronJob:一次性任务 / 定时任务
Chapter 04

Helm 5 大优势

  • 1) 模板化:values.yaml + Chart 复用
  • 2) 版本化:helm history 查看历史,一键回滚
  • 3) 依赖管理:Chart 嵌套,自动拉取依赖
  • 4) 发布管理:helm install / upgrade / rollback 统一管理
  • 5) 生态:Bitnami / ArtifactHub 数万 Chart 可用
Chapter 05

Operator 模式 4 优势

  • 1) 自定义资源 CRD:扩展 K8s API
  • 2) 控制器:CRD 的调谐循环
  • 3) 领域知识:把运维专家经验编码到 Operator
  • 4) 自动化:备份/恢复/扩缩容/升级全自动化
  • 代表:Prometheus Operator / TiDB Operator / MongoDB Operator

操作流程

可视化操作流程

🔄 5 步标准操作流程

  1. 1. 编写 docker-compose.yml → 启动容器或检查环境
  2. 2. 安装 Kompose → 拉取依赖或配置
  3. 3. kompose convert 转换 → 启动核心服务
  4. 4. 检查生成的 K8s manifest → 验证运行状态
  5. 5. kubectl apply -f k8s/ → 部署上线或回归测试
