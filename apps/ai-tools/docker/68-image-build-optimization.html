Chapter 01

基础镜像 3 选择

01

scratch:C 语言最小镜像(0 层,如 Go 静态编译)

02

alpine:通用轻量镜像(5MB,如 node:20-alpine)

03

distroless:Google 维护,无 shell 无包管理器(gcr.io/distroless/*)

Chapter 02

多阶段构建 4 优势

01

构建工具不进入最终镜像:builder 含 gcc/make,runner 仅含 runtime

02

敏感信息隔离:secrets 凭据仅在 builder 阶段可用

03

产物精准复制:COPY --from=builder /app/bin /app/bin

04

测试与构建解耦:可独立运行测试阶段而不影响产物

Chapter 03

层缓存 5 技巧

01

变更频率排序:不常变(系统依赖)在前,常变(代码)在后

02

合并 RUN:apt-get update && apt-get install -y xxx && rm -rf /var/lib/apt/lists/*

03

.dockerignore:排除 .git / node_modules / .env / tests

04

缓存挂载:--mount=type=cache,target=/root/.cache/pip(不进入镜像)

05

--cache-from:从 CI registry 复用缓存

Chapter 04

构建参数 3 优化

01

BuildKit 启用:DOCKER_BUILDKIT=1 docker build .(并行构建、缓存感知)

02

并行构建:--ssh / --secret 隔离敏感数据

03

镜像压缩:docker build --compress .(牺牲兼容性,提升 push 速度)

实战代码

实战代码示例

📝 多阶段构建

完整可执行代码,直接复制即可在生产环境使用:

多阶段构建 · dockerfile 
            
FROM node:20-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
FROM node:20-alpine
COPY --from=deps /app/node_modules ./node_modules
COPY . .
CMD ["node", "server.js"]
操作流程

可视化操作流程

🔄 5 步标准操作流程

  1. 分离 deps/runtime → 启动容器或检查环境
  2. 利用构建缓存 → 拉取依赖或配置
  3. 选最小基础镜像 → 启动核心服务
  4. 清理无用文件 → 验证运行状态
  5. 验证镜像大小 → 部署上线
