Docker 安装 MySQL 与 Redis 完全指南

从单机版到主从复制、Sentinel 高可用、Cluster 分布式集群,系统讲解两大核心中间件的 Docker 部署方案。所有命令均经过生产环境验证,可直接复用。

难度 ★★★ 中级
阅读时长 约 30 分钟
中间件 MySQL 5.7 + Redis 7.0
最后更新 2026-06-03
MySQL Redis 主从复制 Sentinel Cluster 数据卷

概述

MySQL 和 Redis 是后端架构中 最核心的两大中间件 :MySQL 负责持久化存储,Redis 负责高性能缓存。本文以生产环境视角,从 单机版 → 主从复制 → Sentinel 高可用 → Cluster 分布式 逐层深入,所有命令均提供完整示例。

数据持久化的重要性

Docker 容器默认使用联合文件系统,数据存储在容器可写层。 容器删除时,数据全部丢失 。生产环境必须挂载数据卷(volume),将 MySQL 的数据/日志/配置、Redis 的数据和配置持久化到宿主机。

Chapter 04

Redis 单机版

4.1 拉取镜像

bash 
                
                  
docker pull
                  
 redis:7.0

4.2 准备 redis.conf

复制一份 redis.conf 到 /root/redis ,并修改以下 四项关键配置 :

conf 
                
                  
# 解除 IP 绑定
                  
                  
# bind 127.0.0.1 -::1
                  
                  
# 关闭保护模式,否则只能本机访问
                  
                  
protected-mode
                  
 no
                  
# 关闭守护模式(Docker 本身已后台运行,Redis 再 daemonize 会立刻 fork 退出)
                  
                  
daemonize
                  
 no
                  
# 指定 RDB/AOF 持久化目录
                  
                  
dir
                  
 /data

4.3 启动容器

bash 
                
                  
docker run
                  
                  
--name
                  
 myredis \
                  
-v
                  
 /root/redis/redis.conf:/etc/redis/redis.conf \
                  
-v
                  
 /root/redis/data:/data \
                  
-dp
                  
 6379:6379 \
  redis:7.0 \
  redis-server /etc/redis/redis.conf

挂载两个数据卷:配置文件 + 数据目录。命令加载挂载点目录的 redis.conf。

4.4 连接 Redis

bash 
                
                  
docker exec
                  
                  
-it

redis-cli
💡

Docker 容器本身就是后台运行的进程,Redis 如果再 daemonize(后台守护),会立即 fork 退出,导致容器停止。所以 Docker 部署 Redis 必须 daemonize no 。

Chapter 06

Redis Sentinel 高可用集群

Sentinel(哨兵)在主从基础上加 3 个哨兵节点, 自动监控 master 状态并在故障时 自动选举新 master ,实现高可用。

6.1 准备 3 份 sentinel.conf

复制 sentinel.conf 为 sentinel1.conf 、 sentinel2.conf 、 sentinel3.conf ,每份修改 两处 :

conf 
                
                  
# sentinel1.conf
                  
                  
# 指定要监视的 master 及 
                  
                  
sentinel monitor
                  
 mymaster 192.168.220.128 6381 2
                  
# 指定对外 ip 和端口号
                  
                  
sentinel announce-ip
                  
 192.168.220.128
                  
sentinel announce-port
                  
 26381
                  
# sentinel2.conf(只改端口 26382)
                  
                  
# sentinel3.conf(只改端口 26383)

6.2 启动 3 个 Sentinel

-dp

  redis:7.0 \

docker run

6.3 验证 Sentinel

bash

-it

-h

-p

高可用集群搭建成功。当 master 故障,Sentinel 通过 Raft 算法 自动选举 新 master(从 2 个 slave 中选),应用端无需修改。

⚠️

Sentinel 至少 3 个节点。quorum 设为 2,意味着至少 2 个 Sentinel 同意才认为 master 真正故障,避免误判导致不必要的切换。生产推荐 3 节点起步。

Chapter 07

Redis Cluster 分布式系统

Redis Cluster 是真正的 分布式系统 ,数据通过 虚拟槽分区算法 (16384 个槽)分布在多个 master 节点,实现 水平扩展 。每个 master 配备一个 slave,master 故障时自动故障转移。

主从 vs Sentinel vs Cluster

1) 主从 :读写分离,master 故障需手动切换;
2) Sentinel :在主从基础上加 3 个哨兵,自动监控并选举新 master,实现 HA;
3) Cluster :真正的分布式,数据分片(16384 槽)分布在多个 master,水平扩展能力强,适合海量数据。
三者层级递进:主从 → Sentinel → Cluster。

FAQ

常见问题

MySQL 5.7 vs 8.0 在 Docker 中有什么区别?

MySQL 5.7 稳定,生态成熟,默认字符集 latin1(中文需手动改 utf8),密码策略简单;MySQL 8.0 性能更好,默认字符集 utf8mb4(完整 Unicode 支持),密码策略更严格(caching_sha2_password),窗口函数、CTE、JSON 增强。新项目推荐 8.0,旧系统兼容 5.7。

MySQL 容器为什么必须挂载数据卷?

容器默认使用联合文件系统,数据存储在容器可写层,容器删除时数据全部丢失。生产环境必须挂载 3 个数据卷:1) 数据目录 /var/lib/mysql;2) 日志目录 /var/log/mysql;3) 配置目录 /etc/mysql/conf.d。这样容器重建时数据可恢复,符合生产数据持久化要求。

Redis 主从复制、Sentinel、Cluster 有什么区别?

主从复制:读写分离,master 写、slave 读,但 master 故障需手动切换;Sentinel:在主从基础上加 3 个哨兵节点,自动监控并选举新 master,实现高可用(HA);Cluster:真正的分布式,数据分片(16384 槽)分布在多个 master,水平扩展能力强,适合海量数据。三者层级递进:主从→Sentinel→Cluster。

Redis 配置中的 daemonize no 是什么意思?

Redis 默认 daemonize yes(后台守护进程),但 Docker 容器本身就是后台运行的,Redis 不能再 daemonize,否则进程会立刻 fork 退出,导致容器停止。所以 Docker 部署 Redis 必须设置 daemonize no。同理 MySQL 也不能用 mysqld_safe 守护。

Sentinel 至少需要几个节点?

至少 3 个。Sentinel 集群通过 Raft 多数派决策,3 节点可容忍 1 节点故障,5 节点可容忍 2 节点故障。生产环境强烈建议奇数节点(1/3/5/7),避免偶数造成脑裂。

Redis Cluster 至少需要几个节点?

至少 6 个(3 master + 3 slave)。Redis Cluster 通过虚拟槽分区(0-16383)分配数据,每个 master 负责一部分槽。当某个 master 故障时,其 slave 自动提升为新 master,继续提供服务。生产推荐 6 节点起步,数据量大时横向扩展。

为什么 Redis Cluster 启动要加 --network host?

因为 Cluster 节点之间需要通过 IP+端口互相通信(bus port 端口号+10000),使用 bridge 网络时容器 IP 难被其他容器/主机直接访问。使用 --network host 让容器共享宿主机网络命名空间,容器端口直接绑定宿主机端口,简化集群节点互联。新版 Docker 19.03+ 推荐使用自定义 macvlan 网络代替 host 模式。
