Chapter 01

CI/CD 7 大阶段

  • 1) 代码触发:push / PR / tag / schedule
  • 2) 单元测试:覆盖率 >= 80%
  • 3) 镜像构建:Dockerfile 多阶段 + BuildKit
  • 4) 安全扫描:Trivy + Snyk + SonarQube
  • 5) 镜像推送:Registry / Harbor / ECR
  • 6) 自动化部署:staging → production 分级
  • 7) 验证:冒烟测试 + 监控告警 + 灰度发布
Chapter 02

GitHub Actions 5 步模板

  • 1) actions/checkout@v4 检出代码
  • 2) docker/setup-buildx-action@v3 启用 buildx
  • 3) docker/login-action@v3 登录 Registry
  • 4) docker/build-push-action@v5 构建并推送
  • 5) anchore/sbom-action 报告 SBOM
Chapter 03

GitLab CI 4 阶段

  • 1) build:docker buildx build --tag $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
  • 2) test:test --health:启动容器跑测试,完成后停止
  • 3) scan:trivy image 扫描 + 报告
  • 4) deploy:kubectl apply -f k8s/ 或 helm upgrade
  • GitLab Runner:Docker executor 隔离构建环境
Chapter 04

Argo CD GitOps 实战

  • Argo CD 自动同步 K8s manifest 与 Git 仓库
  • App of Apps:父 App 管理所有子应用
  • PR 触发预览环境:PR-Bot 自动创建临时 namespace
  • 回滚:argocd app rollback my-app 回到上一版本
  • 审计:Argo CD Notifications + Slack 通知
Chapter 05

部署策略 3 大选

  • 1) 蓝绿部署:新旧版本并存,流量秒切
  • 2) 金丝雀发布:10% → 50% → 100% 渐进发布
  • 3) 滚动发布:RollingUpdate,逐批替换 Pod
  • 推荐:核心服务用金丝雀(可控),内部工具用滚动
  • Argo Rollouts:K8s 原生蓝绿/金丝雀控制器

📝 Argo CD GitOps

完整可执行代码,直接复制即可在生产环境使用:

Argo CD GitOps · yaml 
            
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp-prod
spec:
  source:
    repoURL: https://github.com/myorg/k8s
    path: prod/myapp
  destination:
    server: https://kubernetes.default.svc
  syncPolicy:
    automated: { prune: true, selfHeal: true }
操作流程

可视化操作流程

🔄 5 步标准操作流程

  1. 写 GitOps manifest → 启动容器或检查环境
  2. 部署 Argo CD → 拉取依赖或配置
  3. 建 Application → 启动核心服务
  4. 自动同步配置 → 验证运行状态
  5. 监控同步状态 → 部署上线
