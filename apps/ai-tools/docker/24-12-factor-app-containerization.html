12-Factor App 与容器化原则

Heroku 12 要素 + 容器化最佳实践

详解 Heroku 12-Factor App 12 要素在容器化时代的实践:代码/依赖/配置/后端服务/构建发布运行/进程/端口绑定/并发/可处置/环境等价/日志/管理进程。

Chapter 01

12 要素概览

  • 1) Codebase:一份代码库,多份部署
  • 2) Dependencies:显式声明依赖
  • 3) Config:配置存储在环境
  • 4) Backing Services:后端服务作为附加资源
  • 5) Build/Release/Run:严格分离
  • 6) Processes:无状态进程
Chapter 02

后 6 要素

  • 7) Port Binding:通过端口绑定暴露服务
  • 8) Concurrency:通过进程模型扩展
  • 9) Disposability:快速启动 + 优雅关闭
  • 10) Dev/Prod Parity:环境尽量一致
  • 11) Logs:日志作为事件流
  • 12) Admin Processes:管理进程作为一次性任务
Chapter 03

容器化对应实践

  • Codebase:git tag/release 对应镜像 tag
  • Dependencies:requirements.txt / package.json / go.mod
  • Config:ConfigMap / env file / Vault
  • Backing Services:DB/Redis 独立容器,通过网络访问
Chapter 04

Build/Release/Run 容器化

  • Build:Dockerfile 多阶段构建生成镜像
  • Release:镜像 tag + ConfigMap 组成不可变 Release
  • Run:docker run / kubectl apply 启动容器
  • 可回滚:Release 有版本号,镜像可回退到任意历史 tag
Chapter 05

12-Factor 现代化扩展

  • 13) API First:OpenAPI / gRPC 接口优先
  • 14) Telemetry:统一可观测性(Metrics+Logs+Traces)
  • 15) Auth/Authz:身份认证与授权分离
  • 16) 安全性:DevSecOps 全流程安全检查
  • 这些是 Cloud Native 12-Factor 的扩展
