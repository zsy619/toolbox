什么是 Docker

Docker 是一个 开源的应用容器(Container)引擎 ,其可以让开发者将 应用及应用运行的环境 打包到一个 轻量级、可移植 的镜像中,然后发布到 Linux、Windows 服务器上。

Docker = jar/war + 环境

Docker 容器除了可以提供相同的应用外,还提供了该应用的 统一运行环境 ,确保在任何宿主机上都可以跑出相同的效果。即 Docker = jar/war + 环境 ——Docker 解决了"代码一致但环境不一致"的经典痛点。

Chapter 01

Docker 的 4 大用途

用途 核心价值 解决的问题
1. 提供统一的运行环境 Docker=jar/war+环境,任何宿主机效果相同 开发/测试/生产环境不一致,导致各种奇怪问题
2. 便捷的应用迁移 物理机/虚拟机/公有云/私有云,结果完全相同 平台迁移时担心运行环境变化导致应用出问题
3. 超快的启动时间 秒级甚至毫秒级,无需启动操作系统 传统虚拟机启动数分钟:启动 VM + 加载 OS + 启动应用
4. 更轻松的维护和扩展 分层存储+镜像机制,复用更容易 应用重复部分难以复用,基础镜像扩展困难
💡

环境一致性 是 Docker 的核心价值。过去常见问题"在我电脑上能跑,到你那就不行"通常由环境差异引起。Docker 通过"应用 + 环境"打包,实现 一次构建、到处运行 (Build once, run anywhere)。

1.1 启动速度对比

传统虚拟机 vs Docker 容器

传统的虚拟机启动一般需要 数分钟 :先启动虚拟机 → 再加载操作系统 → 最后手动启动应用。

Docker 容器应用, 直接运行在宿主机系统,无需启动操作系统 ,因此可以做到 秒级、甚至毫秒级 的启动。本质区别:
1) VM 启动 —— 整个操作系统 (几 GB 的内核+服务)
2) 容器启动 —— 单个应用进程 (几十 MB 的运行时)

Chapter 02

容器与虚拟机的核心区别

Docker 容器 本质 就是通过容器虚拟技术虚拟出的一台主机,就像虚拟机一样,可以将应用及其运行环境部署在这个虚拟出的主机上运行。但容器与虚拟机又有 本质的不同 。

对比维度 传统虚拟机(VM) Docker 容器
虚拟化层级 硬件 + 操作系统 仅应用进程 (共享 host OS)
启动时间 数分钟 秒级甚至毫秒级
磁盘占用 几 GB(整个 OS) 几十 MB(仅应用)
性能损耗 CPU/内存虚拟化有损耗 几乎无损耗 (共享 host 内核)
隔离级别 VM 级强隔离 进程级隔离 (共享内核)
运行数量 宿主机一般跑 10 几个 可跑 上千个
🎯

选择建议 :需要 强隔离 (多租户、不同 OS)选 虚拟机 ;需要 轻量、快速、一致 选 Docker 容器 。现代架构常组合使用:KVM 虚拟机上跑 Docker 容器,既安全又高效。

Chapter 03

3 种程序运行原理对比

程序是一个对计算机硬件资源调度使用的 指令序列 。理解 3 种运行原理的差异,能帮助在选择虚拟化方案时做出正确决策。

3.1 普通系统中的程序运行

程序直接运行在 物理机操作系统 上,通过系统调用或库函数使用硬件资源。结构简单但 环境强耦合 ,换台机器可能就运行不了。

3.2 传统虚拟技术

在物理机的操作系统上安装一个 虚拟机管理程序 (如 VMware、VirtualBox)。其管理下可以创建多个 虚拟机 。

每个虚拟机要安装 独立的操作系统 ,应用就是安装在虚拟机操作系统上的程序。程序通过调用指令或库函数来使用 虚拟化后的 系统资源。

⚠️

对于完全相同的两个应用,若需要运行在两个虚拟机中,则需要 两套完全相同的虚拟机操作系统与 bins/libs ——这样存在 大量的资源浪费 。

3.3 容器虚拟化技术

Docker 容器运行在 Docker 引擎 上,所有 Docker 容器 共享一个 Docker 引擎 ,但它们的运行又是 相互隔离、互不干扰 的。

  • Docker 容器 不需要进行虚拟硬件和操作系统 ,而是 共享宿主机的硬件与操作系统 ,所以 Docker 容器 占用资源少
  • 所有 Docker 容器对系统资源的使用都是由 Docker 引擎统一管理 ,所以系统资源 利用率高
  • 无论 执行速度、内存损耗 或者 文件存储速度 ,都比传统虚拟技术更高效
容器虚拟化的核心创新

Docker 不虚拟化硬件和操作系统,而是 利用 Linux 内核的 Namespace 和 CGroup 机制 实现进程级隔离。每个容器看起来像独立的进程,但 共享同一个 Linux 内核 。这比传统 VM 的" 一整套 OS "轻量得多——这也是容器能在 1 秒内启动的根本原因。

Chapter 04

Docker 系统架构 6 大要素

Docker 系统架构由 Docker Daemon、Image、Container、Repository、Tag、镜像中心 6 大要素组成。

要素 英文 角色 类比
Docker Daemon Dockerd 守护进程 监听 Docker API 请求并管理 Docker 对象(镜像/容器/网络/卷) 操作系统的 kernel
镜像 Image Image 用于创建 Docker 容器的 模板 面向对象中的 类
容器 Container Container 镜像 运行时的实体 。每个容器包含一个或多个应用,容器间相互隔离 面向对象中的 实例
仓库 Repository Repository 保存一组有相同镜像名称的镜像,分公开库/私有库 代码仓库的概念
标签 Tag Tag 通过 : 定位一个镜像,用于区分同一仓库中的不同镜像 git tag 标签
镜像中心 Registry 存放大量公开/私有仓库的服务,如 Docker Hub 类似 GitHub 平台

4.1 6 大要素协同关系

  • Docker Daemon 是后端服务,接收客户端的 docker 命令并执行
  • 镜像 存储在 仓库 中,仓库托管在 镜像中心 (如 Docker Hub)
  • 用户通过 docker pull 从镜像中心拉取 仓库:标签 指定的镜像到本地
  • 用户通过 docker run 用镜像创建 容器
  • 用户可以 docker push 把自定义镜像推送到仓库
  • 一个镜像可以创建 多个 容器

4.2 Docker Hub 镜像中心

Docker 镜像中心存放很多由 官方、其他机构或个人 创建的 Docker 仓库,其他用户可以从这些仓库 pull 需要的镜像,也可以将自己的镜像 push 到 Docker 镜像中心的仓库中。

🎯

Docker Hub( hub.docker.com ) 是默认的 公开镜像中心 。企业生产环境通常自建 私有镜像中心 (如 Harbor、Nexus、Artifactory)用于存放内部镜像,既保证速度又保证安全。

FAQ

常见问题

Docker 是什么?

Docker 是一个 开源的应用容器(Container)引擎 ,其可以让开发者将 应用及应用运行的环境 打包到一个轻量级、可移植的镜像中,然后发布到 Linux、Windows 服务器上。Docker 容器除了可以提供相同的应用外,还提供了该应用的统一运行环境,确保在任何宿主机上都可以跑出相同的效果。即 Docker = jar/war + 环境 。

Docker 有哪些核心用途?

Docker 有 4 大核心用途:1) 提供统一的运行环境 :Docker=jar/war+环境,任何宿主机效果相同;2) 便捷的应用迁移 :从物理机、虚拟机、公有云、私有云无缝迁移,无需担心运行环境变化;3) 超快的启动时间 :直接运行在宿主机系统,无需启动操作系统, 秒级甚至毫秒级 启动;4) 更轻松的维护和扩展 :使用分层存储和镜像机制,重复部分复用更容易,基于基础镜像扩展镜像很简单。

容器与虚拟机的区别是什么?

本质区别在于 是否虚拟化硬件和操作系统 :
1) 虚拟机 :通过 VM 管理程序虚拟化 硬件和操作系统 ,每个 VM 需独立 OS,资源占用大;
2) Docker 容器 : 共享宿主机硬件和操作系统 ,由 Docker 引擎统一管理资源,资源占用少、执行快、存储快;
3) 启动速度 :VM 需数分钟,容器 秒级甚至毫秒级 ;
4) 隔离性 :VM 强隔离,容器 进程级隔离 (共享内核,文件/网络/进程隔离)。

Docker 系统架构包含哪些要素?

Docker 系统架构包含 6 大要素:1) Docker Daemon (Dockerd 守护进程):监听 Docker API 请求并管理 Docker 对象(镜像/容器/网络/卷);2) 镜像 Image :用于创建 Docker 容器的模板(类似面向对象中的 类 );3) 容器 Container :镜像运行时的实体(类似面向对象中的 实例 );4) 仓库 Repository :保存一组镜像,有公开库/私有库之分;5) 标签 Tag :通过 : 定位一个镜像,用于区分同一仓库中的不同镜像;6) 镜像中心 (Docker Hub):存放大量公开仓库,用户可 pull/push 镜像。

Docker 容器启动为什么比虚拟机快?

传统虚拟机启动一般需要数分钟:先启动虚拟机,再加载操作系统,最后手动启动应用(整个 VM 启动链路过长)。Docker 容器应用 直接运行在宿主机系统,无需启动操作系统 ,因此可以做到 秒级甚至毫秒级 的启动。本质是:VM 启动 整个 OS ,容器启动 单个进程 。

Docker 镜像和容器的区别?

镜像是用于创建容器的 模板 (类似面向对象中的 类 ),容器是镜像 运行时的实体 (类似面向对象中的 实例 )。一个镜像可以创建 多个 容器。每个容器都包含一个或多个应用,且容器与容器之间 相互隔离 。镜像存储在镜像仓库中,容器运行在 Docker 引擎之上。

Docker 仓库和镜像中心是一回事吗?

不是。 仓库(Repository) 是一组具有相同镜像名称的镜像集合(如 centos 仓库有 centos:7、centos:8 等多个 tag 的镜像),根据是否公开共享分为 公开库 和 私有库 。 镜像中心(Registry,如 Docker Hub) 是存放很多仓库的 服务 。一个镜像中心可以托管多个仓库,类似代码仓库(GitHub)和具体仓库(user/repo)的关系。
