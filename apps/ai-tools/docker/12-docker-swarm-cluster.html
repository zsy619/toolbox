什么是 Docker Swarm

Docker Swarm 是 Docker 官方推出的 原生集群管理系统 ,自 Docker 1.12.0 起内置于 Docker 引擎中,无需单独安装。它将一组运行 Docker 的物理机或虚拟机组成一个虚拟主机,使用者通过简单的 Docker API 即可与整个集群通信。

核心价值

Swarm 把多个 Docker 主机"抽象"成一台逻辑主机。当你在 Swarm 上部署一个 service 时,集群会自动完成镜像分发、容器调度、负载均衡、故障恢复等任务,屏蔽底层多主机的复杂性。

💡

Swarm 使用标准 Docker API,与现有 docker-compose 文件天然兼容,学习曲线远低于 Kubernetes,适合 中小型团队 与 快速搭建 场景。

Chapter 01

节点架构 (Node Architecture)

从 物理 角度看,一个 Swarm 集群由若干台安装了 Docker 的主机组成;从 逻辑 角度看,集群由若干个 node (节点)组成。每个 node 落实在一台物理 Docker 主机上,但 一个物理主机不一定就是一个 node ,一台主机上也可以运行多个 node。

Swarm 节点架构

1.1 Manager 节点

Manager 节点负责 维护集群状态 、 调度 service 、 处理集群管理任务 。Swarm 通过 Raft 一致性算法 在多个 Manager 之间同步集群状态。为防止单点故障,生产环境推荐 3 个或 5 个 Manager (3 个可容忍 1 个故障,5 个可容忍 2 个)。

1.2 Worker 节点

Worker 节点是 执行层 ,在其容器中运行 task 任务,对外提供 service 服务。默认 Manager 同时充当 Worker 角色,也可以运行 task。

1.3 角色转换

Manager 与 Worker 角色可相互转换:

  • Manager → Worker: 称为 节点降级 (demote)
  • Worker → Manager: 称为 节点升级 (promote)
⚠️

Manager 数量必须是 奇数 (1、3、5、7...),以满足 Raft 多数派选举。偶数 Manager 在投票时会造成"脑裂"风险,反而不利于容灾。

Chapter 02

服务架构 (Service Architecture)

搭建 Swarm 集群的 最终目的 是在集群中运行应用,提供抗压能力强的服务。需要理解 4 个核心概念:

概念 性质 作用
service 逻辑概念 对外提供的服务定义(镜像、副本数、端口等)
task 调度单元 Service 在节点上的具体实现,通常对应一个容器
orchestrator 编排器 Manager 组件 创建/停止 task,通过内置 DNS 注册/注销
dispatcher 分发器 Manager 组件 为 task 分配节点,实现负载均衡

编排器工作流程

以定义一个包含 3 个 task 的 service 为例:

  1. 编排器创建 3 个 task,每个 task 有唯一 taskID,通过分配器为每个 task 分配虚拟 IP(VIP)
  2. 将 task 注册到内置 DNS;当 task 不可用时,编排器在 DNS 中注销

分发器工作流程

编排器创建 3 个 task 后,分发器接管:

  1. 在集群所有节点中找到 3 个 available node,每个节点分配一个 task
  2. 每个 task 像一个"插槽",里面放入一个容器
  3. 分发器持续监测容器运行状态
  4. 若容器不可用或被终止,编排器立即创建新 task 并重新调度
  5. 分发器内置 DNS 轮询,实现访问请求的负载均衡
关键点

task 是 Swarm 调度的 最小单位 ,task 与容器是 1:1 关系。service 是逻辑抽象,task 是物理实例。一个 service 由 1 个或多个 task 组成。

Chapter 03

服务部署模式

Swarm 提供两种 service 部署模式,适用于不同场景:

模式 描述 task 数量 典型场景
Replicated 副本模式 (默认) 手动指定 task 数量,分发器分配到任意可用节点 可配置 Web 服务、API 服务
Global 全局模式 每个节点都运行一个 task,自动跟随节点数量 = 节点数 节点监控、日志收集、Agent 守护
bash 
                
                  
# Replicated 模式:指定 3 个副本
                  

docker service create --name web --replicas 3 -p 80:80 nginx:alpine
                  
# Global 模式:每个节点运行一个
                  

docker service create --name monitor --mode global prom/node-exporter
🎯

选择建议 :当 task 数量 ≠ 节点数量 时必须用 Replicated;当希望"每个节点都跑一份"时用 Global(例如采集节点指标)。

Chapter 04

集群搭建实战

下面演示搭建一个包含 3 Manager + 2 Worker 的 Swarm 集群(共 5 节点):

5 节点 Swarm 集群拓扑

4.1 准备 5 台主机

主机名分别为 docker1 ~ docker5 ,确保 Docker 已安装并运行,各节点之间网络互通。

4.2 检查 Swarm 激活状态

bash 
                
                  
docker info
                  
 |
                  
grep -i swarm

若输出 Swarm: inactive 表示 Swarm 未激活。

4.3 初始化 Swarm (在 docker1)

bash 
                
                  
docker swarm init
                  
                  
--advertise-addr
                  
 10.0.0.1

执行后 docker1 自动成为 Manager,并输出 添加 Worker 与 添加 Manager 的完整命令。

4.4 添加 Worker 节点

在 docker4 和 docker5 上运行 docker1 输出中的 worker 加入命令:

bash 
                
                  
docker swarm join
                  
                  
--token
                  
 SWMTKN-xxx-xxx \
  10.0.0.1:2377

4.5 添加 Manager 节点

在 docker1 获取 manager token,然后在 docker2 和 docker3 上运行:

bash 
                
                  
# 在 docker1 获取 manager 加入命令
                  
                  
docker swarm join-token
                  
 manager
                  
# 复制输出,在 docker2、docker3 运行

4.6 验证集群

在 任一 Manager 节点 运行(Worker 节点无此权限):

bash 
                
                  
docker node ls

可以看到 5 个节点及其角色(Leader / Reachable / Worker)与状态(Ready / Down)。

Chapter 05

集群维护 (Cluster Maintenance)

5.1 Worker 节点退群与重加入

bash 
                
                  
# Worker 退群
                  
                  
docker swarm leave
                  
                  
# 在 Manager 重新生成 worker token
                  
                  
docker swarm join-token
                  
 worker
                  
# 在新 worker 上执行复制的 join 命令

在 Manager 上查看节点状态,旧的 worker 节点变为 Down ,新节点 Ready 。可执行 docker node rm 删除 Down 状态的 worker。

5.2 Manager 节点退群

⚠️

Manager 节点 不推荐直接退群 ,会破坏 Raft 一致性。若必须退群,使用 docker swarm leave -f 强制执行,但需要确保剩余 Manager 数量仍满足多数派。

5.3 自动锁定 (Autolock)

Manager 之间通过 Raft 日志同步数据,但 Raft 数据传输有被攻击风险。Swarm 提供 autolock 机制对通信启用 TLS 加密,密钥维护在 Docker 内存中,Docker 重启后密钥丢失,需要重新解锁。

bash 
                
                  
# 开启自动锁定
                  
                  
docker swarm update
                  
                  
--autolock
                  
=true
                  
# 查看解锁密钥(务必妥善保存)
                  
                  
docker swarm unlock-key
                  
                  
# Manager 重启后,需手动解锁
                  
                  
docker swarm unlock

节点维护 (Node Maintenance)

6.1 角色转换

bash 
                
                  
# Worker 升级为 Manager
                  
                  
docker node promote
                  
 docker4 docker5
                  
# Manager 降级为 Worker
                  
                  
docker node demote
                  
 docker2 docker3
                  
# 等价方式
                  
                  
docker node update
                  
                  
--role
                  
 manager docker2
                  
docker node update
                  
                  
--role
                  
 worker  docker4

6.2 节点标签

为节点添加描述性标签,便于 service 调度时筛选目标节点。

bash 
                
                  
# 添加/修改标签
                  
                  
docker node update
                  
                  
--label-add

--label-add
                  
 email=zs@163.com \
                       docker2
                  
# 查看标签
                  
                  
docker node inspect
                  
 docker2 |
                  
grep -A 5 Labels
                  
                  
# 删除标签
                  
                  
docker node update
                  
                  
--label-rm

--label-rm

6.3 节点删除

场景 能否删除 正确做法
Ready 状态的 Worker ❌ 无法直接删除 先 docker swarm leave 关闭 Docker → 节点 Down → 再 docker node rm
Manager 节点 ❌ 无法直接删除 先 demote 降级为 Worker,再按上面流程
已 Down 的 Worker ✅ 可删除 docker node rm
强制删除( -f ) 对 Manager 无效 docker node rm -f 仅对 Worker 有效
Chapter 07

Swarm 安全:PKI 体系

Docker 内置 PKI(Public Key Infrastructure,公钥基础设施)保障系统安全。所有 Swarm 节点之间的通信都通过 TLS 鉴权、授权与加密。

7.1 TLS 工作流程

  1. 运行 docker swarm init 时,Manager 生成新的 Swarm CA 根证书 与一对密钥
  2. 同时生成 2 个 token:一个用于添加 Worker,一个用于添加 Manager,每个 token 包含 CA 根证书的 digest 和随机密钥
  3. 节点加入时,使用 token 中的随机密钥做 对称验证 保障通信安全
  4. 加入后,所有通信都通过 TLS 加密 :先用 CA 证书验证对方身份,再进行加密数据传输

7.2 CA 证书轮换

为防止 CA 私钥泄露,Swarm 默认每 90 天轮换一次 CA 根证书。手动轮换流程:

bash 
                
                  
# 手动轮换 CA 证书
                  
                  
docker swarm ca
                  
                  
--rotate
                  
                  
# 查看 CA 证书信息
                  
                  
docker swarm ca

轮换过程按顺序执行:生成交叉签名根证书 → 通知所有节点更新根证书 → 节点仅信任新证书 → 使用新证书签发自己的数字证书。

🎯

也可以指定外部 CA 根证书( docker swarm ca --cert ),从外部 CA 中心签发,适合对接企业内部的统一 PKI 体系。

Chapter 08

Manager 集群容灾

Swarm 的 Manager 集群采用 热备方式 提升容灾能力:多个 Manager 中只有一个处于 Leader 状态,其余处于 Reachable 热备状态。当 Leader 宕机,其余 Manager 通过 Raft 算法 自动发起选举,重新选出新 Leader。

Manager 数量 可容忍故障数 适用场景
1 0 开发测试
3 1 生产环境(推荐)
5 2 关键业务
7 3 金融级(慎用,增加选举延迟)
⚠️

Raft 选举需 过半数 Manager 在线才能产生新 Leader。3 Manager 容忍 1 故障,但若同时挂 2 个,集群将不可写(读仍可用)。

9.3 负载均衡

当 service 包含多个 task 时,用户访问会通过 Swarm 内置 DNS 轮询 (Round-Robin) 负载均衡转发到各个 task。负载均衡策略 无法 通过 service 属性修改,需要更复杂的策略时可使用 Nginx 、 HAProxy 等第三方代理。

Chapter 10

Service 操作

10.1 弹性伸缩

不停止服务的前提下对 task 进行扩/缩容,两种方式:

bash 
                
                  
# 方式 1:docker service update
                  
                  
docker service update
                  
                  
--replicas
                  
 4 toms
                  
# 方式 2:docker service scale
                  
                  
docker service scale
                  
 toms=7

10.2 节点可用性控制

bash 
                
                  
# pause:不向此节点分配新 task(扩容时跳过)
                  
                  
docker node update
                  
                  
--availability
                  
 pause docker2
                  
# drain:清空此节点上的 task(用于节点维护)
                  
                  
docker node update
                  
                  
--availability
                  
 drain docker2
                  
# 恢复为 active(恢复正常调度)
                  
                  
docker node update
                  
                  
--availability
                  
 active docker2

10.3 task 容错

当 task 所在主机或容器故障,Manager 编排器自动创建新 task,并分配到可用节点。无需人工干预。

10.4 删除 service

bash 
                
                  
docker service rm
                  
 toms

删除后 service 消失,所有 task 与容器也被删除。

FAQ

常见问题

Docker Swarm 与 Kubernetes 有什么区别?

Docker Swarm 内置于 Docker 引擎,学习曲线平缓,适合中小型团队与快速搭建场景;Kubernetes 功能更强大(自动扩缩、复杂调度、服务网格),适合大规模生产环境。Swarm 使用标准 Docker API,兼容现有 Docker Compose;Kubernetes 使用独立的 API 体系,生态丰富但运维复杂。

Swarm 集群最少需要几个节点?

最少 1 个节点(单节点 Swarm),但生产环境推荐至少 3 个 Manager 节点(满足 Raft 共识算法的多数派要求,容忍 1 个节点故障)。Worker 节点数量根据业务负载灵活配置。

Manager 节点和 Worker 节点有什么区别?

Manager 节点负责维护集群状态、调度 service、处理集群管理任务,通过 Raft 算法保证一致性;Worker 节点用于运行 task(任务容器),对外提供服务。默认 Manager 同时也是 Worker,可以运行 task。两者的角色可以通过 docker node promote / demote 命令相互转换。

Swarm 集群的负载均衡策略是什么?

Swarm 内置 DNS 轮询(Round-Robin)负载均衡,无法通过修改 service 属性变更。如需更复杂的策略(IP Hash、最小连接、加权等),可通过 Nginx、HAProxy 等第三方代理实现。

如何安全地删除一个 Manager 节点?

Manager 节点不建议直接退群,会破坏集群一致性。正确流程是:先 docker node demote 降级为 Worker,再按 Worker 节点的删除流程操作。如果使用 docker swarm leave -f 强制退群,可能造成 Manager 集群丢失多数派,导致集群不可用。

什么是 Swarm 自动锁定(autolock)?

autolock 是 Swarm 的一种安全机制,用于加密 Manager 之间的通信(TLS)。启用后,Manager 重启后会被锁定,需要提供解锁密钥(unlock key)才能重新加入集群。密钥通过 docker swarm unlock-key 命令查看,务必妥善保管。

如何查看 Swarm 集群的 CA 证书?

通过 docker swarm ca 命令可以查看、轮换(rotate)或指定外部 CA 证书。Swarm 默认每 90 天自动轮换一次 CA 根证书,可通过 docker swarm ca --rotate 手动触发。
