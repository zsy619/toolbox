容器资源限制与 cgroup 深入

Chapter 01

cgroup v1 与 v2 差异

  • v1:每个资源独立层级,cpu/memory/blkio 分开
  • v2:统一层级,所有资源统一管理
  • cgroup namespace:容器内只看到自己的进程
  • Docker 20.10+ 默认 v2(Kernel 5.8+ 推荐)
Chapter 02

namespace 6 种隔离

  • PID:进程 ID 隔离(容器内 PID 1 是入口进程)
  • Network:网络协议栈隔离(独立 IP/路由/防火墙)
  • Mount:文件系统挂载点隔离(chroot 增强版)
  • UTS:主机名/域名隔离
  • IPC:进程间通信隔离(消息队列/信号量)
  • User:用户/组 ID 隔离(root in container ≠ host root)
Chapter 03

CPU 资源 4 限制

  • --cpus=1.5:最大使用 1.5 核(最直观)
  • --cpu-shares=512:相对权重(默认 1024)
  • --cpuset-cpus=0,1:绑核(避免跨核开销)
  • --cpu-period + --cpu-quota:完全公平调度器(CFS)
Chapter 04

内存 4 限制

  • --memory=512m:硬上限,超限 OOM Kill
  • --memory-reservation=256m:软保证(系统压力时优先回收)
  • --memory-swap=1g:总内存+swap(默认=memory,0 禁用 swap)
  • --oom-kill-disable:禁用 OOM Kill(慎用,易拖垮宿主机)
Chapter 05

ulimit 系统级限制

  • ulimit -n:文件描述符数(容器默认 1024,高并发需调大)
  • ulimit -u:最大进程数(默认无限制,需显式设)
  • ulimit -l:最大锁定内存(Redis/ES 内存锁必需)
  • ulimit -c:core dump 大小(0 禁用)
💡 检测 cgroup 版本

stat -fc %T /sys/fs/cgroup/ → tmpfs 是 v2,无输出是 v1

⚠️ OOM 排查

dmesg | grep 'oom' 看容器是否被 OOM Killer 终止
