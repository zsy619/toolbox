Chapter 01

主从复制 3 模式

  • 基于 binlog position:传统模式,需指定 file+pos
  • 基于 GTID(MySQL 5.6+):事务标识自动同步,推荐
  • 半同步复制:master 等待 slave ACK 才返回,数据零丢失
  • 异步复制:master 不等待 slave,性能好但有丢失风险
  • 推荐:生产用 GTID + 半同步(semi-sync)
Chapter 02

GTID 主从配置 5 步

  • 1) master 创建复制用户:CREATE USER 'repl'@'%' IDENTIFIED BY 'xxx'
  • 2) GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%'
  • 3) slave 配置 CHANGE MASTER TO MASTER_AUTO_POSITION=1
  • 4) START SLAVE 启动复制
  • 5) SHOW SLAVE STATUS\G 查看 Slave_IO_Running: Yes / Slave_SQL_Running: Yes
Chapter 03

binlog 模式 3 选

  • ROW 模式:记录每行变更,数据最安全但文件大
  • STATEMENT 模式:记录 SQL 语句,文件小但主从不一致风险
  • MIXED 模式:自动选择,MySQL 5.7+ 默认
  • 生产推荐:ROW(可恢复任意数据)
  • binlog_format = ROW 性能影响约 10-20%
Chapter 04

读写分离实现

  • 应用层:MyBatis 拦截器 + ThreadLocal 路由
  • ProxySQL 中间件:基于规则自动路由读从库
  • MySQL Router 官方轻量级路由
  • MaxScale MariaDB 商业级中间件
  • 推荐:ProxySQL + 权重配置 + 故障自动切换
Chapter 05

备份恢复 4 选

  • mysqldump:逻辑备份,适合小数据(< 100GB)
  • Percona XtraBackup:物理热备,推荐大数据
  • mysqlbinlog + binlog:基于位置恢复,误操作找回
  • 云厂商快照:EBS / 阿里云盘 整盘备份,最快
  • 定时 crontab:每日 02:00 全量 + 6 小时增量 binlog
💡 字符集

推荐 utf8mb4_0900_ai_ci 支持 4 字节 emoji 与中文

innodb_buffer_pool_size = 容器内存 70%,推荐 8GB+

实战代码示例

📝 MySQL CHANGE MASTER

完整可执行代码,直接复制即可在生产环境使用:

MySQL CHANGE MASTER · sql 
            
CHANGE MASTER TO
  MASTER_HOST='mysql-master',
  MASTER_USER='repl',
  MASTER_PASSWORD='repl_pwd',
  MASTER_LOG_FILE='mysql-bin.000001',
  MASTER_LOG_POS=154;
START SLAVE;
