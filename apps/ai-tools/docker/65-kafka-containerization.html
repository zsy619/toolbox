Kafka 消息队列容器化实战

KRaft 模式 + 3 节点集群 + 持久化

Chapter 01

KRaft 模式新特性

  • Kafka 2.8+ 支持 KRaft,3.3+ 生产可用
  • 彻底摆脱 ZK,集群状态由 Controller 自身管理
  • 元数据传播快:节点加入集群毫秒级感知
  • 运维简单:无需维护 ZK 集群(2 套集群变 1 套)
  • 单集群可扩展到数百万分区
Chapter 02

3 节点集群 Docker Compose

  • kafka1/kafka2/kafka3 三个服务镜像相同,环境变量区分
  • KAFKA_NODE_ID=1/2/3, KAFKA_PROCESS_ROLES=broker,controller
  • KAFKA_CONTROLLER_QUORUM_VOTERS=1@kafka1:9093,2@kafka2:9093,3@kafka3:9093
  • 数据持久化:每个 broker 独立 volume(/var/lib/kafka/data)
  • advertised.listeners 暴露 PLAINTEXT://kafka1:9092 外部访问
Chapter 03

生产配置 5 要点

  • KAFKA_NUM_PARTITIONS=3 默认分区数(可 topic 覆盖)
  • KAFKA_LOG_RETENTION_HOURS=168(默认 7 天)
  • KAFKA_LOG_SEGMENT_BYTES=1073741824(1GB 滚动)
  • KAFKA_COMPRESSION_TYPE=producer 减少存储 50%
  • KAFKA_AUTO_CREATE_TOPICS_ENABLE=false 生产禁用自动创建
Chapter 04

Producer/Consumer 调优

  • acks=all 生产端保证不丢(性能下降 20%)
  • enable.idempotence=true 防止重复消息
  • compression.type=snappy 平衡压缩率与 CPU
  • Consumer group:group.id + enable.auto.commit=false 手动提交
  • max.poll.records=500 控制单次拉取数量
Chapter 05

监控与可观测性

  • JMX exporter 暴露 Kafka 指标:9093 端口给 Prometheus 抓取
  • 关键指标:UnderReplicatedPartitions / ActiveControllerCount / MessagesInPerSec
  • Burrow / 滴滴 Kafka manager:消费 lag 监控
  • kafka-lag-exporter:基于 consumer offset 监控
  • 告警规则:lag > 1000 持续 5min 触发告警
