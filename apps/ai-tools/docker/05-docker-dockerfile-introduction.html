为什么需要 Dockerfile

Dockerfile 是构建 Docker 镜像的脚本文件 ,由一系列指令构成。通过 docker build 命令构建镜像时,Dockerfile 中的指令由上到下依次执行,每条指令都会构建出一个镜像(就是 镜像的分层 )。因此指令越多,层次就越多,创建的镜像就越多,效率就越低。

Dockerfile 三原则

1) 指令不区分大小写 ,一般惯例写为全大写;
2) 指令后至少会携带一个参数 ;
3) 注释以 # 开头 。
所以在定义 Dockerfile 时,能在一个指令完成的动作就不要分为两条。

15+ 核心指令速查

下表汇总了 Dockerfile 中最常用的 15+ 指令,涵盖构建、运行、元数据等全场景。

指令 语法 作用
FROM FROM [:] 指定基础镜像,必须是第一条指令;省略 tag 默认为 latest
MAINTAINER MAINTAINER 维护者姓名和邮箱(官方 不建议 使用,推荐 LABEL)
LABEL LABEL = ... 键值对形式包含任意镜像元数据,代替 MAINTAINER
ENV ENV = ... 指定环境变量,后续 RUN 可用,容器运行时也可见
WORKDIR WORKDIR 容器打开后默认进入的目录;可设置多个,后续相对路径会基于上次的 WORKDIR
RUN RUN 或 RUN ["EXECUTABLE","PARAM1",...] 在 docker build 过程中执行 shell 命令
CMD CMD [...] 或 CMD command param1 ... 容器启动后立即执行的默认命令( 可被 docker run 覆盖 )
ENTRYPOINT ENTRYPOINT [...] 或 ENTRYPOINT command ... 容器启动时 一定执行 的命令(类似 main 入口)
EXPOSE EXPOSE [...] 声明容器运行时监听的端口(需 -p 映射才对外)
ARG ARG [=] 定义 构建时 变量( --build-arg 传入)
ADD ADD 复制文件到容器;src 可为 URL,或 tar 包自动解压
COPY COPY 功能类似 ADD,但 不能是 URL ,压缩包不自动解压
ONBUILD ONBUILD [INSTRUCTION] 当前镜像的 子镜像 构建时执行的指令(钩子)
VOLUME VOLUME ["/dir1","/dir2"] 声明容器可挂载的数据卷挂载点
USER USER 指定 RUN/CMD/ENTRYPOINT 的执行用户
HEALTHCHECK HEALTHCHECK CMD ... 健康检查命令,常用于 docker compose depends_on
🎯

最少必须掌握的 5 个指令 :FROM(基础)、RUN(构建时操作)、COPY(复制文件)、CMD/ENTRYPOINT(启动命令)、EXPOSE(端口声明)。这 5 个能覆盖 80% 的 Dockerfile 场景。

Chapter 02

scratch 镜像与 HelloWorld 实战

2.1 scratch 镜像

scratch 镜像是一个 空镜像 ,是所有镜像的 Base Image。

  • scratch 镜像只能在 Dockerfile 中被继承( FROM scratch ), 不能 pull 拉取
  • 不能 run,没有 tag
  • 不会生成镜像中的 文件系统层
  • scratch 是一个保留字,用户 不能 作为自己镜像的名称

scratch 常用于构建 极小镜像 (如 Go 编译后的二进制文件)。

2.3 docker build 参数说明

参数 说明
-t [:] 指定要生成镜像的 repository 和 tag,省略 tag 默认为 latest
-f 指定要使用的 Dockerfile 文件路径(文件名不是默认的 Dockerfile 时需要)
最后的 . 宿主机 URL 路径,构建时从此路径中查找 Dockerfile
--no-cache 不使用 build cache,强制重新构建每一层
--build-arg name=value 为 ARG 指令传入构建时变量

2.4 镜像重打标签(docker tag)

当进行过出新版本了,上个版本的镜像标签就不能再用了。 docker tag 命令可以对镜像重打标签。重打标签实际是 复制了一份镜像 ,将新镜像指定新的 tag。新镜像的 ImageID 和 Digest 和原镜像的 相同 。

bash

Chapter 03

CMD vs ENTRYPOINT

这两个指令都是用于指定容器启动时要执行的命令,无论哪个指令,每个 Dockerfile 中 只能有一个 CMD/ENTRYPOINT 指令, 多个指令只会执行最后一个 。

3.1 核心区别

维度 CMD ENTRYPOINT
覆盖性 可被 docker run 后面的命令 覆盖 不会被覆盖,只会被作为 arg 拼接(array 形式)
使用场景 容器启动时 默认 执行的命令 容器启动时 必须 执行的命令(类似 main 入口)
参数传递 启动命令 docker run 中 不能 添加参数 启动命令 docker run 中 可以 添加参数

3.2 CMD 例子

创建 Dockerfile2 :

dockerfile 
                
                  
FROM
                  
 centos:7
                  
CMD
                  
 cal

构建并运行:

bash 
                
                  
docker build
                  
                  
-f
                  
 ./Dockerfile2
                  
-t
                  
 mycal .
                  
docker run
                  
                  
-it
                  
 mycal

运行就会显示当前月份的日历。

⚠️

此时若在 docker run 时指定要执行的命令(如 docker run -it mycal cal 2020 ),则 Dockerfile 中 CMD 指定的命令 不执行了 。也无法为 CMD 指定的命令设置选项。

3.3 ENTRYPOINT 例子

创建 Dockerfile4 :

dockerfile 
                
                  
FROM
                  
 centos:7
                  
ENTRYPOINT
                  
 cal

如果 docker run 时指定了执行命令(如 cal 2020 ),ENTRYPOINT 指令 依然会执行 ,不会被覆盖。此时即使在 docker run 中添加命令选项,也是 无效的 (因为 shell 形式不拼接 arg)。

如果 Dockerfile 内容改为 array 形式:

dockerfile 
                
                  
FROM
                  
 centos:7
                  
ENTRYPOINT
                  
 [
                  
"cal"
                  
]

那么在 docker run 中添加命令选项 cal 2020 是 有效 的——daemon 会先把 cal 和 2020 拼接成 cal 2020 再运行。

3.4 总结

为什么 array 形式更通用

docker daemon 对 ENTRYPOINT 指定的 command 和 ["EXECUTABLE"] 处理方式不同:
1) command (shell 形式):daemon 直接运行 ,不会与 docker run 后的 arg 拼接;
2) ["EXECUTABLE"] (array 形式):daemon 会与 docker run 后的 arg 拼接,然后运行拼接后的结果。
结论 :无论 CMD 还是 ENTRYPOINT,使用 ["EXECUTABLE"] array 形式的 通用性会更强 。

Chapter 04

ADD vs COPY

创建一个 Dockerfile:

dockerfile 
                
                  
FROM
                  
 centos:7
                  
WORKDIR
                  
 /opt
                  
ADD
                  
 zookeeper.tar.gz /opt/add
                  
COPY
                  
 zookeeper.tar.gz /opt/copy
                  
CMD
                  
 /bin/bash

构建并运行镜像后会发现:

  • ADD 指令添加的是解压后的目录 (zookeeper 文件夹)
  • COPY 指令添加的是未解压的 (zookeeper.tar.gz 压缩包)
特性 ADD COPY
src 可以是 URL ✅ 相当于 wget 下载 ❌ 必须是本地路径
src 是压缩包 ✅ 自动解压 到 dest ❌ 保持原压缩包
行为可控性 有副作用(解压、下载) 仅复制 ,更可控
生产推荐 需要下载/自动解压时使用 默认推荐
🎯

最佳实践: 能用 COPY 就不用 ADD 。只有当需要下载远程资源(如 ADD http://x.com/app.tar.gz /opt/ )或自动解压 tar 包时才用 ADD。其他场景一律 COPY,行为更可预测。

Chapter 05

ARG 指令(构建时变量)

ARG 指令用于定义一个 变量 ,该变量会在 镜像构建时 使用,而 不是容器启动时 。

5.1 示例 Dockerfile

dockerfile 
                
                  
FROM
                  
 centos:7
                  
ARG
                  
 name=TOM
                  
RUN
                  
 echo $name

5.2 使用 ARG 默认值构建

构建时没给变量 name 赋予新值,所以 name 还是 TOM :

bash 
                
                  
docker build
                  
                  
-t
                  
 myargs:1.0 .

5.3 使用 ARG 指定值构建

构建时给变量 name 赋予新值,所以 name = jerry :

bash 
                
                  
docker build
                  
                  
-t
                  
 myargs:1.0
                  
--build-arg
                  
 name=jerry .

5.4 ARG vs ENV

指令 作用阶段 是否在容器运行时可见 典型用途
ARG 仅 构建时 ❌ 容器运行时不可见 --build-arg VERSION=1.0
ENV 构建时 + 运行时 ✅ env 可见,代码 process.env 可读 NODE_ENV=production
Chapter 06

ONBUILD 指令(子镜像钩子)

ONBUILD 指令只对 当前镜像的子镜像 进行构建时有效。

6.1 父镜像 Dockerfile

dockerfile 
                
                  
FROM
                  
 centos:7
                  
ENV
                  
 WORKPATH /usr/local
                  
WORKDIR
                  
 $WORKPATH
                  
ONBUILD
                  
                  
RUN
                  
 yum
                  
-y
                  
 install wget
                  
CMD
                  
 /bin/bash

6.2 子镜像 Dockerfile

dockerfile 
                
                  
FROM
                  
 parent:1.0

6.3 效果

  • 当前镜像及其子镜像的工作目录都是 /usr/local
  • 子镜像在进行 docker build 时 会自动运行 ONBUILD 后面的 RUN yum -y install wget
  • 构建并运行子镜像后,就可以使用 wget 指令了
🎯

典型应用场景:父镜像是一个 基础镜像 (如预装好 Python 的镜像),子镜像在 FROM 这个父镜像时,自动触发 ONBUILD 后面的指令(如自动 pip install requirements.txt), 简化子镜像的 Dockerfile 编写 。

Chapter 07

构建新镜像的 5 种方式

  1. docker build (基于 Dockerfile 构建, 生产首选 )
  2. docker commit (将容器修改保存为新镜像,适合调试)
  3. docker import (从 tar 包导入为镜像)
  4. docker compose (通过 compose.yml 批量构建)
  5. Docker Hub 中完成 Automated Builds (GitHub 集成自动构建)
⚠️

注意: docker load 并没有 构建出新镜像,其与原镜像是 同一个镜像 (只是从 tar 文件加载回本地)。

方式 命令示例 是否产生新 ImageID 适用场景
build docker build -t myapp:1.0 . 是(产生新 ID) 生产首选,可复现
commit docker commit mytom tomcat10:own 是(产生新 ID) 调试、临时修改
import docker import myimage.tar myimg:1.0 是(产生新 ID) 从 tar 包恢复
compose docker compose up --build 是(产生新 ID) 多服务编排
load docker load -i myimage.tar 否 (ImageID 不变) 镜像迁移

FAQ

常见问题

Dockerfile 是什么?

Dockerfile 是构建 Docker 镜像的脚本文件,由一系列指令构成。通过 docker build 命令构建镜像时,Dockerfile 中的指令由上到下依次执行,每条指令都会构建出一个镜像(就是镜像的分层)。因此指令越多,层次就越多,创建的镜像就越多,效率就越低。所以在定义 Dockerfile 时,能在一个指令完成的动作就不要分为两条。

CMD 和 ENTRYPOINT 有什么区别?

CMD 指定的是容器启动时 默认 的命令,如果 docker run 时指定了其他命令,Dockerfile 中的 CMD 指定的命令时不会执行;ENTRYPOINT 指定的是容器启动时 一定会执行 的命令,即使在 docker run 中指定了其他命令,ENTRYPOINT 也会执行(用 array 形式时,后面的内容会被作为 arg 拼接到 ENTRYPOINT 后面)。结论:无论 CMD 还是 ENTRYPOINT,使用 ["EXECUTABLE"] array 形式的通用性会更强。

ADD 和 COPY 指令有什么区别?

ADD 和 COPY 功能相似,主要区别:1) ADD 的 src 可以是 URL(相当于 wget 下载),COPY 不行;2) ADD 的 src 如果是压缩包(如 .tar.gz),复制到容器后会 自动解压 ,COPY 不会自动解压;3) COPY 行为更可控,生产环境推荐优先用 COPY,仅在需要下载远程资源或自动解压时才用 ADD。

什么是 scratch 镜像?

scratch 镜像是一个空镜像,是所有镜像的 Base Image。scratch 镜像只能在 Dockerfile 中被继承(FROM scratch),不能 pull 拉取,不能 run,没有 tag,并且它不会生成镜像中的文件系统层。scratch 是一个保留字,用户不能作为自己镜像的名称。常用于构建极小镜像(如 Go 编译后的二进制文件)。

ARG 和 ENV 有什么区别?

ARG 用于定义构建时变量,只在 docker build 阶段有效,容器运行时不可见;ENV 用于定义环境变量,容器运行时仍可通过 env 命令或代码中 process.env.X 访问。生产实践:ARG 用于构建参数(如 --build-arg VERSION=1.0),ENV 用于运行时配置(如 NODE_ENV=production)。

构建新镜像的 5 种方式?

1) docker build(基于 Dockerfile 构建,生产首选);2) docker commit(将容器修改保存为新镜像,适合调试);3) docker import(从 tar 包导入为镜像);4) docker compose(通过 compose.yml 批量构建);5) Docker Hub 中完成 Automated Builds(GitHub 集成自动构建)。注意 docker load 并没有 构建出新镜像,其与原镜像是同一个镜像。

ONBUILD 指令有什么特殊用途?

ONBUILD 指令只对当前镜像的子镜像进行构建时有效。典型应用场景:父镜像是一个基础镜像(如预装好 Python 的镜像),子镜像在 FROM 这个父镜像时,自动触发 ONBUILD 后面的指令(如自动 pip install requirements.txt),简化子镜像的 Dockerfile 编写。
