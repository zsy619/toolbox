Docker 与 CI/CD 集成完整实战

GitHub Actions + GitLab CI + Jenkins + Argo

Chapter 01

CI/CD 4 阶段

  • 代码触发:push / PR / tag / schedule
  • 构建测试:编译 + 单元测试 + 代码质量
  • 镜像构建:Dockerfile + buildkit 缓存
  • 部署:staging → canary → production
Chapter 02

GitHub Actions 5 步模板

  • 1) actions/checkout@v4 检出
  • 2) docker/setup-buildx-action@v3 启用 buildx
  • 3) docker/login-action@v3 登录 Registry
  • 4) docker/build-push-action@v5 构建推送
  • 5) anchore/sbom-action 输出 SBOM
Chapter 03

GitLab CI 4 阶段

  • 1) build 阶段:docker buildx build
  • 2) test 阶段:启动容器跑测试
  • 3) scan 阶段:trivy 漏洞扫描
  • 4) deploy 阶段:helm upgrade / kubectl apply
  • Docker executor:每个 Job 独立容器,彻底隔离
Chapter 04

Jenkins + Docker Pipeline

  • 声明式语法:agent { docker 'maven:3.9' }
  • Docker Build and Publish 插件:可视化构建发布
  • Jenkinsfile 完整模板:checkout + build + push + deploy
  • Trivy 插件:安全扫描集成到 Pipeline
Chapter 05

Argo CD GitOps 完整实战

  • GitOps:Git 仓库即真实状态源
  • Argo CD 自动 sync Git manifest → K8s
  • App of Apps:父 App 管理子 App
  • PR 触发:PR-Bot 临时 namespace 预览
  • 回滚:argocd app rollback 回到上一 Revision
  • 审计:Argo CD Notifications + Slack 通知
💡 选型建议

GitHub 项目用 Actions,企业私有部署用 GitLab CI

🎯 GitOps 优势

所有变更经 Git 审计,可一键回滚到任意版本
