第 5 章 · 接工具，打通飞书、Hermes、Codex

只有 Profile，没有资料入口和执行工具，Agent 仍然只是一个"会说话的岗位说明书"。

🤔 为什么工具打通才算开始工作？

只有把真实工作资料、Agent 承载环境、执行工具连起来，它才可能完成一次真实交付。

💡 一句话：打通它们，就是把一个 Agent 从"会说话"变成"能干活"。

🧬 为什么是这三个工具？

为了理解工具分工，可以把 AI 能力简化为五层：

模型层 → 提示词层 → 能力流程层 → Agent 工作层 → 组织层

📁 飞书

上下文资源层

数据从哪来、交付到哪去

🤖 Hermes

Agent 工作层

岗位、Profile、长期记忆

⚡ Codex

执行层

调用工具、执行任务、检查结果

🛠️ 三个工具分别负责什么

工具 在本次课程中的角色
飞书 提供真实文档、表格、消息等工作资料，也作为结果交付空间
Hermes 承接 Agent 的岗位、Profile、运行状态和持续工作能力
Codex 负责搭建、调试、调用工具、执行任务和检查结果

⚠️ 检查标准：不要按"装了哪些工具"来检查，而要按工作流节点检查：每一步由谁执行、读什么、写到哪里、失败时由谁接管。

✅ 工作流节点检查表

工作流节点 主要工具 连接是否成功的证据
读取输入 飞书 能打开指定文档或表格，且读取的是正确版本
加载岗位与规则 Hermes Agent 能复述岗位、边界和当前 Profile 版本
执行与调试 Codex 能按工作流运行，并给出可定位的错误信息
写回结果 飞书 结果出现在约定位置，链接可打开且权限正确
记录修正 成长档案 本次问题、人工改法和下一次规则都有记录

🔧 失败排查顺序：先查输入链接与版本 → 再查飞书权限 → 再确认 Hermes 是否加载了正确 Profile → 然后看 Codex 的执行日志 → 最后检查输出位置和写入权限。一次只改一个环节，改完立刻用同一份资料复测。

🎯 现场操作顺序（手把手 8 步）

  1. 1.确认 Codex、飞书和 Hermes 都能正常使用
  2. 2.用 Codex 创建或检查对应的 Hermes Agent
  3. 3.把岗位卡和工作流交给 Codex，生成或更新 Profile
  4. 4.接通飞书入口，让 Agent 能够读取指定资料
  5. 5.只授权完成当前任务所需的必要能力 —— 需要读的才给它读，需要写的才给它写
  6. 6.准备一份测试资料，先运行一次读取和输出
  7. 7.检查 Agent 是否读到了正确资料，是否写到了正确位置
  8. 8.设好成长档案：为 Agent 的运行结果、人工修正和错误记录指定一个固定存放位置

🔐 权限最小化 + 来源标记

第 5 步的授权，再往前补一刀：

权限最小化

管"谁能读"

来源标记

管"读的是什么"——给每份入库资料打三个标：来源（人工/AI）、属性（正例/反例）、状态（已审/未审）

📒 成长档案：为什么必须有它？

接工具不只是"能读能写"，还要设计回流：Agent 每次运行的结果、你的人工修正、它犯的错，都要写进成长档案。

没有反馈闭环的 AI，就像一个永远不听劝的实习生 —— 第一天犯的错，第一百天还会犯。

持续改进闭环：

识别问题 → 收集案例 → 修正规则 → 再次使用 → 记录反馈

⛔ 关键提醒：成长档案就是"反馈"那一环。没有它，前面五步都白做，飞轮转不起来。

✅ 过关标准

  • ①Agent 能从飞书拿到测试资料
  • ②Hermes 能承接岗位和规则
  • ③Codex 能完成执行和检查，并把结果写回飞书
  • ④Agent 只被授权了必要权限
  • ⑤成长档案已经设好

✍️ 现在轮到你

确认自己的测试资料、输入位置、输出位置，并写下这三个位置分别由谁负责。

⚠️ 常见卡点

卡点 ①：连接错了、权限不够、输出位置不清楚

→ 逐段确认"飞书能不能读、Hermes 有没有岗位、Codex 能不能执行"

卡点 ②：跑通了但每次结果都不一样

→ 大概率是输入不稳定或规则有缺口。先记录，第 6 章复盘时再修

卡点 ③：没有设成长档案

→ 现在设一个固定位置。否则改多少次都是原地踏步

💎

每一步都留痕，Agent 才会越用越强；
不留痕，第一天犯的错第一百天还会犯。
