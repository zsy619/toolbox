第 2 章 · 定一个 Agent 岗位

想象你招一个新员工。你不会说"你来帮我做运营吧"——你会给他一个岗位：负责什么、每周做什么、交什么、什么情况请示。给 Agent 定岗，和招人一模一样。

🚫 为什么不能只说"做一个万能 Agent"

"万能 Agent"听起来很强，实际上很难判断它该做什么，也很难知道做得好不好。

一个能长期使用的 Agent，首先应该像一个岗位：有明确职责、有固定输入、有稳定流程，也有清楚的边界。

🎯 一个能长期使用的 Agent = 一个岗位：明确职责 + 固定输入 + 稳定流程 + 清楚边界。

📄 先看一张"合格"的岗位卡长什么样

直接看那位实践者那张真实的岗位卡：

项目这位实践者的 AI 标签审核员
岗位名称酒店标签审核员
收到什么新标注的酒店标签（七级深度、几千个标签池）
做什么判断标签归类是否正确，标注"负向/中性"的边界
交付什么审核结论 + 与人工判断不一致的案例清单
什么时候不做两套旧标签体系冲突、历史遗留标签不判，转人工
成功标准与老员工判断一致率达标；不一致案例全部回流

看出差距了吗？这张卡里最有价值的，不是"做什么"，而是"什么时候不做"和"成功标准"。

🔑 定岗位的关键

不要从"我想让 AI 帮我做什么"开始，而要从"这项工作最后要交付什么"开始。

岗位越小，越容易跑通；岗位越具体，越容易验收。

选岗位之前，先做两个判断

① 场景识别：这个任务适合 Agent 化吗？

不是所有重复工作都适合。判断标准是"边界收敛、解法发散"：

  • • 边界要小：不是"帮我做运营"，而是"把客户咨询记录整理成跟进建议"这种具体任务；
  • • 解法要发散：有很多做法可以试。如果查教程就能解决的固定套路，Agent 价值不大。
② ROI 预判：值不值得做？

算两笔账：

  • • 成本侧：搭建时间、Token 消耗、后续维护；
  • • 收益侧：每月省下的重复时间、不依赖某个人的稳定性、能不能复制给同事。

一句话：搭两小时，未来一个月省不回两小时，就换个岗位。

⭐ 优先选择满足这些条件的任务

  • ✓反复出现，而不是只做一次；
  • ✓输入相对稳定，资料容易拿到；
  • ✓步骤大致清楚，主要靠规则而不是临场灵感；
  • ✓输出可以被检查和验收；
  • ✓出错后可以由人接管，不会直接造成不可逆损失。

🚫 反例：小到"每天把 A 表复制到 B 表"，ROI 不划算、维护成本还高。标准不是"小"，是高频 + 规则稳定 + 可验收。

🚫 本次工作坊以下三类任务不做
  1. 1. 需要 AI 独立做重大决策的（比如"决定是否给客户放贷"）；
  2. 2. 信息极度不完整、需要大量主动猜测的；
  3. 3. 输入来源不稳定的（别指望一次性和 AI 说"以后都归你"）。

📝 岗位卡模板

请把你的 Agent 写成一张岗位卡：

岗位名称例如：客户咨询整理员
服务对象谁会使用这个 Agent
工作目标它要稳定交付什么
输入资料文档、消息、表格、链接或其他资料
处理动作Agent 需要完成的主要工作
输出结果文档、表格、消息、清单或报告
成功标准什么样的结果才算完成
人工兜底哪些情况必须交给人判断
本次不做明确不处理的范围，越界必须转人工

这张岗位卡，就是这个 Agent 的产品内核：最小、可用、被需要的解决方案。内核越清晰，后面越稳。

💡 填卡时再问一句：这个岗位里最小的、绕不开的那个动作是什么？Agent 连这个都做不好，更复杂的肯定做不好。先从这个最小单元开始。

💬 可以直接给 Codex 的提示词

请根据下面的岗位卡，帮我检查这个 Agent 岗位是否足够具体。
重点检查：输入是否明确、动作是否可执行、输出是否可验收、边界是否清楚、是否存在需要人工确认的情况。
不要替我扩展成万能 Agent。如果范围过大，请帮我缩小到今天能完成一次真实交付的版本。

✅ 过关标准

别人只看岗位卡，也能大致知道这个 Agent 收到什么、做什么、交付什么，以及什么时候不能自己决定。

把你的岗位卡拿给旁边的人看，对方不看你的解释，能说出你收到什么、做什么、交付什么、什么时候不做——才算过关。

✍️ 现在轮到你

用一句话写出自己的 Agent 岗位，再写出本次明确不做的三件事。

⚠️ 常见卡点

  • •岗位写得太宽，比如"负责运营"。→ 用"最小绕不开的动作"缩小它，先收成一项能重复交付的工作。
  • •ROI 算下来不划算 → 换岗位，别硬做。简单但高频的任务才是最值得做的。
  • •找不到"什么时候不做" → 边界本身就是岗位最重要的定义。没有边界的 Agent 一定会越界。

"一张没有边界的岗位卡，
只是愿望清单。"

—— 第 2 章金句
