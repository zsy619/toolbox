第 0 章 · 开始前工具准备

飞书是资料仓库，Hermes 是承载岗位的工作台，Codex 是负责搭建、执行和排错的人。今天不是"认识三个工具"就结束，而是要让它们共同完成一次小任务。

❗

必保留，不得删除

本章是线下工作坊的手把手安装、授权、连接和验收环节。没有完成本章，后面的 Agent 搭建就没有稳定的运行环境。

0.1先确认工具清单

开始前工具准备与连接关系

  • •Codex：负责搭建项目、运行命令、调用工具、调试和检查结果。
  • •飞书客户端与飞书 CLI：负责登录飞书，并让 Agent 读写文档、表格、消息等真实工作数据。
  • •Hermes Agent：承载 Agent 的岗位、Profile、运行状态和持续工作能力。
  • •模型配置：Hermes 必须已经配置一个可用模型，能在 Codex 中确认状态。

0.2安装或确认 Codex

先确认 Codex 已经安装，并能正常打开当前工作目录。现场不要求大家手工敲复杂命令，直接让 Codex 检查当前系统、安装状态和可用目录；出现授权页面时，只在浏览器完成确认，不复制 Token、验证码或回调地址。

给 Codex 的提示词
请检查当前电脑上的 Codex 是否已安装并能正常运行。
请告诉我：
1. 当前运行环境是 Windows 原生、WSL、macOS 还是 Linux；
2. 当前实际使用的 Codex 可执行文件位置；
3. 当前工作目录是否可读写；
4. 是否还缺少继续搭建 Agent 所需的基础依赖。
只报告状态和下一步，不要输出任何密码、Token、Cookie 或其他凭据。

✅ 过关标准：Codex 能打开当前项目目录，能执行一次无副作用的环境检查，并且没有让学员手工复制敏感凭据。

0.3安装飞书并准备飞书 CLI

飞书客户端用于日常对话、查看文档和确认授权；飞书 CLI 是 Agent 连接真实飞书数据的工具箱。两者都要准备好：能登录同一个飞书账号，能打开文档，并能完成一次只读连接检查。

  1. 打开飞书客户端或网页，登录本次工作坊使用的账号。
  2. 打开一份自己创建的测试文档，确认账号有查看和编辑权限。
  3. 让 Codex 检查飞书 CLI 是否已安装、登录状态是否有效。
  4. 如果浏览器弹出授权，只由本人在浏览器点击确认；授权完成后回到 Codex 看结果。
  5. 不要把 access_token、refresh_token、授权码或 Cookie 粘贴到聊天框。
给 Codex 的提示词
请检查当前环境中的飞书客户端和飞书 CLI：
1. 飞书 CLI 是否已安装；
2. 当前登录状态是否有效；
3. 是否能读取我指定的测试文档；
4. 是否具备后续创建和编辑测试文档所需的基础权限。
如果需要授权，请只打开官方浏览器授权流程并等待我确认，不要让我复制授权码、Token、Cookie 或回调地址。

0.4 · 0.5安装 Hermes Agent + 接入飞书

Hermes 是 Agent 的承载位置。安装完成后，要能在 Codex 中确认 Hermes 的状态，并且能看到一个可用的 Agent Profile。

  • 确认 Hermes 已安装。
  • 确认模型已经配置并能正常响应。
  • 确认 Agent 的 Profile 文件已经生成。
  • 找到 SOUL.md 或 Profile 文件，复制"文件路径"，不要复制文件里的密钥。
路径 A · 复用已经创建的 Agent
请你配置上这份 Profile，文件路径是【这里替换成你的文件路径】。
完成 Profile 配置后，告诉我你现在的岗位职责、可处理的任务和还缺少的权限。
路径 B · 自己新建 Agent
根据目前的 Profile，帮我将这个 Hermes Agent 接入飞书，创建对应的飞书 Bot，并完成私聊和群聊的接通测试。
中间如果需要授权，请打开浏览器让我确认；不要让我复制授权码、Token、Cookie 或回调地址。
完成后只汇报连接结果和还缺少的权限。

⚠️ 验收顺序：授权完成后，先看私聊测试，再看群聊测试。必须看到 Agent 能收到消息并返回一条测试回复。

0.6根据 Profile 补齐外部工具

Agent 有了 Profile 还不等于有能力。Profile 里写着"下载、转录、解析、写回文档"，系统里就必须存在对应工具。先让 Codex 根据工作流列清单，再由 Hermes 逐项安装、逐项验证。

先让 Codex 列工具清单
根据当前 Profile 中的工作流，分析整个流程需要哪些额外的外部工具。
请按"工具名称、用途、是否已经安装、安装方式、验证方式、失败时怎么处理"列出清单。
不要直接安装，不要输出任何凭据；先给我清单，等我确认后再逐项执行。

以音视频转录 Agent 为例，常见工具包括：yt-dlp 下载音视频、ffmpeg 做格式转换、faster-whisper 做语音识别和转录、飞书 CLI 负责读取资料并写回结果。

让 Hermes 逐项安装并验证
请按顺序安装当前 Agent 所需的工具。
每装完一个工具，都要先验证版本或最小可用性，再继续下一个。
全部完成后，请汇报：已安装、未安装、验证结果、失败原因和下一步处理建议。
遇到权限、网络或版本问题时暂停，不要绕过安全设置，也不要输出任何密钥。

0.7开通飞书文档与协作权限

Agent 处理完资料后，还要能把结果交付出去。权限要按"能完成任务的最小范围"开通，至少确认它能创建、编辑目标文档，必要时能操作表格和多维表格；不要一上来开放无关权限。

给 Codex 的权限检查提示词
请帮我检查当前 Agent 是否具备完成本次工作流所需的飞书权限。
重点检查文档、表格、多维表格的创建和编辑权限，以及把我加入协作者的能力。
请列出缺少的权限和官方授权入口；需要授权时打开浏览器让我确认。
不要输出任何 Token、Cookie、授权码或应用密钥。

✅0.8 · 完整验证一次真实任务

准备一份低风险、可重复的测试资料，完整走一遍：输入资料 → Agent 接收任务 → 调用外部工具 → 处理内容 → 创建或编辑飞书文档 → 返回交付链接。

  • ✓Agent 能收到任务，并能说明自己当前岗位；
  • ✓外部工具确实被调用，安装结果可验证；
  • ✓飞书文档能打开，目录和格式正常；
  • ✓内容是可交付的整理稿，不是粗糙转录或空泛摘要；
  • ✓当前账号有查看和编辑权限；
  • ✓保存一张对话过程截图和一张最终文档截图，作为本关成功证据。

🎯 过关标准（全部打勾才算过）

  1. Codex 已安装并能执行环境检查。
  2. 飞书客户端和飞书 CLI 已登录，能读取测试文档。
  3. Hermes Agent 已安装、模型可用、Profile 已准备。
  4. Hermes 已接入飞书，私聊或群聊至少成功测试一次。
  5. Profile 所需外部工具已逐项安装并验证。
  6. Agent 能把一次真实任务交付为可打开、可检查的飞书文档。

⚠️ 常见卡点

  • •Hermes 项目跑不起来 → 把报错截图交给 Codex，先判断是环境、模型还是项目配置问题。
  • •飞书 CLI 权限不足 → 检查登录状态、应用权限和当前 Agent 身份，不要直接重复登录。
  • •Agent 能创建文档但本人打不开 → 检查文档协作者权限和可见范围。
  • •外部工具装不上 → 一次只处理一个工具，记录系统、版本和完整报错，再让 Codex 给出修复方案。
  • •三个工具像各自单独工作 → 回到工作流图，逐步写清楚"这一步由谁执行、输入是什么、输出到哪里"。
  • •遇到看不懂的错误 → 截图或复制报错给 AI，先问 AI，再决定是否人工处理。

本章再次提醒：安装 Codex、飞书与飞书 CLI、Hermes Agent，完成模型配置、飞书接入、外部工具安装、权限开通和完整验收，这些内容都是必保留项，不得删除。
