第 1 章 · 先让 Agent 动起来

先跑出一个能动的东西。哪怕它又笨又慢，只要看到它"收到输入 → 做了一串动作 → 给出交付物"，就成功了。

🧠 为什么要先跑一个 Demo？

先回答一个问题，凭直觉选：AI 落地，应该先挑最重要的岗位做，还是先挑最简单的岗位做？

大多数人选"最重要的"。一位研发团队负责人一开始也这么选——让最强工程师直接用 AI 拆最复杂的功能模块，结果全军覆没。

后来他退回来，先让 AI 做实习生负责的基础单元任务，反而跑通了。这个变化说明：先验证最小单元，比一开始挑战最复杂流程更容易建立稳定方法。

🎯 原点里程碑：找那个最小、最简单、绕不开的起点。AI 化的第一步，不是挑最值钱的，是挑最小的。

👀 动手之前，先看一个样例

先花几分钟看一个跑通的 Demo 样例（助教现场演示或看录屏）：

  • •输入是什么（比如一份飞书文档）；
  • •Agent 中间做了什么（读了文档、提炼了重点）；
  • •最终交付物长什么样（一份新的行动清单文档）。

💡 一个完整 Demo 的最小样子：输入是一份包含背景、结论和待办的飞书文档；处理过程是读取资料、区分事实与建议、提取负责人和时间；输出是一份新的行动清单，并把缺失信息标为"待确认"。

为什么要先看？因为你得先"看见"一个合格的交付长什么样，才知道自己跑出来的结果是 60 分还是 90 分。这在刻意练习里叫"最佳实践池子"——把自己的产出扔进标杆里看差距。

📝 第一次运行 · 最小 Demo 启动提示词

重点不是写得多，而是把输入、输出和停止条件说清楚。

请读取这份测试文档，并完成一次最小交付：
1. 提炼 3—5 条关键信息；
2. 整理成行动清单，字段包括行动项、负责人、截止时间、来源；
3. 原文没有的信息一律标为"待确认"，不要补写；
4. 将结果写入一份新的飞书文档，并返回文档链接。
完成后说明：你读取了什么、做了什么、输出在哪里。

记住一句话：你执行力的上限，不会超过你对最佳实践理解的上限。没见过的，你想象不出来，也做不出来。

🎯 现场任务 & 手把手步骤

📋 默认任务

读取一份飞书文档，提炼重点，整理成行动清单，并输出到一份新的飞书文档。

如果你的工作更适合其他任务，也可以替换成：整理客户咨询、生成会议待办、汇总销售线索、检查内容格式、制作项目日报等。

手把手 5 步

  1. 选一份不敏感、内容不长的测试资料（第 0 章准备的那份就行）。
  2. 跟 Codex 说清楚你希望它交付什么结果。说结果，不要说动作。比如："提炼成一份行动清单，每条一个行动项"，而不是"帮我处理一下这份文档"。
  3. 让 Codex 先检查环境（第 0 章已经做过就不用重复了）。
  4. 运行一次最小任务，观察 Agent 能不能：拿到资料 → 完成处理 → 返回结果。
  5. 不急着优化。先把"输入到输出"这条路走通。

✍️ 现在轮到你

写下一个你最近反复做过三次以上的小任务，并补上它的输入资料和最终输出。

比如："每周一整理销售周报"——输入是销售系统的原始数据，输出是一份周报文档。

✅ 过关标准

  • ✓能看到输入资料；
  • ✓能看到 Agent 完成了一次处理；
  • ✓能打开最终输出；
  • ✓人工判断结果基本可用；
  • ✓并且，你记录了至少 1 个它做得不好的地方——先记下来，不用修。

⚠️ 常见卡点

  • •Agent 能聊天，但拿不到飞书资料 → 回第 0 章检查授权范围。
  • •拿到了资料，但输出混乱 → 任务目标和验收标准没说清。重说一遍"你希望它交付什么"，而不是只说"帮我处理一下"。
  • •每次都要重新解释背景 → 正常，岗位和 Profile 还没建立，后面章节会解决。

"AI 化的第一步，不是挑最值钱的，
是挑最小的。"

—— 第 1 章金句
