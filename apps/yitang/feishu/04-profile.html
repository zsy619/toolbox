第 4 章 · 给 Agent 写大脑（Profile）

Profile 不是漂亮的介绍，而是 Agent 每次执行任务时可以照着做的工作依据。

🧭 Profile 是什么？

Hermes Profile 就像新员工的岗位说明书。

它要写清楚：

  • •Agent 是谁、负责什么
  • •怎么工作、什么情况下停下来问人
  • •什么可以做、什么明确不做

⚠️ 注意：它不是一段漂亮的介绍，而是 Agent 每次执行任务时的工作依据。

📋 Profile 应包含什么（逐条解释）

01 身份

它是什么岗位，不是什么岗位

02 服务对象

谁会给它任务，谁会验收结果

03 工作目标

它要稳定交付什么

04 输入格式

接受哪些资料；资料不完整时怎么办

05 工作步骤

按什么顺序处理（贴入第 3 章的工作流）

06 判断规则

"如果……就……" 的判断语句

07 输出格式

结果写成什么结构，放到哪里

08 成功标准

什么样的结果才算完成

09 失败处理

遇到错误、缺资料或冲突时怎么处理

10 人工兜底

哪些情形必须暂停并交给人

11 明确不做

哪些事情不在岗位范围内

12 事实边界 ⛔

资料里没有的信息，禁止自行编造；不确定必须标"待确认"

⛔ 最后一条特别重要：幻觉当事实，是 Agent 翻车最大的风险之一。AI 很会"一本正经地编"，所以必须写死：没有依据，不许猜。

🧱 最小 Profile 模板

第一版不需要写成长篇说明书，先用下面的骨架覆盖主路径。真实运行后，再把高频错误和新判断补进去。

# 身份与目标
你是【岗位名称】，服务【对象】，负责稳定交付【结果】。

# 输入
接受【资料类型】；缺少【关键字段】时先询问，不继续猜测。

# 工作步骤
1. 【读取与确认】
2. 【判断与处理】
3. 【检查与输出】

# 规则与边界
- 如果【条件】，就【动作】。
- 遇到【高风险情况】必须暂停并转人工。
- 不处理【明确排除范围】。

# 输出与验收
按【固定结构】输出到【位置】；满足【标准】才算完成。

🤖 交给 Codex 的生成提示词

请根据我的岗位卡和五字段工作流卡，生成一份最小可运行的 Hermes Profile。
1. 先覆盖正常主路径，再写清输入缺失、规则冲突和需要人工确认时的处理方式。
2. 不要扩展岗位范围；没有来源的事实不要补写。
3. 生成后逐项说明岗位卡中的内容写到了哪里。

📁 两个文件的区别：课程文档里保存的是便于讨论和备份的 Profile 草稿；Hermes 实际运行读取的是当前配置路径下的 Profile 文件。修改草稿后，还要让 Codex 同步到 Hermes 的实际文件，并让 Agent 重新加载，再用同一条测试任务验证。

📚 Profile 之外，配一个最小知识包

Profile 是岗位说明书，但岗位说明书之外，新员工还需要能查阅的资料库。一位数字员工实践者踩过的坑：知识明明在库里，数字员工却还是给出泛泛而谈的回答。因为知识没被结构化、没被打标签、没被 Agent 正确调用。

✅ 过往合格样例

好结果的 Before/After，让 Agent 知道"好"长什么样

❌ 失败样例

让它知道什么不能做；每条必须标注"反例/测试用"，防止垃圾进垃圾出

🎯 判断规则的具体案例

规则不是抽象的，光写"意向等级分三级"没用，要给每级配 2 个真实例子

🔑 关键提醒：当前任务的工作上下文和长期知识库要分开存。混在一起，Agent 会越用越乱，这就是"串扰"。

✅ 过关标准

  • ①把同一份输入交给 Agent 时，它不需要你每次重新解释完整背景，就能够按 Profile 执行主要流程
  • ②随便挑一条判断规则，你能当场给它配上一个真实案例——配不出来，说明这条规则 Agent 也学不会，删掉或补案例

✍️ 现在轮到你

写出 Agent 的身份、目标、三条核心规则，以及三种必须找人确认的情况。

写完后和旁边的人交换 Profile，让对方只说一个问题："我照着做，卡在哪一步？"
同伴反馈的价值不在夸，在帮你找到差距（GAP）。

⚠️ 常见卡点

卡点 ①：Profile 写得像口号

→ 没写判断条件和失败处理，回去补"如果……就……"

卡点 ②：Profile 写得过长

→ 把所有可能性都提前塞进去了。先覆盖主路径，真实运行后再补规则

卡点 ③：知识包里的样例没打标记

→ 正例、反例、来源、状态都要标，否则 Agent 分不清好坏

💎

AI 不是不会干，是没人把"怎么干"写清楚。
