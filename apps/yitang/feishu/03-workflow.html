第 3 章 · 拆出 Agent 的工作流

岗位确定之后，下一步就是把你脑中的经验，变成一条可执行的工作流。

🤔 为什么要拆工序？

人可以凭经验跳过很多步骤，但 Agent 不行。Agent 需要知道：

  • •先做什么
  • •遇到什么情况怎么判断
  • •什么时候必须停下来问人

💡 思考题（先想 30 秒再看下面）：如果你是那位实践者，老员工会干但说不出、硬逼着写又抵触，你会怎么办？

这位实践者的解法是反着来的：不逼会干的人写，而是招一群不会干的人来问。这就是"白纸提问法"，这一章会讲到。

➕➖ 第一步 · 先做加法，再做减法

拆流程分两步，顺序不能反：

①加法

把你做这件事时的所有动作全部列出来，包括那些"我觉得不用说"的小动作——比如"打开飞书找到那份表""看一眼截止日期""把结果粘贴到文档里"。

保底 10 个，争取 20 个，不要筛选。

②减法

合并同类项，收敛到 3 到 8 个主步骤。每步是一个完整的动作单元，不是微动作。

判断标准：这一步的产出物，能不能被下一步直接使用？能，就是一步；不能，就是缺了中间步骤。

📐 工作流通用模板

输入 → 判断 → 处理 → 检查 → 输出 → 人工确认

例如"客户咨询整理员"：

  1. 获取客户的原始咨询记录。
  2. 判断是否包含姓名、联系方式、需求、预算和时间等关键信息。
  3. 提取并整理客户需求，去掉重复和无关内容。
  4. 根据预设规则判断客户意向等级。
  5. 生成下一步跟进建议。
  6. 检查是否存在缺失字段、明显误判或敏感信息。
  7. 写入飞书表格，并标记需要人工确认的记录。

📋 给每一步加上判断点 · 五字段工作流卡

为了让流程真正可执行，建议把每一个主步骤都写成一张五字段工作流卡。这五项能把"凭感觉做"变成"照规则做"。

字段要回答的问题
输入这一步必须拿到什么资料？格式和版本是什么？
动作Agent 具体要读取、判断、提取或生成什么？
输出下一步能直接使用的结果是什么？保存到哪里？
检查用什么标准判断这一步已经完成且结果可信？
失败处理缺资料、权限不足或规则冲突时，是补充、重试、退回还是转人工？

✅ 写完后的自查：如果去掉你的口头解释，另一个人仍能看懂这一步需要什么、产出什么、失败时怎么办，这张卡才算合格。

不要只写"分析资料""生成结果"这种大词。要继续追问：

  • •什么情况下可以继续？
  • •什么情况下需要补资料？
  • •什么情况下必须停下来问人？
  • •什么结果需要再次检查？
  • •哪些信息不能由 Agent 自行猜测？

📄 白纸提问法 · 把隐性判断逼出来

如果发现自己"说不清自己怎么做的"，就用白纸提问法：

找一个完全不懂你业务的人，让他就你的流程不停地提问。他问到的那些"这也要说？"的地方，恰恰就是以后 Agent 最容易犯错的地方。

这位实践者当时配了三个动作，才让这招生效：

  1. 找真白纸：招不懂业务的外包，而不是让现有同事——现有同事会"不好意思问"；
  2. 切断私下解答：两个城市办公，强制线上文档交互，问答自动留痕；
  3. 打怪升级：提问加分、解答加分，把"说出来"变成有奖励的事。
💡 反例：没有新人可招怎么办？
请扮演一个完全不懂这件事的新人，就我的流程提出 20 个你会卡住的问题。

它问出来的问题，就是你流程里的隐性判断。

✅ 过关标准

另一个没有参与过这项工作的人，按照你的工作流，也能理解 Agent 应该如何从输入走到输出。

再狠一点：你把工作流交给一个完全不懂业务的人，他能照着做出及格的结果，才算过关。

✍️ 现在轮到你

把自己的岗位拆成一条 3 到 8 步的流程，并圈出其中最容易出错的一步。

⚠️ 常见卡点

  • •拆出来只有 2 步 → 加法没做够，回去把微动作全部列出来，至少 10 个再开始减法。
  • •拆出来 20 多步，砍不下来 → 按"产出物能不能被下一步直接用"合并。
  • •有些判断"只可意会" → 白纸提问法。写不出来的，Agent 以后也学不会。

"你教不会 AI 的地方，
恰恰是你自己也没想清楚的地方。"

—— 第 3 章金句
