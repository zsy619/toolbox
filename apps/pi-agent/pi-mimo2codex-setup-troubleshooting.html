1

启动 mimo2codex 本地代理

mimo2codex 是一个本地代理，负责把 Pi / Codex 发出的 Responses API 请求 实时翻译成上游模型能理解的 Chat Completions 格式。 无论用哪种方式启动，最终暴露的端点都是 http://127.0.0.1:8788/v1。

需要 Node ≥ 18

# 1. 全局安装
npm install -g mimo2codex

# 2. 初始化配置（创建 ~/.mimo2codex 数据目录）
mimo2codex init

# 3. 编辑 ~/.mimo2codex/.env，填入至少一个 provider 的 API Key
#    例如：MIMO_API_KEY=sk-xxxxxxxxxxxx

# 4. 启动代理，默认监听 127.0.0.1:8788
mimo2codex

启动后 mimo2codex 会打印 Codex 用的 config.toml 与 auth.json 片段，但 Pi 的配置方式不同，Pi 侧只需要端点地址。

适合内网共享 / 团队部署

docker run -d --name mimo2codex \
  -p 8788:8788 \
  --env-file ./.env \
  -v ~/.mimo2codex:/data \
  ghcr.io/7as0nch/mimo2codex:latest

该镜像默认已开启 MIMO2CODEX_AUTH=on，无需再手动设置 Server 模式。

关键点：无论哪种方式，Pi 侧使用的 base URL 都是 http://127.0.0.1:8788/v1，末尾不要多加斜杠。

2

在 Pi 中配置自定义 Provider

Pi 通过 ~/.pi/agent/models.json 添加 OpenAI 兼容服务商。注意：如果你设置了 PI_CODING_AGENT_DIR 环境变量， 路径会变为 $PI_CODING_AGENT_DIR/agent/models.json。 

{
  "providers": {
    "mimo2codex": {
      "baseUrl": "http://127.0.0.1:8788/v1",
      "api": "openai-completions",
      "apiKey": "placeholder",
      "compat": {
        "supportsDeveloperRole": false
      },
      "models": [
        { "id": "mimo-v2.5-pro",       "name": "MiMo V2.5 Pro" },
        { "id": "minimax-m3.1-flash",   "name": "MiniMax M3.1 Flash" }
      ]
    }
  }
}
字段 值 说明
baseUrl http://127.0.0.1:8788/v1 指向 mimo2codex 的 /v1 端点，末尾不要多加 /
api openai-completions 必须设为此值，是 Pi 中通用性最强的协议适配器
apiKey 任意非空字符串 Pi 强制要求该字段存在，仅用于通过加载校验
models[].id 与 mimo2codex 注册 ID 一致 避免斜杠，避免与已知 Provider 名称前缀冲突
compat.
supportsDeveloperRole		 false mimo2codex 不完全支持 OpenAI 的 developer 角色消息
3

设置 API 访问 Key（两端）

本地模式（默认）

authMode = off

代理接口完全开放，不需要任何 Key。仅适合本机使用。

推荐

Server 模式

authMode = on

必须携带 Authorization: Bearer m2c_…，适合内网共享与 Docker 部署。

A 配置上游 API Key

mimo2codex 需要上游大模型的 Key 才能转发请求。这些密钥通过环境变量管理， 且只自动加载数据目录下的 ~/.mimo2codex/.env—— 修改项目根目录的 .env 是无效的。 

# 文件路径：~/.mimo2codex/.env

# 小米 MiMo 的 API Key
MIMO_API_KEY=sk-xxxxxxxxxxxxxxxxxxxx

# 或 DeepSeek
# DEEPSEEK_API_KEY=sk-xxxxxxxxxxxx

# 开启 Server 模式（Docker 镜像已默认开启）
MIMO2CODEX_AUTH=on

密钥以 sk- 或 tp- 开头时， mimo2codex 会自动识别并路由到正确的上游主机。保存后需重启代理。

B 生成代理访问 Key

  1. 1

    重启 mimo2codex，日志中出现 INFO auth: on — admin login required 说明 Server 模式已生效。

  2. 2

    浏览器打开 http://127.0.0.1:8788/admin/（Docker 部署替换为对应主机地址），首次启动需按提示创建管理员账号。

  3. 3

    进入 /admin/account 页面，找到「我的 API Key」卡片，点击「新建 Key」。

  4. 4

    输入名称（如 pi-agent），确认后生成的 m2c_ 开头密钥仅显示一次，立即复制保存。

C 在 Pi 端使用这个代理 Key

方法一：/login 命令（推荐）

# 在 Pi 交互模式下运行
/login mimo2codex

# 选择 API Key 类型
# 粘贴刚才生成的 m2c_... 密钥

凭证会安全写入 ~/.pi/agent/auth.json。

方法二：手动编辑 auth.json

{
  "mimo2codex": {
    "type": "api_key",
    "key": "m2c_你的密钥"
  }
}

此时 models.json 的 apiKey 可保留为占位符。

4

验证与使用

  1. 1

    在 Pi 中运行 /model 命令。

  2. 2

    在 provider 列表中应能看到 mimo2codex，并带有你配置的模型 ID。

  3. 3

    选择该模型，即可通过 mimo2codex 将请求转发到上游大模型。

保存 models.json 后，Pi CLI 无需重启——该文件在每次打开 /model 选择器时会自动重载。pi-web 可能需要完全重启服务并刷新浏览器。

!

故障排查

按报错信息定位根因。点击卡片展开详细解法。

在 pi-web 中不能选择模型

配置写好了，但模型列表里不出现

P0
1

检查文件路径与 JSON 语法。Pi 默认读取 ~/.pi/agent/models.json；若设置了 PI_CODING_AGENT_DIR，则路径变为 $PI_CODING_AGENT_DIR/agent/models.json。多余的逗号或引号不匹配会导致整个文件被静默忽略。

2

重启 pi-web。Pi CLI 会自动重载 models.json，但 pi-web 可能缓存了模型列表——完全关闭并重启 pi-web 服务（或 Docker 容器），然后刷新浏览器。

3

用 CLI 交叉验证。运行 pi --list-models，若自定义 provider 出现则问题在 Web 界面，否则在配置本身。

4

核对模型 ID 与命名冲突。访问 http://127.0.0.1:8788/admin/ 确认 mimo2codex 实际注册的模型 ID；同时确保 provider 键名（如 mimo2codex）没有被 Pi 内置 provider 占用。

5

排查扩展冲突。某些扩展（如 pi-provider-manager）会注册自己的模型管理逻辑，可能覆盖 models.json。尝试暂时禁用近期安装的扩展后重启。

★

备选方案：pi-openai-compat 扩展。专用于把 OpenAI 兼容端点注册为 Pi 一等公民，可绕过 models.json 的部分验证限制。
pi install npm:@billjr99/pi-openai-compat → 在 Pi 中运行 /compat-login 按向导操作。

失败 · No API key found for "mimo2codex"

Provider 加载阶段被拒绝

P0

根因

Pi 在加载 models.json 中的自定义 provider 时，强制要求存在 apiKey 字段——即使真实密钥已在 auth.json 或环境变量中。验证逻辑不会去别处查找。

解法：在 models.json 中添加占位符

{
  "providers": {
    "mimo2codex": {
      "baseUrl": "http://127.0.0.1:8788/v1",
      "api": "openai-completions",
      "apiKey": "local",
      "models": [
        { "id": "mimo-v2.5-pro" }
      ]
    }
  }
}

本地代理通常不校验传入的 Key，所以占位符（"local" / "placeholder"）只需让 Pi 通过验证。实际请求时 Pi 会优先使用 auth.json 或环境变量中的真实密钥。

!

附带检查：模型 ID 斜杠解析。若模型 ID 含斜杠（如 mimo/MiMo-V2.5-Pro），Pi 可能把斜杠前的 mimo 误解析为 provider 名，报出 No API key found for "mimo"。确保 id 是纯模型名。

Failed to switch model: No API key for mimo2codex/MiniMax-M3.1-Flash-Preview

模型已识别，但运行时认证失败

P0

根因（两层叠加）

  • 模型 ID 中的 MiniMax 前缀被 Pi 的解析器识别为一个 provider 标识，导致它去查找名为 MiniMax 的密钥，而非 mimo2codex 的。
  • 即使解析正确，若密钥只写在 models.json 的 apiKey 字段而未经 /login 或 auth.json 配置，运行时认证仍会失败。

解法一：修改模型 ID 为不冲突的别名（最优先）

{
  "providers": {
    "mimo2codex": {
      "baseUrl": "http://127.0.0.1:8788/v1",
      "api": "openai-completions",
      "apiKey": "placeholder",
      "models": [
        {
          "id": "minimax-m3.1-flash",
          "name": "MiniMax M3.1 Flash"
        }
      ]
    }
  }
}

关键：让 id 不与 MiniMax 字符串关联，但通过 name 字段保留可读显示名。保存后重新打开 /model 让 Pi 重载配置。

解法二：通过 /login 保存正式凭证

# 在 Pi 会话中运行
/login mimo2codex

# 选择 API Key 类型，输入任意非空字符串（如 local）
# 凭证写入 ~/.pi/agent/auth.json

Pi 在切换模型时会优先从 auth.json 查找密钥。若已启用 Server 模式，这里应填入真实的 m2c_ 密钥。

解法三：确认 mimo2codex 侧的模型 ID 映射

访问 http://127.0.0.1:8788/admin/ 查看模型目录，确认代理期望接收的模型标识符。若 mimo2codex 期望 MiniMax-M2.7 这样的格式，Pi 侧应使用完全一致的 id——但鉴于解析冲突，仍建议用别名 + name 字段映射。

supportsDeveloperRole 相关报错

mimo2codex 不完整支持 developer 角色消息

P1

在 provider 层级添加兼容性开关即可：

{
  "providers": {
    "mimo2codex": {
      "baseUrl": "http://127.0.0.1:8788/v1",
      "api": "openai-completions",
      "apiKey": "local",
      "compat": {
        "supportsDeveloperRole": false
      },
      "models": [ /* ... */ ]
    }
  }
}

若模型支持，也可按需在模型层级添加 "reasoning": true 等字段。

上游 Key 不生效 / 401 Unauthorized

.env 改了但代理仍报鉴权失败

P1

mimo2codex 只自动加载数据目录下的 ~/.mimo2codex/.env，修改项目根目录的 .env 是无效的。Docker 部署时则通过 --env-file 传入。

另外确认：

  • 修改 .env 后必须重启 mimo2codex 进程 / 容器。
  • Docker 场景下，宿主机的 127.0.0.1:8788 与容器内地址不同，Pi 侧 baseUrl 要写宿主机可达的地址。
  • 可在 /admin/ 后台确认各 provider 的 Key 是否已被识别。

速查表

关键文件路径

  • ~/.pi/agent/models.json Pi 自定义 Provider 配置
  • ~/.pi/agent/auth.json Pi 运行时凭证
  • ~/.mimo2codex/.env 上游 Key + Server 模式开关
  • ~/.mimo2codex/providers.json 多上游注册（Qwen / Kimi / Ollama）

关键端点

  • 127.0.0.1:8788/v1 OpenAI 兼容 API（Pi 使用）
  • 127.0.0.1:8788/admin/ 管理后台 / 模型目录
  • /admin/account 生成 m2c_ 代理密钥

排查顺序建议

检查文件路径与 JSON 语法 → 重启 pi-web 服务 → 核对模型 ID 与兼容性设置 → 检查扩展冲突 → 必要时启用 Server 模式并生成正式代理 Key。
