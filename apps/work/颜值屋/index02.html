基于 Go + Hertz + GORM + MySQL + Vue3 + 小程序 技术栈

选择项（系统带出/预设选择） 填写项（客户/管理员手动输入） 上传项（照片/视频多媒体凭证）

系统架构与职责划分

小程序端（客户端）

面向全屋定制客户，提供报备与报修入口，流程闭环的起点。

  • •售后安装完成报备单填写
  • •售后报单维修需求提交
  • •维修进度实时追踪与最终确认
  • •多媒体凭证（图片/视频）上传

管理后台（Vue3）

面向总部管理员、客服，负责审核、派单与全局调度。

  • •报备单审核（通过/驳回）
  • •维修工单受理与指派维修师傅
  • •保外维修报价单审核
  • •数据看板与服务质量考核

服务端（Go API）

基于 Go + Hertz + GORM + MySQL，负责核心业务逻辑与数据持久化。

  • •API 路由、JWT 鉴权与参数校验
  • •工单状态机流转与事务管理
  • •微信服务通知推送
  • •OSS/COS 多媒体文件签名上传

核心业务流程梳理

流程一：售后安装完成报备

客户填报 → 管理员审核 → 交付
1

客户填写提交报备

客户在小程序选择订单与空间，填写安装完成日期，上传现场照片/视频，提交报备单。

2

后台管理员审核

管理员在 Vue3 后台查看客户提交的图文资料，进行合规性审核。

3

审核结果处理

【通过】系统自动生成交付档案，启动质保期。客户在小程序点击确认交付。

【驳回】管理员填写驳回原因，系统通知客户，客户修改后重新提交（回到步骤1）。

流程二：售后报单维修

客户报修 → 派单 → 上门 → 客户确认
1

客户提交报修单

客户选择空间/产品，填写故障描述，上传故障照片/视频，提交售后报单。

2

后台管理员受理与派单

管理员查看报单，根据故障类型和区域指派维修师傅。

3

维修师傅联系客户

师傅接单后电话联系客户，沟通上门时间及维修方案。

4

上门维修与客户最终确认

维修完成后，客户在小程序内查看维修结果，上传维修后照片。

【客户点击确认】工单关闭，服务记录归档，并可进行服务评价。

【客户点击不确认】客户填写原因，系统退回至管理员重新处理。

开发注意事项与待确认业务规则

1. 后端 (Go+Hertz+GORM) 开发注意

  • 状态机管理：建议引入状态机库（如 `looplab/fsm`）管理工单流转，避免代码中散落大量 `if-else` 状态判断。
  • 事务处理：在“管理员审核通过”和“客户确认闭环”节点，必须使用 GORM 的 `Transaction`，确保状态更新、质保生成、通知发送的原子性。
  • 文件上传：小程序端直接上传到 OSS/COS，后端只保存 URL 路径，降低 Go 服务器带宽压力。

2. 待确认的业务规则（需产品/运营介入）

  • 质保期起算日：从“客户提交报备日”、“管理员审核通过日”还是“实际安装完成日”开始计算？
  • 补件类维修流转：若需工厂重新生产板件，系统如何与工厂生产系统对接？客户如何查看补件进度？
  • 客户超时未确认：客户一直不点击“确认”也不点击“不确认”，工单是否设置“7天后系统自动确认”的兜底机制？
  • 师傅空跑费：若保外维修客户拒绝支付报价，师傅空跑费如何界定与承担？
