技术栈：Go + Hertz + GORM + MySQL + Vue3 + 小程序

需求边界总览

本系统包含

  • • 后台录入门店信息，自动生成门店专属二维码
  • • 客户扫码进入，自动关联门店
  • • 客户填写联系信息 + 上传合同照片（形成订单）
  • • 后台审核订单信息与合同
  • • 审核通过自动生成电子质保卡（含唯一编号、提示信息、动态二维码）
  • • 客户针对订单进行评分与文字评价
  • • 后台查看订单审核记录、订单评价记录、评分统计

本系统不包含

  • • 产品信息管理（客户登记不涉及任何产品名称、型号、数量、金额）
  • • 具体质保期限展示（仅展示提示信息，期限以合同约定为准）
  • • 分店管理员角色（仅设总部管理员）
  • • 电子签名（统一使用照片/视频上传替代）
  • • 售后报修/维修派单（本系统聚焦质保卡与订单评价）

系统架构与职责划分

小程序端：红棉花豫质本

面向购买红棉花板材的客户，提供扫码登记、质保卡出示与订单评价。

  • •扫码选择购买门店
  • •填写联系信息 + 上传合同（生成订单）
  • •查看审核结果与电子质保卡
  • •对具体订单进行评价
  • •个人中心（我的订单/质保卡/评价记录）

管理后台（Vue3）

面向总部管理员，负责门店录入、订单信息审核与订单评价查看。

  • •录入/管理所有门店信息
  • •审核客户提交的订单信息与合同
  • •查看每个订单的评价记录
  • •数据看板与统计导出
  • •系统设置（账号/权限/日志）

服务端（Go API）

基于 Go + Hertz + GORM + MySQL，负责核心业务逻辑与数据持久化。

  • •门店信息 CRUD 接口
  • •订单信息及合同上传与审核流转
  • •电子质保卡生成（唯一编号 + 提示信息）
  • •订单评价数据存储与查询
  • •文件上传（OSS 签名）与微信集成

核心业务流程

1

后台录入门店信息

总部管理员在 Vue3 后台录入所有门店信息（门店名称、地址、联系方式等），系统自动为每家门店生成专属二维码，支持下载打印。

2

客户扫码进入并填写联系信息 + 上传合同（生成订单）

客户扫描门店二维码，进入「红棉花豫质本」小程序，自动关联该门店。客户填写相关联系信息（姓名、电话等），并上传购买合同照片，提交后台审核。此记录即形成一个订单。本环节不涉及任何产品信息填写。

3

后台审核

管理员在后台查看客户提交的订单信息与合同照片，进行审核。可选择“通过”或“驳回”（驳回需填写原因）。

4

生成电子质保卡

审核通过后，系统自动生成电子质保卡（含唯一质保编号、客户信息、门店信息、合同签订日期、质保期限提示信息、动态核验二维码）。客户可在小程序内查看并线下出示。（不展示具体质保期限，期限以合同约定为准）

5

客户对订单进行评价

客户可在小程序内针对该笔订单进行评价（评分 + 文字描述），评价记录同步至后台，并与该订单一一绑定。

6

后台查看订单审核记录与订单评价

管理员可在后台查看所有订单审核记录，也可按订单查看每一条评价记录与评分统计，支持数据导出。

数据库设计（MySQL + GORM 方向）

5.1 stores - 门店信息表

CREATE TABLE stores (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  name          VARCHAR(100) NOT NULL -- 门店名称,
  address       VARCHAR(255) NOT NULL -- 门店地址,
  phone         VARCHAR(20)  NOT NULL -- 联系电话,
  qr_code_url   VARCHAR(500) -- 门店二维码图片地址,
  status        TINYINT DEFAULT 1 -- 1启用 0停用,
  created_at    DATETIME,
  updated_at    DATETIME,
  deleted_at    DATETIME INDEX
);

5.2 orders - 订单表（客户登记）

CREATE TABLE orders (
  id                BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  order_no          VARCHAR(32) NOT NULL UNIQUE -- 订单编号（系统生成）,
  openid            VARCHAR(64)  NOT NULL -- 微信用户 openid,
  store_id          BIGINT UNSIGNED NOT NULL -- 关联门店,
  customer_name     VARCHAR(50)  NOT NULL -- 客户姓名,
  phone             VARCHAR(20)  NOT NULL -- 联系电话,
  contract_date     DATE         NOT NULL -- 合同签订日期,
  contract_images   JSON         NOT NULL -- 合同照片URL数组,
  remark            VARCHAR(500) -- 备注,
  audit_status      TINYINT DEFAULT 0 -- 0待审核 1通过 2驳回,
  reject_reason     VARCHAR(500) -- 驳回原因,
  audit_at          DATETIME -- 审核时间,
  audit_by          BIGINT UNSIGNED -- 审核管理员ID,
  created_at        DATETIME,
  updated_at        DATETIME,
  deleted_at        DATETIME INDEX,
  INDEX idx_store (store_id),
  INDEX idx_openid (openid),
  INDEX idx_audit (audit_status)
);

5.3 warranties - 电子质保卡表

CREATE TABLE warranties (
  id                  BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  warranty_no         VARCHAR(32) NOT NULL UNIQUE -- 质保卡编号,
  order_id            BIGINT UNSIGNED NOT NULL -- 关联订单,
  store_id            BIGINT UNSIGNED NOT NULL -- 关联门店,
  customer_name       VARCHAR(50) NOT NULL,
  phone               VARCHAR(20) NOT NULL,
  contract_date       DATE NOT NULL,
  tip_message         VARCHAR(500) -- 质保期限提示信息,
  verify_code         VARCHAR(64) -- 动态核验码,
  status              TINYINT DEFAULT 1 -- 1有效 0失效,
  created_at          DATETIME,
  updated_at          DATETIME,
  deleted_at          DATETIME INDEX,
  INDEX idx_store (store_id),
  INDEX idx_order (order_id)
);

5.4 order_reviews - 订单评价表

CREATE TABLE order_reviews (
  id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  order_id        BIGINT UNSIGNED NOT NULL -- 关联订单（核心）,
  store_id        BIGINT UNSIGNED NOT NULL -- 关联门店（冗余，便于统计）,
  openid          VARCHAR(64) NOT NULL -- 评价客户openid,
  rating          TINYINT NOT NULL -- 评分 1-5,
  content         VARCHAR(1000) -- 评价内容,
  created_at      DATETIME,
  updated_at      DATETIME,
  deleted_at      DATETIME INDEX,
  INDEX idx_order (order_id),
  INDEX idx_store (store_id),
  INDEX idx_openid (openid)
);

5.5 admin_users - 管理员表

CREATE TABLE admin_users (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  username      VARCHAR(50) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  real_name     VARCHAR(50),
  role          VARCHAR(20) DEFAULT 'super_admin' -- 仅超级管理员,
  status        TINYINT DEFAULT 1,
  created_at    DATETIME,
  updated_at    DATETIME,
  deleted_at    DATETIME INDEX
);

数据表关系说明

  • stores 1 : N orders（一个门店可有多笔订单）
  • orders 1 : 1 warranties（审核通过后生成唯一质保卡）
  • orders 1 : N order_reviews（一笔订单可有一条或多条评价？默认一条，可扩展）
  • stores 1 : N order_reviews（通过冗余字段便于按门店统计）
  • 所有表采用 GORM 软删除（deleted_at），保证数据可追溯

开发注意事项与待确认规则

技术实现要点

  • 状态机管理：订单审核状态流转建议引入状态机库，避免散落的 if-else。
  • 事务处理：审核通过时必须使用 GORM Transaction，确保订单状态更新 + 质保卡生成 + 通知发送的原子性。
  • 文件上传：小程序端直传 OSS/COS，后端只保存 URL 路径，降低带宽压力。
  • 二维码生成：门店二维码建议使用 Go 二维码库生成，包含门店 ID 的加密参数。
  • 微信订阅消息：审核通过/驳回时推送微信服务通知，需提前申请模板。

待确认的业务规则

  • 质保卡提示语文案：系统固定提示语的具体文案需确认（如“质保期限以合同约定为准，如有疑问请联系购买门店”）。
  • 审核时效：管理员需在多少个工作小时内完成审核？是否需要超时提醒？
  • 评价次数限制：同一订单是否只能评价一次？是否允许修改评价？
  • 核验二维码有效期：动态二维码是否设置有效期？线下核验时展示的信息范围如何界定？
  • 数据导出：后台数据导出是否需要生成 Excel 文件？导出字段范围需确认。
